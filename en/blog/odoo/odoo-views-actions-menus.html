Odoo 20 Views, Actions and Menus: List, Form, Search

The Odoo interface is built from XML records. This guide shows how to connect menus, actions and views, design list, form and search views for the course model, and understand domains for filtering data.

Updated: October 16, 2026 15 min read Vinc Academy Team

Quick summary

Odoo builds its interface from XML records in a Menu → Action → View chain. A menu opens an action (ir.actions.act_window), the action names a model and the available modes (list,form), and each mode is a view (ir.ui.view) whose root is <list>, <form> or <search>. The XML file must be listed in the manifest's data, and is reloaded only by upgrading with -u.

How menu, action and view chain together

In part 5 we loaded data from CSV. When the data has a richer structure, such as the layout of a view, Odoo uses XML files. They sit next to the CSV files (interface-related ones go in views/), are declared in data the same way, and are also loaded one after another in manifest order.

Most of the Odoo interface comes from combining XML records in a familiar pattern:

  1. Menu: the entry users click.
  2. Action: the bridge between a menu and a model, deciding which model opens and with which views.
  3. View: how records are displayed (list, form, search…).

Practical tip

For plain data that must load fast, prefer CSV because it loads quicker than XML. For interface definitions, XML is practically the only choice.

Action: connecting a menu to a model

An action can be triggered three ways: clicking a menu item, clicking a button inside a view (if the button is wired to an action), or as a contextual action on a record. This part uses only the first. Here is an action that opens vinc.course in list mode and in form mode:

custom-addons/vinc_course/views/vinc_course_views.xml

<odoo>
    <record id="vinc_course_action" model="ir.actions.act_window">
        <field name="name">Courses</field>
        <field name="res_model">vinc.course</field>
        <field name="view_mode">list,form</field>
    </record>
</odoo>
  • id: an external id, a stable name other records can use instead of the numeric database id.
  • model="ir.actions.act_window": the kind of action that opens a window showing records.
  • res_model: the model the action works on.
  • view_mode: the permitted view modes, comma-separated; the default is list,form.

Kinds of actions

Every action has two mandatory attributes: type (the action category, deciding which fields apply and how it is interpreted) and name (a short description for users). Actions arrive in several forms, for instance as database records or as dictionaries returned by a button method.

KindUsed to
Window (ir.actions.act_window)The most common kind: present a model through views
URL (ir.actions.act_url)Open a web address; target is new (default, a new window), self (replace current content) or download
Server (ir.actions.server)Run automatically (for example through action rules) or manually from the contextual menu
Report (ir.actions.report)Print a report; see part 10
Client (ir.actions.client)An action handled entirely on the client, identified by a tag
Scheduled (ir.cron)Runs by itself at a set frequency

An action can also be attached to a model's contextual menus with binding_model_id: binding_type is action (the default, the Action menu) or report (the Print menu), and binding_view_types defaults to list,form.

Pinning specific views to an action

For a window action, view_mode is a string of view types separated by commas, with no spaces. To use one particular view instead of the default, set view_id. When a model has several views and you want to control their order, prefer ir.actions.act_window.view records over view_ids:

<record id="vinc_course_action_list" model="ir.actions.act_window.view">
    <field name="sequence" eval="1"/>
    <field name="view_mode">list</field>
    <field name="view_id" ref="vinc_course_view_list"/>
    <field name="act_window_id" ref="vinc_course_action"/>
</record>

The server assembles the views list in this order: take each (id, type) pair from view_ids by sequence; add view_id if its type is not yet covered; then for every type still missing from view_mode add an entry with no id, letting the client fetch the default view. The first type in the list is the one opened first.

Menus: three levels

A menu is a record of the ir.ui.menu model, but we use the short <menuitem> tag. A real menu tree has three tiers: the root entry (listed in the application switcher), a first-level entry (in the top bar) and the action entry that opens the records. The easiest approach is nesting them in XML:

custom-addons/vinc_course/views/vinc_course_menus.xml

<odoo>
    <menuitem id="vinc_course_menu_root" name="Vinc Course">
        <menuitem id="vinc_course_menu_main" name="Courses">
            <menuitem id="vinc_course_menu_action" action="vinc_course_action"/>
        </menuitem>
    </menuitem>
</odoo>

The third-level menu takes its label from the action's name. Declare both new files in the manifest, listing the view file that holds the action before the menu file, because the menu refers to the action:

'data': [
    'security/ir.model.access.csv',
    'views/vinc_course_views.xml',
    'views/vinc_course_menus.xml',
],

Run -u vinc_course, reload the browser (the web client caches menus and views), and open the new menu. You can already create courses through the default view Odoo generates.

Designing views: list, form, search

Every view is stored as a row of ir.ui.view, usually kept in the same XML file as the action and menus. Each has a name, a model and an arch (the view's XML structure). Add the following records inside the <odoo> tag of vinc_course_views.xml:

List view

Shows records as a table. The root is <list> and every field becomes a column:

<record id="vinc_course_view_list" model="ir.ui.view">
    <field name="name">vinc.course.list</field>
    <field name="model">vinc.course</field>
    <field name="arch" type="xml">
        <list>
            <field name="name"/>
            <field name="level"/>
            <field name="start_date"/>
            <field name="duration_hours"/>
            <field name="price"/>
            <field name="is_published"/>
        </list>
    </field>
</record>

Form view

This is where one record is created or edited. The root is <form>, laid out with group and notebook; plain HTML like div and h1, together with class, can refine the look:

<record id="vinc_course_view_form" model="ir.ui.view">
    <field name="name">vinc.course.form</field>
    <field name="model">vinc.course</field>
    <field name="arch" type="xml">
        <form>
            <sheet>
                <h1><field name="name"/></h1>
                <group>
                    <group>
                        <field name="level"/>
                        <field name="start_date"/>
                    </group>
                    <group>
                        <field name="duration_hours"/>
                        <field name="price"/>
                        <field name="is_published"/>
                    </group>
                </group>
                <notebook>
                    <page string="Description">
                        <field name="description"/>
                    </page>
                </notebook>
            </sheet>
        </form>
    </field>
</record>

Search view

Unlike list and form, a search view displays no data; it filters what other views show. The root is <search>. Each field adds a quick search box, while a filter is a switch for a predefined search and needs either a domain (adds a condition) or a context (with the group_by key to group the results):

<record id="vinc_course_view_search" model="ir.ui.view">
    <field name="name">vinc.course.search</field>
    <field name="model">vinc.course</field>
    <field name="arch" type="xml">
        <search>
            <field name="name"/>
            <field name="level"/>
            <filter name="published" string="Published"
                    domain="[('is_published', '=', True)]"/>
            <filter name="group_level" string="By level"
                    context="{'group_by': 'level'}"/>
        </search>
    </field>
</record>

Domains: the language of filtering

A domain chooses which rows of a model you want, using conditions. Every condition is written as (field name, operator, value). Conditions are combined with AND unless you say otherwise; to be explicit, use & (and), | (or) and ! (not), placed before the operands they combine:

[('level', '=', 'beginner'), ('price', '>', 0)]

['|', ('level', '=', 'beginner'), ('is_published', '=', True)]

Inside XML you cannot type < or & directly. Write &lt; and &amp; instead, e.g. domain="[('price', '&lt;', 1000)]".

What about kanban?

Kanban is a board of cards: each record is a card, optionally grouped into columns to follow work progress. The root is <kanban>, and Odoo opens only the first ten columns, folding the rest until a user expands them. Building the card needs QWeb knowledge, so we leave it for later parts; to use it, add kanban to the action's view_mode once the matching view exists.

Faster view editing with --dev=xml

Restarting the server after every view tweak wastes time. Launch with --dev=xml and, after editing an XML file, simply reload the page to see the change.

python3 odoo-bin --addons-path=addons,../custom-addons \
    -d odoo20_dev -u vinc_course --dev=xml

A special field: active

Odoo gives special meaning to certain field names. The best known is active: a record with active=False is automatically left out of every search, and to see it again you must search for inactive records explicitly. If you add this field, give it default=True so new records do not vanish.

Common mistakes when writing views

  • Copying a view and forgetting to change its id. Every view needs its own external id; when you copy and paste, always change the id (and preferably the name) so you do not overwrite the original.
  • Typing < or & straight into a domain in an XML file. XML forbids both characters in element content and attributes; replace them with &lt; and &amp;.
  • Editing the XML but the screen looks the same. Re-run with -u (or use --dev=xml) and reload the browser, because the web client caches menus and views.
  • The Create button is missing. If a user has read permission only, the button is not shown. Review ir.model.access.csv from part 5.

Summary

  • The Odoo interface: a Menu opens an Action, the Action picks the Model and view_mode, each mode is a View.
  • XML files must be declared in data in order (action before menu) and upgraded with -u.
  • List, form and search are the three basic views; search uses filter with domain or group_by.
  • A domain is a list of conditions; in XML remember to escape &lt; and &amp;.

FAQ

How does the Menu, Action, View chain work? ▾
A user clicks a menu, the menu opens an action, the action names a model and view modes such as list and form, and each mode is a view. The action is the bridge between menu and model.
Why does editing an XML file not change the screen? ▾
Data files load only on install or upgrade, so re-run with -u. The browser also caches menus and views, so reload the page. You can use --dev=xml to avoid upgrading.
What is a domain in Odoo? ▾
A domain expresses conditions for choosing certain records. Each condition is a (field, operator, value) triple, conditions are ANDed by default, and &, | and ! let you combine them explicitly.
How does a search view differ from a list view? ▾
A list view shows records as a table, while a search view displays no data and is used to filter and group the content of other views.
