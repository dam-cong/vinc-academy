Your First Odoo 20 Module: Structure, Manifest and Install

Every Odoo feature lives in a module. This guide shows you how to generate a module skeleton with scaffold, what each file is for, how to write a proper manifest, and how to install and upgrade a module while developing.

Updated: October 16, 2026 11 min read – views Vinc Academy Team

Quick summary

An Odoo 20 module needs only two files: __init__.py and __manifest__.py, and the manifest requires just one key, name. The odoo-bin scaffold command generates a standard skeleton. Put the module on the addons-path, enable developer mode, choose Update Apps List and install it; after changing code, upgrade it with -u.

What does a minimal Odoo module contain?

Every feature you write for Odoo lives in a module: a Python directory with its own declaration for Odoo. The conditions for Odoo to recognize that directory are small:

  • __init__.py: turns the directory into a Python package. It can stay empty at first; later it imports sub-packages such as models.
  • __manifest__.py: a file holding a single Python dictionary that describes the module. The only required key is name, but in practice you should declare more.

With these two files in a directory on the addons-path, Odoo can already list the module, even though it is still an empty shell with no features.

Check before you build

Before writing a new module, make sure Odoo (or a community addon repository) does not already solve the problem. Re-implementing something that exists is the most expensive kind of maintenance.

Generate a skeleton with odoo-bin scaffold

Instead of creating every file by hand, use the scaffold command. It takes the module name (required) and a destination directory (the current directory by default). In this series the example module is called vinc_course and manages courses:

cd ~/odoo-dev
python3 odoo/odoo-bin scaffold vinc_course custom-addons

The result is the custom-addons/vinc_course directory with the default structure:

vinc_course/
├── __init__.py
├── __manifest__.py
├── controllers/
│   ├── __init__.py
│   └── controllers.py
├── demo/
│   └── demo.xml
├── models/
│   ├── __init__.py
│   └── models.py
├── security/
│   └── ir.model.access.csv
└── views/
    ├── templates.xml
    └── views.xml

Note that most of the content inside the sample files is commented out, so the generated module is a hint-filled skeleton, not a working feature. You will uncomment or rewrite it as needed.

What each file and folder is for

ItemRoleCovered in
__init__.py (root)Imports controllers and models so Python loads the module's codeThis part
__manifest__.pyDeclares name, version, dependencies and the list of data filesThis part
models/Python classes that define models and fields, mapped to PostgreSQL tablesPart 4
security/ir.model.access.csvAccess rights per model for each user groupPart 5
views/views.xmlViews, actions and menus for the backend interfacePart 6
views/templates.xmlQWeb templates, used by web pages returned from controllersParts 10, 12
controllers/HTTP routes of the modulePart 12
demo/demo.xmlSample data, loaded only when the database is in demo modeWhen needed

Notice one detail in the generated skeleton: the security/ir.model.access.csv line in the manifest's data list is commented out. When you declare your first model, remember to uncomment it, otherwise the access file will not be loaded.

Key fields of __manifest__.py

KeyTypeMeaning
namestr, requiredModule name shown to users
versionstrRelease number of the module; use semantic versioning
summary / descriptionstrShort / long description (long one in reStructuredText)
author, website, maintainerstrAuthorship info; if maintainer is omitted, the author is assumed to maintain the module
categorystr, default UncategorizedBusiness area. Category names are free text and a new name creates the category automatically; use / to create child levels
licensestr, default LGPL-3Distribution license: GPL-2/3, AGPL-3, LGPL-3, OEEL-1, OPL-1, Other OSI approved licence, Other proprietary
dependslist[str]Modules Odoo has to load ahead of yours
datalist[str]Files always loaded on install or upgrade, written as paths relative to the module folder
demolist[str]Files loaded only in demo mode
applicationbool, default FalseTrue for a full application; False for a technical module that supports another app
installablebool, default TrueControls whether users can add the module through the web interface
auto_installbool or list, default FalseInstalls itself once its dependencies are installed. Often used for "glue modules", e.g. sale_crm linking sale and crm
external_dependenciesdictPython libraries (key python) or executables (key bin) that must exist on the machine; if missing, the module cannot be installed
assetsdictHow static files (JS, CSS) are added to bundles; we will meet it again in the OWL part
pre_init_hook, post_init_hook, uninstall_hookstrNames of functions in __init__.py, each receiving env, run before install, after install and after uninstall. Use only when the normal way is not possible
sequenceint, default 100Position in the Apps list, lower numbers come first

The easiest way to understand depends is to compare it with a package manager such as apt: when your module is installed, Odoo first installs everything it depends on; when a base module is removed, every module depending on it is removed too. base exists in every database, yet you should still list it in depends so your module is upgraded whenever base is.

About the version key

Odoo's reference only asks you to follow semantic versioning. Vinc Academy recommends adding the Odoo series as a prefix, such as 20.0.1.0.0, so you can tell at a glance that a module targets Odoo 20 and which release it is. This is our convention, not a framework requirement.

Hands-on: a manifest for vinc_course

Open custom-addons/vinc_course/__manifest__.py and replace its content with the compact version below. We have no views or models yet, so data stays empty for now:

custom-addons/vinc_course/__manifest__.py

{
    'name': "Vinc Course",
    'version': '20.0.1.0.0',
    'summary': "Manage courses and students",
    'author': "Vinc Academy",
    'website': "https://vinc-academy.vercel.app",
    'category': 'Education',
    'license': 'LGPL-3',
    'depends': ['base'],
    'data': [],
    'application': True,
}

Because application is True, the module shows up in Apps even while the default Apps filter is on. With False you would have to remove that filter to see it.

You can leave the generated controllers folder alone even if you do not use it yet. If you want a leaner module, delete the line from . import controllers in __init__.py first rather than the folder, to avoid import errors.

Installing and upgrading a module

From the interface

  1. Restart the server so Odoo sees the new files, with the folder containing custom-addons in --addons-path.
  2. Enable developer mode (covered in part 2). Without it you will not see the button needed in the next step.
  3. Go to Apps, choose Update Apps List and confirm.
  4. Search for Vinc Course and click install.

From the command line

For everyday development the command line beats clicking. Both parameters go together with -d (database name):

# first install
python3 odoo-bin --addons-path=addons,../custom-addons \
    -d odoo20_dev -i vinc_course

# after changing code or XML/CSV files, upgrade the module
python3 odoo-bin --addons-path=addons,../custom-addons \
    -d odoo20_dev -u vinc_course
OptionUse it when
-i vinc_courseInstalling a module for the first time; separate several modules with commas
-u vinc_courseUpdating a module after changes; -u all updates everything
--reinit vinc_courseReloads like an upgrade but skips upgrade scripts, and also affects data flagged noupdate
--dev=xmlReads views straight from the XML files, so you need not upgrade after tweaking the UI

A quick rule: change Python code, restart the server (or use --dev=reload); change files listed in data, upgrade the module with -u. Never use --dev in production.

Module missing or will not install?

SymptomWhat to check
Module not listed in AppsDid you remove the Apps filter (or set application: True)? Is developer mode on and did you click Update Apps List?
No Update Apps List buttonDeveloper mode is not enabled
Odoo cannot find the module folderThe folder containing modules must be in --addons-path; the module root needs both __init__.py and __manifest__.py
Edited a file in data but nothing changedYou have not upgraded with -u
Module will not install because of a missing libraryCheck external_dependencies: the Python library or executable listed there must exist on the machine

Two mistakes beginners often make

  • Creating a new XML/CSV file but forgetting to list it in data. Only files in the data list are loaded on install or upgrade. Add its path (relative to the module root, e.g. views/course_views.xml) and upgrade with -u.
  • Using an external Python library without declaring it. List the library in external_dependencies; if it is missing on the machine, Odoo refuses to install the module, so you learn the cause at once instead of hitting an error later at runtime.

FAQ

What is the minimum a module needs? ▾
Two files: __init__.py and __manifest__.py. The manifest only requires the name key, but you should also declare a version, author, dependencies and the list of data files.
Why does my new module not show up in Apps? ▾
There are three common causes: the Apps filter is switched on while the module does not set application to True, developer mode is off or you did not click Update Apps List, or the module folder is not on --addons-path.
What is the difference between -i and -u in odoo-bin? ▾
-i installs a module for the first time, -u updates an installed module after you change code or data files. Both must be used together with -d to name the database.
Do I have to list base in depends? ▾
Odoo always installs base, but the documentation recommends declaring it in depends anyway so that your module is upgraded whenever base is upgraded.
