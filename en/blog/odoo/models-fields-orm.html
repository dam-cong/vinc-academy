Odoo 20 Models, Fields and ORM: Build Your First Model

The model is the heart of every Odoo module. This guide shows how to declare a model in Python, pick the right field types, and use recordsets to add, find, edit and delete data without writing SQL.

Updated: October 16, 2026 13 min read Vinc Academy Team

Quick summary

In Odoo 20, each data table is declared by a Python class extending models.Model, and _name is its required attribute. Columns are fields.* attributes (Char, Integer, Selection…). After editing a Python file, restart the server with -d and -u so the ORM creates the table and columns in PostgreSQL. You read and write data through recordsets with create, search, write and unlink.

What are models and the ORM?

The ORM (Object-Relational Mapping) is a layer that lets you work with data as Python objects instead of hand-writing most SQL. Each model is a class extending models.Model; Odoo reads that declaration, creates the matching PostgreSQL table, and adds access-control and extensibility services on top.

The smallest model definition is just _name, a dotted identifier such as vinc.course. Odoo's tutorial notes that this alone gives the ORM enough information to create a table; the table name comes from _name with dots replaced by underscores, so vinc.course becomes the table vinc_course.

File layout convention

Keep all models in a models/ folder, one Python file per model. That file is imported in models/__init__.py, and the models folder is imported in the module's root __init__.py (the scaffold from part 3 already does this last step).

Your first model: vinc.course

We continue the vinc_course module from the previous part and add a course model. Create models/course.py:

custom-addons/vinc_course/models/course.py

from odoo import fields, models


class VincCourse(models.Model):
    _name = 'vinc.course'
    _description = "Course"

    name = fields.Char(string="Course name", required=True)
    description = fields.Text()
    start_date = fields.Date()
    duration_hours = fields.Integer(help="Total hours of teaching")
    price = fields.Float()
    is_published = fields.Boolean(default=False)
    level = fields.Selection(
        [('beginner', "Beginner"), ('intermediate', "Intermediate"), ('advanced', "Advanced")],
        default='beginner',
    )

custom-addons/vinc_course/models/__init__.py

from . import course

The __init__.py generated by scaffold imports the sample models.py; replace that line with the course import shown above.

Any change to Python files requires a server restart. Since we just added a new model, the module must be upgraded so the ORM applies the schema change to the database. Remember that -u always goes together with -d:

python3 odoo-bin --addons-path=addons,../custom-addons \
    -d odoo20_dev -u vinc_course

On startup the log may warn that the model has no access rules. That is expected at this stage and is fixed in part 5. Check that the table exists using psql:

psql -d odoo20_dev -c "\d vinc_course"

In the output, besides the columns you declared there are a few you did not write. Those are the automatic fields covered below.

Configuration attributes of a model

Besides _name and _description, a model has several optional underscore attributes:

AttributeDefaultMeaning
_nameNoneDotted model name; required for a new model
_descriptionNoneThe model's everyday name; leaving it out makes the log warn
_order'id'Default ordering of search results
_rec_namenameThe field used to label records
_tableDerived from _nameThe SQL table name when the model has a table
_autoTrue for ModelWhether a database table is created
_log_accessFollows _autoWhether the access-log fields (create_date, write_uid…) are generated and maintained
_inherit, _inheritsEmptyModel inheritance; see part 9

There are three base classes for models: Model (stored in the database, used most of the time), TransientModel (temporary data, used for wizards) and AbstractModel (no table; a base class for other models to inherit from).

Basic field types

Fields are class attributes that determine which data a model holds and how it is persisted. There are two groups: simple fields (plain values that live as columns of the model table) and relational fields (linking records together, covered in part 7).

FieldPython typePostgreSQL columnUse it for
Charstrcharacter varyingSingle-line strings: names, codes, postcodes
TextstrtextLong, multi-line text
IntegerintintegerWhole numbers: hours, rooms
Floatfloatdouble precisionDecimal numbers: prices, areas
BooleanboolbooleanYes/no flags: published, has garage
DatedatedateA date without time
Selectionstrcharacter varyingOne choice from a fixed list of (value, label) pairs

For Selection, the selection attribute is mandatory (except for extended or related fields). The value stored in the database is the first item of each pair; the second item is the label shown to users.

Common field attributes

AttributeDefaultEffect
stringCapitalized field nameLabel shown in the interface
requiredFalseA value is mandatory; it needs a default or must always be passed on creation. The database column becomes not null
helpEmptyExplanatory tooltip for users
defaultNoneDefault value: a fixed value or a function
readonlyFalseAffects the UI only; assigning the value from code still works
indexFalseAsks the database to index this column

A few more useful field attributes

  • copy: whether the value is carried over when a record is duplicated (True for ordinary fields). A Char field called name is flagged by default so duplicates get a "(copy)" label.
  • groups: a comma-separated string of groups allowed to access the field; details in part 5.
  • index: besides True/False it can be "btree" (a standard index, good for Many2one), "btree_not_null" (skips NULL values) or "trigram" (a GIN index, good for text search).
  • translate (Char, Text) makes the value translatable; size caps the length of a Char.
  • A Float's digits is a pair (total digits, decimals). For quantities tied to a unit of measure, use Float.round(), is_zero() and compare() so comparisons respect the precision.

Automatic fields

Odoo adds a few fields to every model. The system manages them: you can read them but not write them:

  • id: the unique identifier of a record.
  • create_date and create_uid: the creation time and author of the record.
  • write_date and write_uid: the time and author of the latest edit.

So you never need to design "created on" or "created by" columns for each table.

Recordsets and CRUD with the ORM

All interaction with models goes through recordsets: an ordered group of rows from one model, anywhere between empty and the whole table. Looping over a recordset hands you each record separately. The easiest place to experiment is odoo shell, where env is already available:

python3 odoo-bin shell -c ~/odoo-dev/odoo20.conf -d odoo20_dev
Course = env['vinc.course']

# Create: build a record from a dict
course = Course.create({'name': "Odoo Developer Foundation", 'duration_hours': 24})

# Read: access fields as attributes
course.name            # 'Odoo Developer Foundation'
course.level           # 'beginner' (the default value)

# Search: filter with a domain, a list of conditions
Course.search([('level', '=', 'beginner')])
Course.search_count([])          # count records
Course.browse(course.id)         # fetch by id

# Update: assign directly or use write
course.duration_hours = 32
course.write({'is_published': True})

# Delete
course.unlink()

env.cr.commit()        # only when you really want to save to the database

A few things worth remembering about recordsets:

  • The domain passed to search is a list of (field name, operator, value) triples; an empty list matches everything. You can cap results with limit, skip with offset and sort with order.
  • A relational field gives back a recordset even when nothing is set; it is simply empty.
  • To total a field over many records, use mapped(), e.g. sum(courses.mapped('duration_hours')).
  • When a method only accepts one record, call self.ensure_one() at the top so it fails early if it receives several.
  • Odoo caches and prefetches data to avoid repeated queries, so looping over a recordset is usually faster than querying record by record.

The parameters of search

Course.search([('is_published', '=', True)], order='start_date desc', limit=10, offset=20)

order is the sort string, limit the maximum number of records returned (all by default) and offset how many records to skip (none by default), handy for pagination. If the user lacks read access, search raises AccessError. It is a high-level method that should not be overridden; to count, use search_count().

Common mistakes when learning the ORM

  • Adding a field in code but not seeing it in the interface or database. For Python files, reloading the browser is not enough: restart the server, and for the ORM to add the new column to the table you must run with -d db_name -u module_name.
  • Reading records.name on a multi-record recordset. For non-relational fields the documentation says this raises an error, since the ORM cannot tell which record's value you mean. Loop with for record in records, or use mapped('name') if you need the list of values.
  • Giving a field the same name as a method in the same class. The documentation warns that the later declaration silently overwrites the earlier one. Start method names with _compute_, action_ and so on to avoid clashes.

Keep state out of module-level globals

One Odoo process may serve several databases at once, each with its own set of installed modules. Data stored in a Python global would leak between them, so keep it in records instead.

Summary

  • A model is a class extending models.Model with a required _name; the ORM generates the table.
  • Fields declare columns; attributes such as required, default, copy and index tune behavior.
  • All data access goes through recordsets: create, search, browse, write, unlink.
  • Python edits need a restart; new columns need -u together with -d.

FAQ

How is the PostgreSQL table named? ▾
Odoo takes the model _name and replaces dots with underscores. For example the model vinc.course creates the table vinc_course.
Why is there no column after I added a new field? ▾
Restart the server and run with -d and -u plus the module name so the ORM applies the schema change. Saving the Python file or reloading the browser is not enough.
Where do id, create_date and write_date come from? ▾
They are automatic fields Odoo adds to every model: id, create_date, create_uid, write_date and write_uid. You can read them but not write them.
Should I use search or browse to query records? ▾
search filters records with a domain, while browse fetches records from ids you already know. Both return a recordset.
