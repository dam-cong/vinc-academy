Odoo 20 Many2one, One2many and Many2many: Relations Between Models

Real-world data is always connected. This guide explains Odoo's three relational fields, how to pick the right one and how to read and write relational data, using a course module with categories, tags and sessions.

Updated: October 16, 2026 15 min read – views Vinc Academy Team

Quick summary

Odoo has three relational fields: Many2one (many records pointing to one, shown as a dropdown), One2many (the list of records pointing back, seen from the opposite side of a Many2one) and Many2many. Naming convention: a Many2one ends in _id, the other two end in _ids. The value of a relational field is always a recordset.

Why do models need relations?

Real applications rarely get by with one lonely model. A course belongs to a category, has an instructor, carries several tags and consists of many sessions. Instead of copying information in several places, Odoo lets models link to each other through relational fields. In this part the vinc_course module grows by three new models:

New modelRelation to vinc.courseRelational field
vinc.course.categoryA category holds many courses; a course has one categoryMany2one
vinc.course.tagA course has many tags; a tag applies to many coursesMany2many
vinc.course.sessionA course has many sessions; each session belongs to one courseOne2many (inverse of a Many2one)

Many2one: a single link to another record

A Many2one is a plain link to one record of another model, usually rendered as a dropdown in forms. A course belongs to one category, while a category can be set on many courses. Create the category model first:

custom-addons/vinc_course/models/course_category.py

from odoo import fields, models


class VincCourseCategory(models.Model):
    _name = 'vinc.course.category'
    _description = "Course category"

    name = fields.Char(required=True)

Then add fields to the vinc.course model (the models/course.py file from part 4):

category_id = fields.Many2one('vinc.course.category', string="Category")
instructor_id = fields.Many2one(
    'res.users', string="Instructor", default=lambda self: self.env.user)
  • The first argument is comodel_name, the target model. You must always supply it, unless the field is related or inherited.
  • Reach the data on the other side with dot notation: course.category_id.name. When nothing is set, you get an empty recordset.
  • The two most common targets are res.partner (a real person or an organization, even just a contact address) and res.users (system users, either internal or portal).
  • ondelete decides what happens when the referenced record is deleted: 'set null', 'restrict' or 'cascade'.

Reading the current environment

The self.env object is a handy toolbox. Use self.env.user to get whoever is logged in, self.env.uid for the numeric id, self.env.context for the context dictionary, self.env.ref('xml_id') to fetch a record by external id, and self.env['model.name'] to reach any model. The example above relies on self.env.user so the instructor defaults to the person logged in.

Many2many: many on both sides

A Many2many works in both directions: each record on either side may be tied to several records on the opposite side. A course has several tags ("hands-on", "for beginners") and a tag applies to several courses.

custom-addons/vinc_course/models/course_tag.py

from odoo import fields, models


class VincCourseTag(models.Model):
    _name = 'vinc.course.tag'
    _description = "Course tag"

    name = fields.Char(required=True)
# add to vinc.course
tag_ids = fields.Many2many('vinc.course.tag', string="Tags")

The value is a recordset, so you iterate with a loop. Recordsets behave like Python collections (len(), looping) and can be merged with recs1 | recs2:

for tag in course.tag_ids:
    print(tag.name)

In a form view, add widget="many2many_tags" so tags display compactly as badges: <field name="tag_ids" widget="many2many_tags"/>.

The intermediate table holding these links gets a name Odoo derives from the two model names. You can set it explicitly with relation, column1 and column2 when needed.

One2many: the list pointing back

A One2many mirrors a Many2one from the other side. Each session belongs to exactly one course (Many2one), and from a course we want to see all its sessions (One2many). So you declare the Many2one on the "many" side first:

custom-addons/vinc_course/models/course_session.py

from odoo import fields, models


class VincCourseSession(models.Model):
    _name = 'vinc.course.session'
    _description = "Course session"

    name = fields.Char(required=True)
    course_id = fields.Many2one('vinc.course', required=True, ondelete='cascade')
    session_date = fields.Datetime()
# add to vinc.course
session_ids = fields.One2many('vinc.course.session', 'course_id', string="Sessions")

The first argument is comodel_name; the second is inverse_name, the Many2one in the target model that this field reflects. Both must be supplied, again unless the field is related or inherited. The value contains every target record whose course_id points to the current course.

A One2many is a "virtual" relation

Since a One2many creates no column, the target model must already hold the matching Many2one. This is also why, when you create a record through a One2many, Odoo fills in the inverse Many2one (course_id) for you, so it need not appear in the child row's view. And not every model needs its own action or menu: the "session" model is only reached through a course, so it needs neither.

Writing to One2many and Many2many

These two field types take a list of commands (Command) to change the relation rather than a plain list of ids. Seven exist: link, unlink, set, clear, create, update and delete. For example in odoo shell:

from odoo import Command

tag = env['vinc.course.tag'].create({'name': "Hands-on"})
course.write({
    'tag_ids': [Command.link(tag.id)],
    'session_ids': [Command.create({'name': "Session 1"})],
})
env.cr.commit()

The seven Command operations

Each operation is really a triplet whose first element is an integer code. In Python, build them with the Command helper functions instead of typing triplets by hand:

CodeOperationEffect
0Command.create(values)Creates a new record in the target model and links it. On a One2many it creates one record for each record in self
1Command.update(id, values)Writes values onto the related record
2Command.delete(id)Removes the related record from the database and drops the link. On a Many2many the removal may be refused while the record is still linked elsewhere
3Command.unlink(id)Drops only the link. On a One2many the record is deleted when the inverse field has ondelete='cascade'; otherwise the inverse is set to False and the record stays
4Command.link(id)Adds a link to an existing record
5Command.clear()Removes every link, like unlink on each record
6Command.set(ids)Replaces all current links by the given list of ids (unlinking the surplus, linking the new)

When calling over RPC

Over RPC (including the JSON-2 API of part 12) neither the helper functions nor the constant names exist. You must send the literal triplet with its numeric code, e.g. [[4, 12, 0]] to link the record with id 12.

Do not forget the files that come with a new model

Every new model brings a few repeated chores, the same ones you did in parts 4 to 6:

  1. Import the new Python file in models/__init__.py (from . import course_category, course_tag, course_session).
  2. Add an access line per model to ir.model.access.csv, e.g. access_vinc_course_category_user,vinc.course.category user,model_vinc_course_category,base.group_user,1,1,1,1.
  3. Add an action, menu and views for the new model if users should manage it, and surface the new fields in the course views.
  4. Upgrade with -u vinc_course.

Common mistakes when learning relations

  • A new model that users cannot see, or that Odoo does not load. Usually one of these steps was skipped: importing the file in __init__.py, declaring the data file in data, or adding access rights for the new model. Check all three and read the startup log.
  • Two Many2many fields to the same target model within one model. Without an explicit relation parameter both would share one link table, which the ORM rejects. Give each field its own relation, column1 and column2.
  • Writing a One2many but forgetting the Many2one it mirrors. inverse_name must name a real Many2one field in the target model. Declare the Many2one first, then the One2many.

Summary

  • A Many2one stores a foreign-key column and shows as a dropdown; a One2many is its virtual inverse; a Many2many uses a link table.
  • Naming convention: _id for Many2one, _ids for the other two.
  • Write to One2many/Many2many with Command; over RPC use numeric triplets.
  • Every new model needs an import, access rights and a module upgrade.

FAQ

How do Many2one and One2many differ? ▾
A Many2one is a single link to one record of another model, stored as a column in the table. A One2many works the other way around: the target records pointing back at the current one, so it needs an inverse_name naming a Many2one.
When should I use Many2many? ▾
When each record on either side may be tied to several on the opposite side, such as courses and tags. Odoo stores this relation in a link table.
How should relational fields be named? ▾
By convention a Many2one ends in _id (for example category_id), while One2many and Many2many end in _ids (for example tag_ids).
Why not assign a plain list of ids to a relational list field? ▾
They take a list of Command operations (link, unlink, set, create and more), so every change to the relation is explicit instead of replacing the whole list of ids.
