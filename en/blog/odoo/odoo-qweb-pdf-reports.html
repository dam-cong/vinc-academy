PDF Reports with QWeb in Odoo 20

Invoices, slips and quotations are all PDF reports. This guide shows how to write QWeb templates, declare a report action, choose a paper format and handle the common wkhtmltopdf problems.

Updated: October 16, 2026 15 min read – views Vinc Academy Team

Quick summary

In Odoo 20 a PDF report is authored with HTML and QWeb, then converted to PDF by wkhtmltopdf. You need two things: a report action (ir.actions.report) and a QWeb template whose id matches the action's report_name. Inside the template, t-foreach, t-if, t-out, t-field and t-call are the directives you will use most.

QWeb: Odoo's template language

QWeb is Odoo's main XML templating engine, mostly producing HTML snippets and pages: kanban cards, website pages and PDF reports. Directives are XML attributes starting with t-; the <t> element is a placeholder that runs its directive without emitting any markup of its own.

DirectivePurpose
t-if, t-elif, t-elseConditional rendering; when the condition is false the element disappears from the output
t-foreach + t-asLoop over a collection; t-as names the current item
t-outPrints the value of an expression, HTML-escaping it automatically to limit XSS risk
t-set + t-valueAssigns a variable
t-callIncludes another template
t-fieldPrints a record field and formats it according to the field type; works only on field access (a.b) of a record returned by the ORM
t-att-*, t-attf-*Sets HTML attributes dynamically

What makes up a report?

Each PDF report needs:

  1. A report action (a ir.actions.report record): states which model the report covers, its type and which template to use.
  2. A QWeb template: the report's HTML content.
  3. (Optional) A paper format: page size, margins, orientation.

Key attributes of the report action: name (required), model (required, the model the report is about), report_type (qweb-pdf unless you pick qweb-html), report_name (required, the external id of the template) and print_report_name (a Python expression naming the file). For the print button to show in a form's Print menu, also set binding_model_id.

Hands-on: a course information sheet

Create reports/vinc_course_report.xml and declare it in the manifest's data:

custom-addons/vinc_course/reports/vinc_course_report.xml

<odoo>
    <record id="action_report_vinc_course" model="ir.actions.report">
        <field name="name">Course sheet</field>
        <field name="model">vinc.course</field>
        <field name="report_type">qweb-pdf</field>
        <field name="report_name">vinc_course.report_course</field>
        <field name="binding_model_id" ref="model_vinc_course"/>
    </record>

    <template id="report_course">
        <t t-call="web.html_container">
            <t t-foreach="docs" t-as="course">
                <t t-call="web.external_layout">
                    <div class="page">
                        <h2 t-field="course.name"/>
                        <p>Level: <span t-field="course.level"/></p>
                        <p>Duration: <span t-field="course.duration_hours"/> hours</p>
                        <table class="table table-sm">
                            <thead><tr><th>Session</th><th>Ngày</th></tr></thead>
                            <tbody>
                                <tr t-foreach="course.session_ids" t-as="session">
                                    <td><span t-field="session.name"/></td>
                                    <td><span t-field="session.session_date"/></td>
                                </tr>
                            </tbody>
                        </table>
                    </div>
                </t>
            </t>
        </t>
    </template>
</odoo>
  • web.html_container wraps the report's HTML skeleton.
  • web.external_layout adds the company's default header and footer; the PDF body is whatever sits inside <div class="page">.
  • docs holds the records being printed, doc_ids their ids and doc_model their model. Templates also always get time, user, res_company, web_base_url and a context_timestamp helper that converts UTC times to the printing user's timezone.
  • The template id (report_course) prefixed with the module name (vinc_course.) must equal the action's report_name.

Upgrade with -u vinc_course, open a course, choose Print and then Course sheet to download the PDF.

wkhtmltopdf and paper format

Converting HTML to PDF is the job of wkhtmltopdf. Odoo 20 recommends version 0.12.6 so that PDFs get headers and footers, and it must be installed manually rather than through pip. Templates may use Bootstrap and FontAwesome classes, and local CSS can sit right inside the template.

A paper format is a record of the report.paperformat model with attributes such as format (A4 by default, or custom), orientation (Portrait/Landscape), margin_* (mm), dpi (default 90), header_line and header_spacing. Attach it to a report through paperformat_id; without one, the company's format applies.

Viewing a report as a web page

Reports are generated dynamically and reachable by URL, which is handy while styling because you can inspect the HTML right in the browser:

http://localhost:8069/report/html/vinc_course.report_course/1
http://localhost:8069/report/pdf/vinc_course.report_course/1

The trailing number is the id of the record to print.

Custom reports: feeding extra data to the template

Normally the data used for rendering is taken from the report's own model. To bring in data from other models, define an abstract model named report.<module>.<report_name> with a _get_report_values(docids, data=None) method; Odoo looks for this model first and uses what it returns as the rendering context:

from odoo import api, models


class ReportCourse(models.AbstractModel):
    _name = 'report.vinc_course.report_course'

    def _get_report_values(self, docids, data=None):
        courses = self.env['vinc.course'].browse(docids)
        return {
            'doc_ids': docids,
            'doc_model': 'vinc.course',
            'docs': courses,
            'total_hours': sum(courses.mapped('duration_hours')),
        }

Note: in a custom report the stock variables docs, doc_ids and doc_model are not added for you; if the template needs them, return them yourself as in the example.

More report action options

AttributeEffect
groups_idRestricts who may see and run the report to these groups
multiWhen True the action is hidden on form views (it appears only when several records are selected in a list)
paperformat_idChooses the page layout; without it the company's default applies
attachment_useWhen True the report is generated once, on first request, and later prints come from the stored copy instead of being rebuilt. Meant for documents that must be produced only once (for legal reasons, say)
attachmentA Python expression naming the stored report; the record is available as object
print_report_nameA Python expression naming the downloaded PDF; name is used when it is not set

For instance, to name the file after the record, print_report_name could be 'Sheet-%s' % (object.name).

Printing in the customer's language

To print a report in each partner's language, split it into two templates: a main one and a translatable document template. The main template includes the document template and passes t-lang, holding either a language code (fr, en_US…) or a field of the record. If you show translatable fields (country names, sales terms…), re-read the record under the right context using with_context(lang=...):

<template id="report_course">
    <t t-call="web.html_container">
        <t t-foreach="docs" t-as="doc">
            <t t-call="vinc_course.report_course_document"
               t-lang="doc.instructor_id.lang"/>
        </t>
    </t>
</template>

<template id="report_course_document">
    <t t-set="doc" t-value="doc.with_context(lang=doc.instructor_id.lang)"/>
    <t t-call="web.external_layout">
        <div class="page"><h2 t-field="doc.name"/></div>
    </t>
</template>
  • If just the body should be translated and the page frame left in one fixed language, include the layout as <t t-call="web.external_layout" t-lang="en_US">.
  • t-lang works only together with t-call to an external template; put on a plain XML node it has no effect. To translate one fragment, give it a template of its own and include that with t-lang.
  • If the template shows no translatable fields, do not re-read the record under another language, which would just waste resources.

Barcodes, CSS and custom fonts

  • Barcodes / QR codes: they are images served by a controller and embedded in a report through QWeb: <img t-att-src="'/report/barcode/QR/%s' % 'your text'"/>. More parameters travel in the query string, such as barcode_type, value, width and height.
  • CSS: Bootstrap and FontAwesome classes are usable, and local CSS can sit inside the template. Global CSS goes in by inheriting the report layout template (inherit_id="report.style") and adding styles with an xpath.
  • Custom fonts: the font and its LESS/CSS must be added to the web.report_assets_common bundle. Registering them in web.assets_common or web.assets_backend will not expose the font to report templates. You must also declare @font-face inside that LESS file, even if it was already declared in another bundle.

A complete paper format example

<record id="paperformat_course_a5" model="report.paperformat">
    <field name="name">Course sheet A5</field>
    <field name="format">A5</field>
    <field name="orientation">Landscape</field>
    <field name="margin_top">20</field>
    <field name="margin_bottom">15</field>
    <field name="margin_left">10</field>
    <field name="margin_right">10</field>
    <field name="header_line" eval="False"/>
    <field name="header_spacing">10</field>
    <field name="dpi">90</field>
</record>

Only name is mandatory. If you give explicit page dimensions (page_height, page_width in mm), set format to custom, because a predefined size cannot be combined with hand-set dimensions.

Common mistakes when building reports

  • Clicking print produces nothing, or Odoo cannot find the template. Check the action's report_name: it has to read module_name.template_id. A template id="report_course" in module vinc_course corresponds to vinc_course.report_course.
  • The PDF lacks header, footer or styling. Check which wkhtmltopdf is installed. The documentation says 0.12.6 is needed for header/footer, and global CSS must be added by inheriting the report layout template.
  • The template uses docs but a custom report does not provide it. When you use _get_report_values, add docs, doc_ids and doc_model to the returned dict yourself.

Summary

  • A report = a report action (ir.actions.report) + a QWeb template whose id matches report_name.
  • web.html_container and web.external_layout provide the skeleton and header/footer; content goes in div.page.
  • Translating a report takes two templates and t-lang; custom fonts must go in web.report_assets_common.
  • wkhtmltopdf 0.12.6 is required for PDFs to have header/footer.

FAQ

What tool produces the PDF file in Odoo? ▾
Report layouts are authored with HTML and QWeb, and wkhtmltopdf performs the conversion to PDF. Odoo 20 recommends version 0.12.6 so PDFs get headers and footers, installed manually rather than through pip.
How does the report template connect to the report action? ▾
The action's report_name must equal the module name joined with the template id, for example vinc_course.report_course.
How do I make the print button appear in a form's Print menu? ▾
Declare the report action as an ir.actions.report record and set binding_model_id to the report's model.
When do I need a custom report with _get_report_values? ▾
When the template needs data from models other than the report's own. You must then return docs, doc_ids and doc_model yourself because the default variables are not added automatically.
