CV and GitHub Portfolio for IT Freshers: A Practical Guide

With no years of experience yet, your CV and GitHub are the only evidence of what you can do. This guide shows how to write a one-page IT CV, present projects with a simple formula, and turn GitHub into a portfolio recruiters actually want to open.

Updated: October 16, 2026 10 min read – views Vinc Academy Team

Quick answer

A fresher's IT application has three parts: a one-page CV, 2–3 GitHub projects with clear READMEs, and the ability to explain every line you wrote. The Projects section is the heart of the CV; each project should cover four points: the problem, your role, the tech and the result. GitHub needs few but solid repos, the right ones pinned, and absolutely no passwords.

What do recruiters look for in a fresher's profile?

As the IT career roadmap 2026 article showed, companies are hiring more selectively: according to TopCV, 52.2% chose to keep headcount steady and raise efficiency. For IT, the report notes that companies value hands-on experience shown through a project portfolio, while the skills candidates lack most are communication, critical thinking and product mindset.

For freshers, that means recruiters read your profile to answer three questions:

  1. What have you actually built? Not "what have you studied", but concrete products.
  2. Do you understand what you built? They'll test this in the interview, but a clear CV and README are the first signal.
  3. Can you present clearly? A tidy, focused CV is itself evidence of communication skills.

So your CV and GitHub are not separate things: the CV is the "cover page" that leads to GitHub, and GitHub proves what the CV claims.

The structure of a one-page IT CV

For newcomers, one page is enough and easiest to read. The table below is the structure Vinc Academy recommends to students, from top to bottom:

SectionIncludeAvoid
ContactFull name, a professional email, phone, GitHub link, LinkedIn (if any), cityID card number, full date of birth, detailed home address, nickname-style emails
Objective1–2 sentences on the role and direction you want, tied to the companyGeneric lines like "eager to learn and grow"
ProjectsYour 2–3 best projects, 3–4 lines each using the formula below, with linksListing project names without saying what you did
SkillsGrouped by type (languages, databases, tools); only what you used in projectsPercentage bars, "proficient" in ten technologies
EducationUniversity, major, graduation year; GPA if good; relevant coursesHigh-school details once you are at university
Activities / internshipsInternships, teaching assistant roles, clubs, coding contests, with concrete tasksUnrelated activities taking up space

A few simple formatting rules that are often skipped: export to PDF so the layout doesn't break, give the file a clear name (for example NguyenVanA_CV_Backend_Fresher.pdf), use one readable font, and put your GitHub link where it is visible at the top.

Common mistake: "proficient" in ten technologies

Situation: the CV lists Java, Python, C#, React, Vue, Docker, Kubernetes, AWS… with 80–90% bars. The interviewer picks Docker and digs in, and you've only followed a tutorial once.

Cause: every line on your CV is a potential interview question. Percentage bars measure nothing; they only raise expectations that then get disappointed.

Fix: list only technologies you used in projects on your CV, split into "used in projects" and "currently learning". Honesty steers the interview toward what you do well.

Writing the Projects section: a 4-point formula

This is the part recruiters read most carefully. Each project should cover four points: Problem → Role → Tech → Result. Compare two ways of writing the same project:

Weak

Course management website
- Used Python, PostgreSQL
- Built add, edit, delete features

Better

Course management system (team of 3, 10 weeks)                 github.com/…
- Problem: a training centre tracked classes, students and attendance in Excel,
  and numbers often didn't match across classes.
- Role: owned the back-end: designed 6 database tables, built the student and
  attendance APIs, wrote tests for the absence-count logic.
- Tech: Python, PostgreSQL, Git (feature branches and merge requests).
- Result: demoed to the lecturer with test data for 3 classes; the README covers
  setup, the data diagram and a list of planned improvements.

Note: only use numbers you actually measured (tables, APIs, test users, processing time before/after). Made-up numbers fall apart as soon as the interviewer asks "how did you measure that?".

Vietnamese or English CV?

Match the language of the job ad. Outsourcing companies working with overseas clients and companies with international teams often post in English, so send an English CV there. The safe approach is to keep two versions with the same content and, for each company, adjust the Objective and the order of projects to match the ad.

Turning GitHub into a portfolio

Recruiters often have only a few minutes per application. Your GitHub page should immediately show who you are and which projects are your best.

1. Profile README: your introduction

According to GitHub's documentation, you create a public repository named exactly like your username and add a README.md; its content then appears on your profile page. Keep it short: who you are, your direction, 2–3 highlighted projects and how to reach you.

github.com/nguyenvana/nguyenvana · README.md

## Hi, I'm Van A 👋
Final-year IT student focusing on **Back-end / ERP (Odoo)**.

**Featured projects**
- [vinc-course](link) – Course management: Python, PostgreSQL, with tests
- [shop-api](link) – Sales API: permissions, pagination, API docs

**Learning now:** Odoo 20, Docker basics
**Contact:** nguyenvana.dev@gmail.com

2. Pin the right projects

GitHub lets you pin up to 6 items (repositories or gists) on your profile via Customize your pins. Pin your 2–4 best projects, ordered by relevance to the role you're applying for. Half-finished exercise repos can be made private or archived to keep your profile clean.

3. A README for each project

GitHub's documentation suggests a README should say what the project does, why it's useful, how to get started, where to get help and who maintains it. For portfolio projects, Vinc Academy recommends this outline to students:

README.md (suggested outline)

# Vinc Course – Course management system

## Problem
A training centre needs to manage classes, students and attendance instead of Excel.

## Main features
- Manage courses, classes and students
- Attendance with an alert when a student misses more than 3 sessions

## Tech
Python 3.12 · PostgreSQL 16 · Git

## Data design
(diagram of the tables, or a short description of the main tables and relations)

## Getting started
1. Clone the repo, create a virtual environment, install from requirements.txt
2. Copy .env.example to .env and fill in the database settings
3. Run the tests, then run the app

## How AI was used
AI suggested test structure and reviewed for bugs; the data design and
attendance logic are my own, and every AI suggestion passed the tests.

## What I learned & next steps
- Learned how to write safe data migrations
- Next: role-based permissions for lecturers and students

The "How AI was used" section is a plus these days: it shows you use AI responsibly and understand your own work, which is exactly what interviewers will check.

4. Commit history and licensing

  • Small commits, clear messages: your history shows how you work. A single "update" commit containing the whole project is a bad sign. See the Practical Git series.
  • License: according to GitHub's documentation, a repository without a license falls under default copyright law: others can view and fork it on GitHub but may not copy, distribute or create derivative works. If you want to allow reuse, pick a license (GitHub points to choosealicense.com).

Common mistake: pushing passwords or a .env file to a public repo

Situation: racing a deadline, you commit the .env file with your database password or an API key and push it to a public repo for your CV. You notice later and delete the file in the next commit.

Cause: deleting it in a later commit doesn't remove it from history. GitHub's documentation is clear that even after rewriting history, the data may remain in clones, forks and caches, so the first step is always to revoke or rotate the exposed password or key.

Prevention: add .env to .gitignore from the start, commit only a .env.example with no real values, and check git status before every commit. A recruiter who sees credentials in your repo will rate your security awareness very low.

Where and how to apply

In Vietnam, IT freshers usually find jobs through IT-focused job platforms (such as ITviec and TopDev), general job platforms (such as TopCV), LinkedIn, company career pages and fanpages, internship/fresher programs at software companies, and university job fairs. Wherever you apply, the process should be the same:

  1. Read the job ad carefully and highlight the hard requirements and technology keywords.
  2. Adjust your Objective, project order and skills to match that ad (without inventing skills).
  3. If applying by email, add a short note: the role, why you fit, your GitHub link.
  4. Keep a log of where, when and for which role you applied, to follow up and prepare for interviews.

Summary

  • A fresher CV fits on one page, puts Projects first and keeps the GitHub link easy to find.
  • Each project covers four points: problem, role, tech, result; use only numbers you really measured.
  • List only skills you used in projects; every line on your CV is a potential interview question.
  • GitHub: a short profile README, 2–4 best projects pinned, a complete README per project including "how AI was used".
  • Never commit passwords or .env files; if one leaks, rotate it before doing anything else.

Frequently asked questions

Should an IT CV be in English or Vietnamese? ▾
Match the language of the job ad. If the ad is in English or the company works with overseas clients, send an English CV; if the ad is in Vietnamese, a Vietnamese CV is enough. Ideally keep both versions ready with the same content.
What do I put on my CV with no work experience? ▾
Put the Projects section before Experience. For each project, state the problem, your role, the tech and a verifiable result. Course projects, personal projects, club or competition team projects all count if you can explain the part you built.
How many GitHub repositories do I need? ▾
Not many. Two or three finished projects with clear READMEs beat dozens of half-done exercise repos. GitHub lets you pin up to 6 repositories or gists on your profile, so pin your best work.
Should I mention that I used AI in a project? ▾
Yes, and be specific: which parts you used AI for, how you verified the output and what you fixed when AI got it wrong. Recruiters want to know that you understand and own your code, not whether you used AI.
Does an IT CV need a photo? ▾
It is not required. Many IT companies only care about the content; if you add a photo, use a clear one with a plain background. For CVs sent to overseas companies, many don't expect a photo, so you can drop it to make room for projects.
