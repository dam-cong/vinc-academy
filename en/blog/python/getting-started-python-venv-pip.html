Getting Started with Python for Odoo Devs: venv and pip

Before writing Odoo code you need a clean Python environment with the right version. This guide covers installing Python 3.12, running scripts, creating a virtual environment and managing libraries with pip, using examples from a course management project.

Updated: October 16, 2026 9 min read Vinc Academy Team

Quick summary

Odoo 20 runs on Python 3.12 or newer. Give every project its own virtual environment (venv) and keep its libraries listed in requirements.txt. Check the version with python3 --version, create the environment with python3 -m venv .venv, activate it with source .venv/bin/activate, then install libraries using python -m pip install -r requirements.txt. This is the first step of the practical Python series: every example comes from the familiar vinc_course course-management project.

Installing Python and checking the version

Odoo 20 needs Python 3.12 or later (see part 2 of the Odoo series). After installing, verify with:

python3 --version
python3 -c "import sys; print(sys.version_info >= (3, 12))"

The second command prints True when the version is recent enough, handy inside an environment-check script. The interpreter usually lives at a path like /usr/local/bin/python3.12, so on a machine with several versions you can call python3.12 by name. On Windows, a Microsoft Store install provides the python3.12 command, and if the py.exe launcher is present you can use py.

Four ways to run Python

WayCommandUse it when
Interactive modepython3Trying an expression quickly; the prompt is >>>, leave with Ctrl+D or quit()
Run a script filepython3 course_info.pyRunning a complete program; odoo-bin is such a file too
Run one linepython3 -c "print('hello')"A quick check from the shell
Run a module as a scriptpython3 -m venv .venvUsing the tools that ship with Python

When you run a file, the file name and everything after it end up as a list of strings in sys.argv. Try it with the small script below:

course_info.py

import sys

course = "Odoo Developer Foundation"
hours = 24
print(f"Course: {course} - {hours} hours")
print("Command-line arguments:", sys.argv[1:])
$ python3 course_info.py abc 123
Course: Odoo Developer Foundation - 24 hours
Command-line arguments: ['abc', '123']

The same mechanism lets odoo-bin receive options such as -d, -u and --addons-path, which you typed many times in the Odoo series.

Virtual environments: one compartment per project

Python programs often rely on libraries beyond the standard one, and sometimes on one exact version. If program A wants library 1.0 while program B wants 2.0, installing either breaks the other. The fix is a virtual environment: a self-contained folder holding one Python plus the packages of a single project. For Odoo this lets Odoo 20 and an older project live side by side without interfering.

cd ~/odoo-dev
python3 -m venv .venv            # create the environment
source .venv/bin/activate        # activate (Linux/macOS)
# Windows: .venv\Scripts\activate
(.venv) $ python --version       # the prompt now shows (.venv)
(.venv) $ deactivate             # leave when finished
  • The venv command builds the environment with the very Python that ran it. Run it with python3.12 and you get 3.12.
  • A popular folder name is .venv: the leading dot keeps it tucked away in the shell and avoids a clash with .env files that hold environment variables.
  • A virtual environment does not belong in Git; treat it as disposable, easy to delete and recreate, never copied elsewhere. Add .venv/ to .gitignore.
  • Keep project code out of the environment folder.

What happens on Debian/Ubuntu

On some Debian/Ubuntu releases, python3 -m venv reports that the environment could not be created because ensurepip is missing and asks for the python3-venv package (for example sudo apt install python3-venv). Install it, create the environment again, and you are done.

Managing libraries with pip

With the environment active, use python -m pip to install libraries from the Python Package Index. Writing python -m pip instead of plain pip guarantees the package goes to the Python you are actually running.

CommandEffect
python -m pip install requestsInstalls the latest release of a package
python -m pip install requests==2.6.0Installs one exact version
python -m pip install --upgrade requestsUpgrades to the newest release
python -m pip uninstall requestsRemoves the package
python -m pip list / show requestsLists installed packages / shows details of one
python -m pip freeze > requirements.txtWrites the package list with versions to a file
python -m pip install -r requirements.txtInstalls everything in that file

The requirements.txt convention is exactly what you used when installing Odoo from source: the Odoo repository ships this file, and the "install dependencies" step in part 2 was just pip install -r requirements.txt inside a virtual environment. When a module you write needs an extra library, you also declare it in the manifest's external_dependencies (part 3).

Practice: set up the environment for vinc_course tooling

  1. Create a project folder and environment: mkdir vinc-tools && cd vinc-tools && python3 -m venv .venv.
  2. Activate it: source .venv/bin/activate and confirm the prompt shows (.venv).
  3. Install a library: python -m pip install requests (used in part 13).
  4. Record it: python -m pip freeze > requirements.txt.
  5. Save the course_info.py script above and run python course_info.py abc.

Expected result: the prompt shows (.venv), pip list includes requests, requirements.txt holds a few lines shaped like name==version, and the script prints two lines like the sample.

Common mistakes when starting out

  • Installing libraries before activating the environment. Once activated, python and pip point into that environment; if you skip it you install into the system Python and the Odoo venv still lacks the library. Look for (.venv) in the prompt before running pip.
  • Creating the venv with the wrong Python. A venv uses the version of the command that created it. If the machine's default is Python 3.10 and you run python3 -m venv, Odoo 20 will not qualify. Run python3.12 -m venv .venv (or newer) and confirm with python --version.
  • Copying the whole venv folder to another machine. Environments are not meant to move. Create a fresh one and install from requirements.txt.

Summary

  • Odoo 20 needs Python 3.12+; check with python3 --version.
  • Run Python interactively, as a script file, with -c or with -m; arguments arrive in sys.argv.
  • One .venv per project (kept out of Git), libraries installed with python -m pip.
  • requirements.txt lets you rebuild the environment elsewhere.

FAQ

Which Python version does Odoo 20 need? ▾
Odoo 20 requires Python 3.12 or later. Check it with python3 --version, or run python3 -c with a comparison on sys.version_info to print True when the version is recent enough.
Why should every project have its own virtual environment? ▾
Each virtual environment is a separate folder holding one Python plus its own packages, so one project can need library 1.0 while another needs 2.0 without conflict.
Should the venv folder go into Git? ▾
No. A virtual environment is disposable, easy to delete and recreate, and must not be copied elsewhere. Add it to .gitignore and rebuild it from requirements.txt.
What is the difference between pip install and python -m pip install? ▾
Both install packages, but python -m pip guarantees the package is installed for the exact Python you are running, which is safer when a machine has several versions.
