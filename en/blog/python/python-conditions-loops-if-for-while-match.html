Python Conditions and Loops: if, for, while, match

Conditions and loops are how a program makes decisions and processes data in bulk. This guide covers if, for, while and match using a course list, and shows why Odoo's for record in self is just the familiar for loop.

Updated: October 16, 2026 10 min read Vinc Academy Team

Quick summary

Conditions (if/elif/else) decide which code runs, and loops (for, while) repeat a block. Python marks blocks with indentation and a colon. The loop you will use most is for item in items, which is exactly the shape of for record in self in every Odoo model method. match (since Python 3.10) helps when one value has several branches.

Conditions: if, elif, else

Every branch ends with a colon and the block below it must be indented (by convention 4 spaces). Python checks branches from the top and runs the first true one. Example: classify a course's length by its hours:

def level_of(hours):
    if hours >= 24:
        return "long"
    elif hours >= 12:
        return "medium"
    else:
        return "short"

print(level_of(24), level_of(16), level_of(8))
# long medium short

You already know comparisons and and/or/not from the previous part. For lists, strings or the number 0 you can write if items: directly to test "has elements" without comparing a length.

One-line conditions and early checks

When you only need to pick between two values, use a conditional expression instead of a whole if/else block. This form appears all over Odoo compute methods, notably to avoid dividing by zero:

hours = 24
label = "long" if hours >= 24 else "short"          # long

price, duration = 4500000.0, 0
price_per_hour = price / duration if duration else 0.0   # 0.0, no division-by-zero error

For data validation, a good habit is to check early and exit early rather than nesting many if levels. Each failing condition returns at once and the success path sits last, flush with the left margin:

def check(course):
    if not course["name"]:
        return "Missing name"
    if course["hours"] <= 0:
        return "Hours must be greater than 0"
    if not course["published"]:
        return "Not published"
    return "OK"

print(check({"name": "", "hours": 8, "published": True}))     # Missing name
print(check({"name": "Git", "hours": 0, "published": True}))  # Hours must be greater than 0
print(check({"name": "Git", "hours": 8, "published": True}))  # OK

This structure mirrors an Odoo constraint method, except that instead of returning a string Odoo does raise ValidationError(...) (part 10). Another pattern you will meet is checking permissions before sensitive work, like the example in Odoo's security documentation: if self.state == "draft" and self.env.user.has_group('base.manager'):.

The for loop: visiting each item

We use a list of courses as sample data (each course is a dict, covered properly in part 4):

courses = [
    {"code": "ODO-F", "name": "Odoo basics", "hours": 24, "published": True},
    {"code": "PY-F", "name": "Python basics", "hours": 16, "published": True},
    {"code": "GIT-T", "name": "Git for teams", "hours": 8, "published": False},
]

total = 0
for course in courses:
    if not course["published"]:
        continue
    total += course["hours"]
print("Published hours:", total)
# Published hours: 40

On each pass the variable course receives one element. continue skips the rest of the current pass, and break leaves the loop entirely. In Odoo the same shape shows up in computed fields:

for course in self:
    course.session_count = len(course.session_ids)

Here self is a recordset (a set of records) and the loop hands each record to course. That is why for record in self opens so many compute, constraint and action_* methods.

A few details that are easy to miss

  • The loop variable outlives the loop. After for course in courses: pass, course still holds the last element. Do not rely on this, and name loop variables differently from outer ones so you do not overwrite them by accident.
  • pass is the "do nothing" statement, used when the syntax demands a block but you have not written one yet (for instance a skeleton method waiting for its body).
  • Avoid range(len(items)) just to get an index. It works but is wordy; use enumerate as in the table above.
  • any() and all() replace checking loops. any(c["hours"] > 20 for c in courses) returns True if at least one course exceeds 20 hours; all(...) is True only when every course qualifies. You have already seen any(course.is_published for course in self) in the delete-blocking example of the Odoo series.
  • while True with break is a familiar pattern when you must run at least once before knowing whether to continue.

while, break and the loop's else

while repeats as long as its condition holds, which fits cases where the number of repeats is unknown (for example retrying an API call until it succeeds):

n = 3
while n > 0:
    print("left", n)
    n -= 1
# left 3
# left 2
# left 1

Python also has a neat quirk: a loop may carry an else branch that runs when the loop ends normally (without break). It suits searching:

for code in ("ODO-F", "XYZ"):
    for course in courses:
        if course["code"] == code:
            print("Found", code)
            break
    else:
        print("Not found", code)
# Found ODO-F
# Not found XYZ

match: several branches by value

Since Python 3.10 the match statement compares a value against case patterns. A | combines values and _ is the default branch. Example: turning HTTP status codes from an API (part 13) into messages:

def status_message(code):
    match code:
        case 200:
            return "OK"
        case 401 | 403:
            return "No permission"
        case 404:
            return "Not found"
        case _:
            return "Other error"

print([status_message(c) for c in (200, 403, 404, 500)])
# ['OK', 'No permission', 'Not found', 'Other error']

Odoo 20 runs on Python 3.12+, so you may use match in new modules. Existing Odoo code is still mostly if/elif chains, so be able to read both.

Practice: a quick course list report

Write code that prints each course with its length, skips unpublished ones, then prints a total:

total = 0
for course in courses:
    if not course["published"]:
        continue
    print(course["code"], level_of(course["hours"]))
    total += course["hours"]
print("Total:", total)
# ODO-F long
# PY-F medium
# Total: 40

Try swapping continue for break to see the difference: the loop stops for good at the first unpublished course.

Common mistakes when starting out

  • Wrong or missing indentation. Forgetting to indent the block after if gives IndentationError: expected an indented block after 'if' statement on line 2. Use 4 spaces and never mix tabs with spaces.
  • A missing colon. if hours > 20 without : gives SyntaxError: expected ':'.
  • Changing a list while looping over it. The Python documentation warns that modifying a collection during iteration is hard to get right. Loop over a copy (for x in nums[:]:) or build a new list. For [1, 2, 3, 4], removing the even numbers from a copy correctly leaves [1, 3].
  • A while loop that never ends. Always change something in the loop body (like n -= 1) or include an explicit break.

Summary

  • if/elif/else runs the first true branch; blocks are recognised by a colon and indentation.
  • for item in iterable is the main loop; enumerate, zip and .items() make loops tidier.
  • break, continue and the loop else steer the flow; match handles many branches by value.
  • Odoo's for record in self is simply a for loop over a recordset.

FAQ

What is for record in self in Odoo? ▾
self is a recordset, a set of records. The for loop walks over each record and assigns it to record, so your method works even when it is called on several records at once.
What is the difference between break and continue? ▾
continue skips the rest of the current pass and moves to the next item, while break leaves the loop altogether.
When does the else branch of a for loop run? ▾
The else branch runs when the loop ends normally, meaning without a break. It suits searches: if nothing was found, else runs.
When should I use match instead of if/elif? ▾
When one value has several clear branches, such as HTTP status codes. match exists since Python 3.10, so it works in Odoo 20 modules running Python 3.12 or newer.
