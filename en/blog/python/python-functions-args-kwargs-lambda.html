Python Functions: Parameters, *args, **kwargs, lambda for Odoo Devs

An Odoo model method is just a Python function with an extra self. This guide teaches how to write functions, use default parameters, *args and **kwargs and lambda, and warns about the changeable-default trap that new developers often hit.

Updated: October 16, 2026 13 min read Vinc Academy Team

Quick summary

A function wraps a piece of logic into a named block you can reuse: def name(parameters): ... return result. You can give parameters defaults, pass them by name, and accept any number of arguments with *args and **kwargs. lambda is a nameless one-line function, very common as a field default and as an argument to filtered and sorted. An Odoo model method is just a function with an extra self.

Defining a function and returning a value

A function is declared with def, named in snake_case, with an indented body. The string right at the top of the body is the docstring, describing the function to readers and help tools. A function hands back a value with return; one with no return (or a bare return) gives back None.

def price_per_hour(price, hours=1):
    """Price per hour; returns 0.0 when hours is 0."""
    if not hours:
        return 0.0
    return price / hours

print(price_per_hour(4500000, 24))      # 187500.0
print(price_per_hour(price=100, hours=4))   # 25.0 (passed by name)
print(price_per_hour(50))               # 50.0 (hours uses its default of 1)

There are two ways to pass arguments: by position (price_per_hour(4500000, 24)) or by name (price=100, hours=4). A parameter with a default (hours=1) may be left out in a call, but it must come after the parameters without defaults, or Python raises SyntaxError: parameter without a default follows parameter with a default.

def show(*args, **kwargs):
    print(args, kwargs)

show(1, 2, name="Odoo", hours=24)
# (1, 2) {'name': 'Odoo', 'hours': 24}

nums = [1, 2]

print(*nums, **opts)    # 1-2   (unpack a list and a dict into arguments)

**kwargs (shortened to **kw) is something you meet constantly in Odoo controllers: the skeleton produced by odoo-bin scaffold already contains def index(self, **kw) to receive any query parameters from the URL without declaring each one.

The biggest trap: a changeable default value

A default value is created only once, when the function is defined. If it is a list or dict, every call shares that very object:

def add_tag(tag, tags=[]):
    tags.append(tag)
    return tags

print(add_tag("a"), add_tag("b"))
# ['a', 'b'] ['a', 'b']   <- the same list is reused!

def add_tag_ok(tag, tags=None):
    if tags is None:
        tags = []
    tags.append(tag)
    return tags

print(add_tag_ok("a"), add_tag_ok("b"))
# ['a'] ['b']

The rule: use None as the default and build the new object inside the function.

Returning several values and checking early

def stats(nums):
    return min(nums), max(nums), sum(nums) / len(nums)

lo, hi, avg = stats([24, 8, 16])
print(lo, hi, avg)      # 8 24 16.0

The function really returns a tuple, which you then unpack (part 4). For functions with many conditions, return early as in part 3 instead of nesting if levels. A function that returns nothing and only has side effects (writing a file, calling an API) is fine returning None. But if you forget return in a function that should produce a value, the result is also None:

def no_return(x):
    y = x * 2        # forgot return

print(no_return(2))  # None

Does a function change your arguments?

Python passes arguments by giving the name to the very object you handed in, without copying. For immutable types (numbers, strings, tuples) that is harmless. But with lists and dicts a function can alter the caller's object without them noticing:

def add_default_hours(vals):
    vals["duration_hours"] = vals.get("duration_hours", 8)   # edits the caller's dict directly
    return vals

v = {"name": "X"}
add_default_hours(v)
print(v)      # {'name': 'X', 'duration_hours': 8}  <- v has been changed!

def add_default_hours_safe(vals):
    vals = dict(vals)                 # work on a copy
    vals.setdefault("duration_hours", 8)
    return vals

w = {"name": "Y"}
print(add_default_hours_safe(w), w)
# {'name': 'Y', 'duration_hours': 8} {'name': 'Y'}

This pattern is very realistic: when you override create(self, vals_list) from the Odoo series you receive a dict (or list of dicts) vals from the caller. If you edit it in place, the caller sees their data change. The rule: either state in the docstring that the function modifies its argument, or work on a copy (dict(vals), list(items)).

Keyword-only parameters

A lone * in the parameter list forces every parameter after it to be passed by name. That keeps calls readable and prevents order mix-ups, especially with boolean parameters:

def search(name, *, published=True, limit=10):
    return name, published, limit

print(search("odoo", limit=5))     # ('odoo', True, 5)
search("odoo", False)
# TypeError: search() takes 1 positional argument but 2 were given

Compare search("odoo", False) with search("odoo", published=False): the second explains itself, while with the first nobody knows what False means.

Writing good functions: a few conventions

  • Each function does one thing and its name is a verb stating that thing (make_code, calc_price_per_hour). A function that grows long usually wants splitting.
  • Prefer pure functions: the same input gives the same result and no outside data changes. Pure functions are easy to test and reuse (part 14).
  • A one-line docstring stating what the function does, especially for shared helpers.
  • Few parameters: beyond three or four, consider bundling them into a dict or an object.

Odoo also has method-naming conventions so readers can guess a method's role, and its documentation uses them consistently:

Method nameRoleExample in the docs

A name starting with _ is a private method, not callable from buttons or external APIs; a public name such as action_done can be called over RPC with arbitrary arguments, so it must verify conditions itself (part 5 of the Odoo series).

Variable scope: inside and outside a function

A variable assigned inside a function is local and exists only there. Reading an outer variable works, but reassigning it requires a global declaration:

counter = 0

def inc():
    global counter     # declare use of the global (use sparingly)
    counter += 1

inc()
print(counter)         # 1

def bad():
    total += 1         # total has not been assigned in this function

bad()
# UnboundLocalError: cannot access local variable 'total' where it is not associated with a value

Use global sparingly. Odoo's documentation has its own warning: do not use mutable global variables, because one Odoo process can serve several databases at once, each with different modules installed, so global state would be shared by accident.

Lambda: a one-line nameless function

lambda parameters: expression builds a small function that returns the expression's value. It is often passed as an argument:

courses = [{"code": "ODO-F", "hours": 24}, {"code": "GIT-T", "hours": 8}]

print(sorted(courses, key=lambda c: c["hours"])[0]["code"])      # GIT-T
print([c["code"] for c in filter(lambda c: c["hours"] > 10, courses)])   # ['ODO-F']

A function defined inside another function (a closure) also remembers the outer function's variables, which underlies the decorators of part 9:

def outer():
    prefix = "ODO"
    def make(seq):                 # a function inside a function that remembers prefix
        return f"{prefix}-{seq:03d}"
    return make

mk = outer()
print(mk(5))                       # ODO-005

Meeting them again in Odoo code

# 1. the default is a function: called each time a record is created
instructor_id = fields.Many2one('res.users', default=lambda self: self.env.user)

# 2. filter a recordset with a lambda
published = courses.filtered(lambda c: c.is_published)

# 3. a controller route accepting arbitrary parameters
@http.route('/vinc_course/courses', auth='public')
def courses(self, **kw):
    ...

The ORM documentation describes a field's default as either a fixed value or a function that takes a recordset and returns a value; and filtered accepts a function, for example records.filtered(lambda r: r.company_id == user.company_id), or a field-path string such as "partner_id.vat".

Practice: a course summary function

def summarize(courses, min_hours=0, **extra):
    """Summarize courses lasting at least min_hours hours."""
    selected = [c for c in courses if c["hours"] >= min_hours]
    total = sum(c["hours"] for c in selected)
    return {"count": len(selected), "total_hours": total, **extra}

courses = [{"code": "ODO-F", "hours": 24}, {"code": "PY-F", "hours": 16}, {"code": "GIT-T", "hours": 8}]
print(summarize(courses))
print(summarize(courses, min_hours=10, source="catalog"))
# {'count': 3, 'total_hours': 48}
# {'count': 2, 'total_hours': 40, 'source': 'catalog'}

Try adding an only_published=False parameter to filter by status. This is exactly how you write a shared helper inside a module and call it from several methods.

Common mistakes when starting out

  • Using a list/dict as a default value. Results "stick" between calls. Use None and create a fresh object inside.
  • Forgetting return. The function gives back None and a later line fails with a confusing error such as 'NoneType' object .... Check that every branch returns.
  • Calling with the wrong number of arguments. price_per_hour() raises TypeError: price_per_hour() missing 1 required positional argument: 'price'; too many gives takes from 1 to 2 positional arguments but 3 were given.
  • Reassigning an outer variable without global. Raises UnboundLocalError. A better route is to pass values in and return results out instead of using globals.

Summary

  • def + return; a function without return gives back None.
  • Default parameters come after required ones; never use a list/dict as a default.
  • *args and **kwargs collect arguments; */** at call time unpack them.
  • Function variables are local; avoid changeable globals. lambda suits short functions.

FAQ

How do *args and **kwargs differ? ▾
*args collects all positionally passed arguments into a tuple, while **kwargs collects all named arguments into a dict. Both let a function accept any number of arguments.
Why should a list not be a default parameter value? ▾
A default value is created only once when the function is defined, so every call shares the same list and results stick between calls. Use None and create a new list inside the function.
When should I use lambda? ▾
When you need a short, single-use function passed as an argument, such as the key of sorted, the function of filtered, or an Odoo field default like default=lambda self: self.env.user.
Why avoid changeable global variables in Odoo? ▾
One Odoo process can serve several databases at once, each with different modules installed, so state kept in a global would be shared by accident.
