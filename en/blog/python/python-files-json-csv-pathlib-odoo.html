Reading and Writing Files, JSON, CSV and pathlib in Python

Moving data in and out is regular work for Odoo developers: CSV files, JSON API responses, configuration files. This guide teaches pathlib, open, json, csv and configparser with a course import/export example, plus the encoding errors you will meet.

Updated: October 16, 2026 16 min read – views Vinc Academy Team

Quick summary

Use pathlib.Path for paths, with open(..., encoding="utf-8") to read and write files, json for nested data and csv for tables. Always specify encoding="utf-8" (and newline="" with csv). Every value read from CSV is a string, so convert it. In Odoo work you meet these formats constantly: CSV for data and access rights (ir.model.access.csv), JSON for APIs, and the odoo.conf configuration file.

Paths with pathlib

Instead of joining path strings by hand, use pathlib.Path: it handles the right separator on every operating system and bundles the operations you reach for:

from pathlib import Path

base = Path("data")
base.mkdir(parents=True, exist_ok=True)       # create the folder, no error if it exists
p = base / "courses.json"                      # the / operator joins paths
print(p, p.suffix, p.stem, p.parent, p.exists())
# data/courses.json .json courses data False

(base / "a.txt").write_text("ODO-F\nPY-F\n", encoding="utf-8")
print((base / "a.txt").read_text(encoding="utf-8").splitlines())   # ['ODO-F', 'PY-F']
print(sorted(x.name for x in base.glob("*.txt")))                  # ['a.txt']
OperationExample
Join pathsbase / "courses.json"
Name part, extension, parent folderp.stem, p.suffix, p.parent

A relative path such as "data/courses.json" is resolved against the current directory at run time, not the folder holding the script. For stable paths, compute them from Path(__file__).resolve().parent.

Reading and writing text files

with open(base / "a.txt", encoding="utf-8") as f:     # the default mode "r" (read)
    for line in f:                                     # loop line by line, saving memory
        print(line.strip(), end=" ")                   # ODO-F PY-F
print()

with open(base / "a.txt", "a", encoding="utf-8") as f:  # "a": append at the end
    f.write("GIT-T\n")
print((base / "a.txt").read_text(encoding="utf-8").splitlines())   # ['ODO-F', 'PY-F', 'GIT-T']
  • Mode "r" reads (the default), "w" writes and erases old content, "a" appends at the end.
  • Always add encoding="utf-8", especially with Vietnamese text, so results match on every machine.
  • Looping with for line in f reads line by line, saving memory with big files, whereas read() loads the whole file at once.
  • Always use with (part 10) so the file closes by itself.

p.write_text("a", encoding="utf-8")

open(p, "x", encoding="utf-8")
# FileExistsError: [Errno 17] File exists: 'x.txt'      <- "x": create only, never overwrite

with open(p, "r+", encoding="utf-8") as f:     # "r+": read and write the same file
    print(f.read())        # a
    f.seek(0)              # jump back to the start of the file
    f.write("Z")
print(p.read_text())       # Z

Binary files and base64

Images, PDFs and archives are binary data: reading gives bytes, not a string. When they must travel through JSON or live in an Odoo field they are encoded as text with base64. Odoo's data-files reference likewise has a base64 type for loading file content (such as images) into attachments, and Odoo's binary fields come back as base64 strings through read():

import base64

img = Path("a.bin")
img.write_bytes(bytes([0, 1, 2, 255]))         # binary write: bytes, not str
raw = img.read_bytes()
print(raw, len(raw))                           # b'\x00\x01\x02\xff' 4

b64 = base64.b64encode(raw).decode("ascii")    # bytes -> base64 text to send through JSON
print(b64, base64.b64decode(b64) == raw)       # AAEC/w== True

Temporary files and folders

When writing tests (part 14) or intermediate processing you do not want to leave junk files behind. The tempfile module creates temporary folders or files and cleans them up when the with block ends:

import tempfile

with tempfile.TemporaryDirectory() as tmp:     # a temp folder, deleted when the with block ends
    t = Path(tmp) / "t.txt"
    t.write_text("temp", encoding="utf-8")
    print(t.exists())                          # True
print(t.exists())                              # False

Reading API JSON safely

JSON arriving from outside does not guarantee every key. Use .get() with a default at each level that may be absent, then convert into a typed object (such as the @dataclass of part 8) so the rest of your code deals with clean data. This is a sensible border for validating and converting types:

import json
from dataclasses import dataclass

payload = json.loads('{"data": [{"code": "ODO-F", "hours": 24, "extra": {"x": 1}}, {"code": "PY-F"}]}')

for item in payload.get("data", []):
    print(item["code"], item.get("hours", 0), item.get("extra", {}).get("x"))
# ODO-F 24 1
# PY-F 0 None

@dataclass
class CourseRow:
    code: str
    hours: int = 0

    @classmethod
    def from_dict(cls, d):
        return cls(code=d["code"].strip().upper(), hours=int(d.get("hours", 0)))

print([CourseRow.from_dict(i) for i in payload["data"]])
# [CourseRow(code='ODO-F', hours=24), CourseRow(code='PY-F', hours=0)]

Compare pathlib with the older os.path: os.path.join("data", "a.txt") returns a string, while Path("data") / "a.txt" returns an object that comes with .exists(), .read_text() and more. New code should prefer pathlib, but you will still read os.path in older code since many functions accept both types.

JSON: nested data

JSON is a text format describing objects, lists, strings, numbers, booleans and null. It maps directly onto Python's dict, list, str, int/float, bool and None (part 4), which is why it is the format of most APIs.

import json

courses = [
    {"code": "ODO-F", "name": "Odoo basics", "hours": 24, "published": True, "price": None},
    {"code": "PY-F", "name": "Python basics", "hours": 16, "published": False, "price": 1500000.5},
]
text = json.dumps(courses, ensure_ascii=False, indent=2)    # object -> JSON string
(base / "courses.json").write_text(text, encoding="utf-8")

back = json.loads((base / "courses.json").read_text(encoding="utf-8"))   # string -> object
print(back == courses, back[0]["published"], back[0]["price"])   # True True None

print(json.dumps({"a": True, "b": None}))             # {"a": true, "b": null}
print(json.dumps("tiếng Việt"))                       # "ti\u1ebfng Vi\u1ec7t"
print(json.dumps("tiếng Việt", ensure_ascii=False))   # "tiếng Việt"

with open(base / "out.json", "w", encoding="utf-8") as f:
    json.dump(courses, f, ensure_ascii=False)         # dump/load work directly with files
  • dumps/loads work with strings; dump/load work directly with files.
  • ensure_ascii=False keeps non-ASCII text instead of turning it into \uXXXX; indent=2 pretty-prints.
  • True/None become true/null in JSON and come back correctly when read.
  • Standard JSON uses double quotes; single quotes are an error.
import datetime
json.dumps({"when": datetime.date(2026, 10, 16)})
# TypeError: Object of type date is not JSON serializable

print(json.dumps({"when": datetime.date(2026, 10, 16)}, default=str))   # {"when": "2026-10-16"}

json.loads("{'a': 1}")
# json.decoder.JSONDecodeError: Expecting property name enclosed in double quotes: line 1 column 2 (char 1)

Dates do not convert to JSON by themselves; turn them into strings with default=str or a format of your own (part 12). You have seen this approach in Odoo's external API documentation, where an illustrative snippet returns json.dumps(records.ids) and json.dumps(names).

CSV: tabular data

import csv

csv_path = base / "courses.csv"
with open(csv_path, "w", encoding="utf-8", newline="") as f:     # newline="" is required with csv
    w = csv.DictWriter(f, fieldnames=["code", "name", "hours"])
    w.writeheader()
    for c in courses:
        w.writerow({k: c[k] for k in ("code", "name", "hours")})
    w.writerow({"code": "X,Y", "name": 'Có "dấu nháy"', "hours": 8})   # commas and quotes are escaped automatically

print(csv_path.read_text(encoding="utf-8"))
# code,name,hours
# ODO-F,Odoo basics,24
# PY-F,Python basics,16
# "X,Y","Có ""dấu nháy""",8

with open(csv_path, encoding="utf-8", newline="") as f:
    rows = list(csv.DictReader(f))                # each row is a dict keyed by the column headers
print(rows[0])            # {'code': 'ODO-F', 'name': 'Odoo basics', 'hours': '24'}
print(type(rows[0]["hours"]))   # <class 'str'>   <- every value read is a string!
print(sum(int(r["hours"]) for r in rows))   # 48
with open(csv_path, encoding="utf-8", newline="") as f:
    r = csv.reader(f)                  # rows are lists, without column names
    header = next(r)                   # take the header row
    print(header, next(r))
# ['code', 'name', 'hours'] ['ODO-F', 'Odoo basics', '24']
  • csv.DictWriter/DictReader work by column name so they read better than the position-based csv.writer/reader.
  • Open CSV files with newline="" so the csv module handles line endings itself.
  • Values containing commas or quotes are wrapped automatically ("X,Y") on writing and split correctly on reading.
  • Every cell read is a string: "24" is not 24; call int() before computing.

odoo.conf-style configuration files

The odoo.conf file is in ini format: sections in square brackets ([options]) and key = value lines. The configparser module reads it:

import configparser

Path("odoo.conf").write_text(
    "[options]\nadmin_passwd = secret\ndb_host = 127.0.0.1\nworkers = 5\n", encoding="utf-8")

cp = configparser.ConfigParser()
cp.read("odoo.conf", encoding="utf-8")
print(cp["options"]["db_host"])                       # 127.0.0.1
print(cp.getint("options", "workers"))                # 5
print(cp.get("options", "dbfilter", fallback="(none)"))   # (none)

fallback supplies a default when a key is absent. You can use this very approach to write a script that checks a production configuration before deployment (part 14 of the Odoo series): read workers, dbfilter, list_db and warn when something is missing.

Practice: exporting and importing the course list

def export_courses(courses, path):
    with open(path, "w", encoding="utf-8", newline="") as f:
        w = csv.DictWriter(f, fieldnames=["code", "name", "hours"])
        w.writeheader()
        for c in courses:
            w.writerow({k: c[k] for k in ("code", "name", "hours")})

def import_courses(path):
    ok, errors = [], []
    with open(path, encoding="utf-8", newline="") as f:
        for n, row in enumerate(csv.DictReader(f), start=2):     # row 1 is the header
            try:
                ok.append({"code": row["code"].strip().upper(), "hours": int(row["hours"])})
            except (KeyError, ValueError) as e:
                errors.append(f"row {n}: {e}")
    return ok, errors

export_courses(courses, base / "export.csv")
(base / "export.csv").open("a", encoding="utf-8", newline="").write("BAD,Broken,abc\n")
print(import_courses(base / "export.csv"))
# ([{'code': 'ODO-F', 'hours': 24}, {'code': 'PY-F', 'hours': 16}], ["row 4: invalid literal for int() with base 10: 'abc'"])

The import_courses function reuses the good-rows/bad-rows pattern from part 10, adding the row number so users know where to fix. This is the core of the script that imports data into Odoo in part 14.

Common mistakes when starting out

open(base / "nope.txt").read()
# FileNotFoundError: [Errno 2] No such file or directory: 'data/nope.txt'

(base / "vn.txt").write_text("Tiếng Việt", encoding="utf-8")
open(base / "vn.txt", encoding="ascii").read()
# UnicodeDecodeError: 'ascii' codec can't decode byte 0xe1 in position 2: ordinal not in range(128)

# CSV for Excel: use utf-8-sig to add a BOM (Excel recognizes UTF-8)
with open(base / "bom.csv", "w", encoding="utf-8-sig", newline="") as f:
    f.write("code,name\nA,Tiếng Việt\n")
  • A relative path works on one machine but not another. FileNotFoundError is usually a different current directory. Compute paths from Path(__file__) or use absolute paths.
  • Forgetting encoding. Reading a UTF-8 file with the wrong codec raises UnicodeDecodeError or produces garbled text. Always state encoding="utf-8".
  • Forgetting newline="" with CSV. It may add extra blank lines (especially on Windows) or misread multi-line cells.
  • Calculating on unconverted CSV values. "24" + "16" gives "2416". Always int()/float() first.
  • Writing with "w" destroys old data. Use "a" to append.

Summary

  • pathlib.Path for paths; with open(..., encoding="utf-8") for files; "w" erases, "a" appends.
  • json: dumps/loads with strings, dump/load with files; ensure_ascii=False for Vietnamese.
  • csv.DictReader/DictWriter with newline=""; every cell read is a string.
  • configparser reads odoo.conf-style files.

FAQ

Why specify encoding="utf-8" when opening a file? ▾
Without it Python uses the system default encoding, so results can differ between machines. With Vietnamese data, always state utf-8 to avoid UnicodeDecodeError or garbled text.
Why does csv need newline=""? ▾
The csv module handles line breaks inside cells and between rows itself. Opening a file without an empty newline can add extra blank lines or misread multi-line cells, especially on Windows.
What is the difference between json.dumps and json.dump? ▾
dumps returns a JSON string, while dump writes straight into an open file. Likewise loads reads from a string and load reads from a file.
Why are numbers in a CSV file read as strings? ▾
CSV is just text, so csv.reader and DictReader return every cell as a string. You must convert with int() or float() before calculating.
