Calling APIs with Python requests: Odoo JSON-2 Guide

Integrating Odoo with other systems almost always starts with one HTTP call. This guide teaches the requests library, setting timeouts, handling errors, and calling Odoo 20's JSON-2 API with an API key, then wraps it into a reusable client.

Updated: October 16, 2026 15 min read Vinc Academy Team

Quick summary

The requests library sends HTTP requests in a single line: requests.post(url, json=body, headers=h, timeout=10). Always set timeout, call raise_for_status() to turn 4xx/5xx codes into exceptions and read data with .json(). With Odoo 20 you call models through the JSON-2 API: POST /json/2/<model>/<method> with an API key in the Authorization: bearer header, exactly as in part 12 of the Odoo series.

HTTP in five minutes

An HTTP request consists of a method (GET to read, POST to send data...), a URL, headers (extra information such as content type and authentication) and an optional body. The response has a status code, headers and a body. The status code tells the outcome:

CodeMeaningSeen with the Odoo API
200SuccessThe body is the method's return value, as JSON
401Not authenticated / wrong keyThe documentation's error example: "message": "Invalid apikey"
403ForbiddenRevoking with a wrong key gives 403 Forbidden
404Not foundA wrong path or model
422UnprocessableExceeding the limit of programmatically generated API keys
Other 4xx/5xxClient / server errorThe body is a JSON object with name, message, arguments, context, debug

requests: sending a request and reading the response

import requests

r = requests.get("https://example.com/api/courses",
                 params={"level": "beginner", "page": 1},     # becomes ?level=beginner&page=1
                 headers={"Accept": "application/json"},
                 timeout=10)                                  # ALWAYS set a timeout

print(r.status_code, r.ok)                  # 200 True
print(r.headers["Content-Type"])            # application/json; charset=utf-8
data = r.json()                             # parse the body into a list/dict
print(r.url)                                # the full URL including parameters
print(r.elapsed.total_seconds())            # response time (seconds)

The URL in the example is hypothetical (example.com has no such API); swap in a real API when you try it. A local mock server gave exactly the results in the comments.

Parameter / attributeEffect
params={...}URL (query string) parameters, with special characters encoded for you
json={...}Sends a JSON body and sets Content-Type itself
headers={...}Request headers
timeout=10Maximum seconds to wait for a response
r.status_code, r.okThe status code; ok is true for codes below 400
r.json(), r.textThe JSON-decoded body / the body as a string
r.raise_for_status()Raises HTTPError for 4xx/5xx codes

HTTP methods and how to send a body

FunctionMethodCommonly used to
requests.getGETRead data, with no side effects
requests.postPOSTSend data to create something or run an action (Odoo's JSON-2 API uses POST only)
requests.put, patchPUT, PATCHUpdate a whole / part of a resource (typical REST APIs)
requests.deleteDELETEDelete a resource

There are two ways to send a body: data= encodes form-style (application/x-www-form-urlencoded) while json= sends JSON and sets Content-Type: application/json. Odoo's API expects JSON, so use json=. A non-JSON response (an image, a PDF) is read through .content (type bytes) and written to a file as in part 11:

p1 = requests.Request("POST", "http://x/y", data={"a": "1", "b": "x y"}).prepare()
print(p1.headers["Content-Type"], p1.body)
# application/x-www-form-urlencoded a=1&b=x+y

p2 = requests.Request("POST", "http://x/y", json={"a": 1, "b": "Vietnamese text"}).prepare()
print(p2.headers["Content-Type"], p2.body)
# application/json b'{"a": 1, "b": "ti\\u1ebfng"}'

img = requests.get(image_url, timeout=10)
print(type(img.content).__name__)                # bytes: for binary files
Path("image.png").write_bytes(img.content)         # save straight to a file (part 11)

Pagination for large data sets

Do not fetch tens of thousands of records in one call. The ORM documentation describes search taking offset (records to skip), limit (maximum records) and order. The loop below uses the OdooClient from the next section to fetch page after page until the last page is shorter than page_size:

def fetch_all_ids(client, domain, page_size=100):
    ids, offset = [], 0
    while True:
        page = client.call("vinc.course", "search", domain=domain,
                           offset=offset, limit=page_size, order="id")   # parameters of search
        ids.extend(page)
        if len(page) < page_size:        # a short last page means the data has run out
            return ids
        offset += page_size

# with fake data holding 7 ids: fetch_all_ids(client, [], page_size=3) -> [1, 2, 3, 4, 5, 6, 7]

Check your database's /doc page for the exact parameters of each method on your own system.

Calling Odoo's JSON-2 API

According to the Odoo 20 documentation you POST to /json/2/<model>/<method>. The mandatory headers are Authorization: bearer <API key> and Content-Type: application/json (requests sets the latter when you use json=); X-Odoo-Database is optional, needed when one server hosts several databases. The JSON body holds ids (if the method works on records), an optional context and the method's own parameters:

import os
import requests

BASE_URL = os.environ["ODOO_URL"] + "/json/2"          # for example https://mycompany.example.com
headers = {
    "Authorization": "bearer " + os.environ["ODOO_API_KEY"],   # NEVER hard-code the key
    "X-Odoo-Database": os.environ.get("ODOO_DB", ""),
}

r = requests.post(
    f"{BASE_URL}/vinc.course/search_read",
    headers=headers,
    json={"domain": [["level", "=", "beginner"]], "fields": ["name", "level"]},
    timeout=10,
)
r.raise_for_status()
print(r.json())
# [{'id': 1, 'name': 'Odoo basics', 'level': 'beginner'}, ...]

A security note: the API key must live outside the code, typically in an environment variable (os.environ) or your system's secret store, because the key carries the rights of its owner. The documentation also advises a dedicated "bot user" with minimal rights for automated integrations, and keys last at most three months, so rotate them regularly.

bad = requests.post(f"{BASE_URL}/vinc.course/search_read", headers={"Authorization": "bearer WRONG"}, json={}, timeout=10)
print(bad.status_code, bad.json()["message"])    # 401 Invalid apikey
bad.raise_for_status()
# requests.exceptions.HTTPError: 401 Client Error: Unauthorized for url: .../json/2/vinc.course/search_read

Handling errors and timeouts

The requests documentation is explicit: without a timeout, a request never expires and your program may hang forever; nearly all production code should set it. All errors raised by requests extend requests.exceptions.RequestException:

import requests

try:
    r = requests.post(url, headers=headers, json=body, timeout=5)
    r.raise_for_status()
except requests.Timeout:
    print("Timed out")             # the server did not answer within 5 seconds
except requests.ConnectionError:
    print("Could not connect")            # DNS failure, connection refused...
except requests.HTTPError as e:
    print("Odoo returned an error:", e.response.status_code, e.response.text[:100])
except requests.RequestException as e:      # the parent of every requests error
    print("Other error:", e)
ExceptionWhen
ConnectionErrorA network problem: DNS failure, refused connection
TimeoutNo response arrived within the timeout period
HTTPErrorOnly when you call raise_for_status() and the code is 4xx/5xx
TooManyRedirectsMore redirects than allowed

Note that timeout does not cap the total time to download a response; it is how long the client waits without receiving any byte from the server.

Wrapping it in a reusable client

When you call an API many times, use requests.Session: it keeps headers (like Authorization) across calls and reuses the connection to the same host, noticeably faster. Combined with classes (part 8) and custom exceptions (part 10) we get a compact client:

class OdooAPIError(Exception):
    """An error returned by Odoo or a connection error."""

class OdooClient:
    def __init__(self, base_url, api_key, database=None, timeout=10):
        self.base_url = base_url.rstrip("/")
        self.timeout = timeout
        self.session = requests.Session()                      # reuses the connection and headers
        self.session.headers["Authorization"] = f"bearer {api_key}"
        if database:
            self.session.headers["X-Odoo-Database"] = database

    def call(self, model, method, **payload):
        url = f"{self.base_url}/json/2/{model}/{method}"
        try:
            response = self.session.post(url, json=payload, timeout=self.timeout)
        except requests.RequestException as e:
            raise OdooAPIError(f"Could not call {url}: {e}") from e
        if not response.ok:
            try:
                message = response.json().get("message", response.text)
            except ValueError:
                message = response.text
            raise OdooAPIError(f"HTTP {response.status_code}: {message}")
        return response.json()
client = OdooClient(os.environ["ODOO_URL"], os.environ["ODOO_API_KEY"], os.environ.get("ODOO_DB"))

print(client.call("vinc.course", "search_read", domain=[["level", "=", "beginner"]], fields=["name", "level"]))
# [{'id': 1, 'name': 'Odoo', 'level': 'beginner'}]
print(client.call("vinc.course", "create", vals_list=[{"name": "Odoo basics", "duration_hours": 24}]))
# [7]

OdooClient(os.environ["ODOO_URL"], "WRONG").call("vinc.course", "search_read")
# OdooAPIError: HTTP 401: Invalid apikey

All the ugly HTTP details (headers, URL, timeout, error codes) sit inside OdooClient; the rest of the program just calls client.call(...) and catches OdooAPIError. This separation also makes tests easier (part 14): swap the real client for a fake object.

Retrying when the network flickers

import time

def with_retry(func, attempts=3, delay=0.5):
    for i in range(1, attempts + 1):
        try:
            return func()
        except OdooAPIError:
            print(f"attempt {i} failed")
            if i == attempts:
                raise                       # out of attempts: re-raise the last error
            time.sleep(delay * i)           # wait longer between attempts

with_retry(lambda: client.call("vinc.course", "search_read", fields=["name"]))

Retry only operations that are safe to repeat, such as reading data. For a write (create), retrying may create a duplicate record if the first attempt actually succeeded. The API documentation also stresses that every JSON-2 call is its own transaction, so steps that belong together must be wrapped in one server-side method.

Practice: checking the connection to Odoo

  1. Create an API key in your Odoo user preferences and set ODOO_URL, ODOO_API_KEY, ODOO_DB as environment variables.
  2. Use OdooClient to call search_read on the res.partner model with fields=["name"] and a small limit.
  3. Deliberately use a wrong key and confirm you get OdooAPIError: HTTP 401: Invalid apikey.
  4. Set timeout=0.001 and watch the timeout error.

Common mistakes when starting out

  • Forgetting timeout. The program can hang forever when the server does not answer.
  • Forgetting raise_for_status(). A 401/404 does not raise by itself, so a later r.json() returns the error body that you take for data. Always check r.ok or call raise_for_status().
  • A badly formed header. It must be Authorization: bearer <key>; a missing bearer word or an expired key both give 401.
  • Putting the API key in code or Git. The key carries its owner's rights; use environment variables and revoke it at once if leaked.
  • A URL without https://. Raises MissingSchema: Invalid URL ... No scheme supplied.

Summary

  • requests.get/post(..., timeout=...); read .status_code and .json(); raise_for_status() turns error codes into exceptions.
  • Odoo's JSON-2 API: POST /json/2/<model>/<method>, an Authorization: bearer header, a JSON body; keep the key in an environment variable.
  • requests.Session keeps headers and connections; wrap it in a client with its own exception.
  • Retry only operations safe to repeat; every JSON-2 call is its own transaction.

FAQ

Why must I always set a timeout in requests? ▾
According to the requests documentation, without a timeout a request never expires and your program may hang forever when the server does not answer. Nearly all production code should set it.
What does raise_for_status do? ▾
It raises HTTPError when the response has a 4xx or 5xx status code. If you skip it, an error code such as 401 raises nothing by itself and r.json() returns the error body, which you may mistake for data.
Which headers does a call to Odoo's JSON-2 API need? ▾
Authorization with the value bearer plus the API key, and Content-Type application/json are mandatory. X-Odoo-Database is optional, needed when one server hosts several databases. requests sets Content-Type itself when you use the json parameter.
What is requests.Session good for? ▾
A Session keeps headers such as Authorization across calls and reuses the connection to the same host, making it faster and suited to many calls.
