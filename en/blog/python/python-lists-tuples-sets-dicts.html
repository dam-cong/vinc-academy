Python Lists, Tuples, Sets and Dicts with Odoo Examples

These four data structures appear in nearly every line of Odoo code: the vals of create is a dict, a domain is a list of tuples, and the manifest is a dict too. This guide helps you pick the right structure and avoid the classic traps.

Updated: October 16, 2026 11 min read Vinc Academy Team

Quick summary

Python's four built-in data structures cover nearly every need: list (ordered, changeable), tuple (a fixed bundle of values), set (unique items) and dict (key-value pairs). In Odoo you meet all four: a dict is the vals of create() and the whole manifest, a list of triples is a domain, tuples are Commands and Selection pairs, and sets inspire the operations on recordsets.

List: ordered and changeable

A list is written in square brackets, its items are numbered from 0 and may be of any type. It is what you use most to hold "many things of the same kind":

codes = ["ODO-F", "PY-F", "GIT-T"]
codes.append("AI-O")           # append at the end
codes.insert(1, "SQL-B")       # insert at position 1
print(codes)
# ['ODO-F', 'SQL-B', 'PY-F', 'GIT-T', 'AI-O']

codes.remove("SQL-B")          # remove by value
last = codes.pop()             # take and remove the last one
print(codes, last)
# ['ODO-F', 'PY-F', 'GIT-T'] AI-O

print(codes[0], codes[-1], codes[1:], len(codes), "PY-F" in codes)
# ODO-F GIT-T ['PY-F', 'GIT-T'] 3 True
  • append, insert and extend add items; remove deletes by value; pop takes and deletes by position (the last item by default).
  • Negative indexes count from the end (codes[-1] is the last item); slicing codes[1:] yields a new list.
  • sorted() returns a new sorted list; the key parameter lets you sort by a field:
print(sorted([24, 8, 16]), sorted([24, 8, 16], reverse=True))
# [8, 16, 24] [24, 16, 8]

courses = [{"code": "ODO-F", "hours": 24}, {"code": "PY-F", "hours": 16}, {"code": "GIT-T", "hours": 8}]
shortest = sorted(courses, key=lambda c: c["hours"])[0]
print(shortest["code"])
# GIT-T

In Odoo, when you call create() for several records you pass a list of dicts called vals_list: env['vinc.course'].create([{...}, {...}]). The ORM documentation describes this argument as a list of dictionaries and says the call returns the created records.

A list also works as a stack (last in, first out) using just append() and pop(). For a queue (first in, first out) the Python documentation recommends collections.deque, since popleft() is much faster than removing the first item of a list:

from collections import deque
q = deque(["a", "b"])
q.append("c")
print(q.popleft(), list(q))    # a ['b', 'c']

You can also split the first item from the rest with first, *rest = [1, 2, 3], giving first = 1 and rest = [2, 3]. It is handy for the first (header) line of a CSV file in part 11.

A classic trap: assigning a list does not copy it

a = [1, 2]
b = a              # b and a are the SAME list
b.append(3)
print(a)           # [1, 2, 3]

c = a.copy()       # an independent copy
c.append(4)
print(a, c)        # [1, 2, 3] [1, 2, 3, 4]

The assignment b = a merely gives the list a second name. For an independent copy use a.copy() or a[:].

Tuple: a fixed bundle of values

A tuple is written in parentheses and cannot be changed after creation. It fits things with a fixed shape: a condition, a coordinate, or a multi-part return value.

cond = ("level", "=", "beginner")
field, op, value = cond            # unpack into 3 variables
print(field, op, value, cond[0])   # level = beginner level

domain = [("is_published", "=", True), ("hours", ">", 10)]   # a list of triples

def min_max(nums):
    return min(nums), max(nums)    # returns a tuple

lo, hi = min_max([24, 8, 16])
print(lo, hi)                      # 8 24

print(type((1,)), type((1)))
# <class 'tuple'> <class 'int'>

Two details to remember: a one-item tuple needs a trailing comma ((1,)), otherwise (1) is just the number 1 in parentheses; and assigning to an element raises TypeError: 'tuple' object does not support item assignment.

You have met tuples everywhere in the Odoo series: each domain condition is a triple (field name, operator, value); each Selection choice is a (value, label) pair; and each Command is really a triple whose first item is a numeric code, for instance Command.link(12) corresponds to (4, 12, 0).

Set: a collection without duplicates

A set is written in braces (or set(...)); each value appears once and there is no fixed order. Use it to drop duplicates or to test membership quickly:

ids = {1, 2, 2, 3}
print(ids, len(ids), 2 in ids)             # {1, 2, 3} 3 True

x, y = {1, 2, 3}, {3, 4}
print(x | y, x & y, x - y, sorted(x ^ y))
# {1, 2, 3, 4} {3} {1, 2} [1, 2, 4]

print(sorted(set([3, 1, 3, 2])))           # [1, 2, 3]  (loại trùng)

Set operations: | union, & intersection, - difference, ^ symmetric difference. Odoo deliberately borrows this notation for recordsets: the ORM documentation says recordsets support set operations like recs1 | recs2 for merging two groups of records.

Dict: key-value pairs

A dict is written in braces with key: value pairs, and lookup by key is very fast. It is the structure you use most with real data: JSON, the vals of create()/write(), settings, the manifest:

vals = {"name": "Odoo basics", "duration_hours": 24}
print(vals["name"], vals.get("price"), vals.get("price", 0.0))
# Odoo basics None 0.0

vals["price"] = 2000                       # add or change a key
vals.update({"is_published": True})        # add several keys at once
for k, v in vals.items():
    print(k, "=", v)
# name = Odoo basics
# duration_hours = 24
# price = 2000
# is_published = True

print(vals.pop("price"), "price" in vals)  # 2000 False

d = {}
d.setdefault("tags", []).append("odoo")    # create an empty list if missing
print(d)                                   # {'tags': ['odoo']}
  • d[key] raises KeyError when the key is absent, whereas d.get(key, default) returns a default instead of failing.
  • Keys must be hashable (numbers, strings, tuples) while lists are not: {[1]: 2} raises TypeError: unhashable type: 'list'.
  • Since Python 3.7 a dict keeps insertion order, so .items() loops give stable results.

Nested structures: JSON-like data

Structures nest inside each other, which is the shape of most API payloads and of the data Odoo returns. For example a course holding a list of sessions, each session being a dict:

data = {"course": {"code": "ODO-F", "sessions": [
    {"name": "Session 1", "hours": 3},
    {"name": "Session 2", "hours": 3},
]}}
print(data["course"]["sessions"][1]["name"])                 # Session 2
print(sum(s["hours"] for s in data["course"]["sessions"]))   # 6
del data["course"]["code"]                                   # remove one key

Read it from the outside in: data["course"] is a dict, ["sessions"] a list, [1] picks the second item, and ["name"] takes its name. With such deep access, consider .get() at each level that might be missing, or test if "sessions" in data["course"]: before iterating. This is also the shape you will receive when calling Odoo's JSON-2 API in part 13: a search_read result is a list of dicts.

Meeting them again in an Odoo module

manifest = {"name": "Vinc Course", "depends": ["base"], "application": True}
print(manifest["depends"][0])              # base

selection = [("beginner", "Basic"), ("advanced", "Advanced")]
print(dict(selection)["beginner"])         # Basic

import json
print(json.dumps({"name": "Odoo basics", "is_published": True}, ensure_ascii=False))
# {"name": "Odoo basics", "is_published": true}

The manifest is a plain Python dict: the 'depends' key holds a list and 'application' a boolean. That explains why __manifest__.py is just one dict that Odoo reads as a data structure.

Practice: group courses by length

Given a list of courses, build a dict collecting course codes by length ("long" from 24 hours, otherwise "short"):

courses = [
    {"code": "ODO-F", "hours": 24},
    {"code": "PY-F", "hours": 16},
    {"code": "GIT-T", "hours": 8},
]
groups = {}
for course in courses:
    key = "long" if course["hours"] >= 24 else "short"
    groups.setdefault(key, []).append(course["code"])
print(groups)
# {'long': ['ODO-F'], 'short': ['PY-F', 'GIT-T']}

This "dict of lists" pattern recurs whenever you group report data. Part 6 will shorten it with comprehensions.

Common mistakes when starting out

  • Reading a missing key. vals["price"] raises KeyError: 'price'. Use vals.get("price", 0.0) when the key may be absent.
  • Confusing assignment with copying. b = a makes both names point at one list, so changing b changes a. Use a.copy() for a copy.
  • Forgetting the comma of a one-item tuple. (1) is an integer; (1,) is the tuple.
  • Using a list as a dict key or set member. It raises TypeError: unhashable type: 'list'; switch to a tuple.

Summary

  • list for many same-kind items, changeable; tuple for fixed bundles; set drops duplicates; dict looks up by key.
  • Assignment does not copy; use .copy().
  • dict.get() avoids KeyError; dict keys must be hashable.
  • Odoo uses exactly these structures: vals, domains, Command, the manifest.

FAQ

What is the difference between a list and a tuple? ▾
A list can change after creation while a tuple cannot. A tuple suits fixed-shape bundles such as a domain condition (field, operator, value) or a Command.
How do I avoid KeyError when reading a dict? ▾
Use d.get(key, default) instead of d[key]. The get method returns a default value instead of raising an error when the key does not exist.
Why does changing b also change a after b = a? ▾
Assignment does not copy; it only adds another name for the same list. For an independent copy use a.copy() or a[:].
When should I use a set? ▾
When you need to drop duplicate items or test membership quickly and order does not matter. Sets also support union, intersection and difference through the |, & and - operators.
