Python Comprehensions, Generators, sorted, filter and Odoo mapped

Processing lists tidily is an everyday skill in Odoo code. This guide walks through comprehensions, generators, sorted, filter, map, any and all, and shows how they correspond to a recordset's mapped, filtered, sorted and grouped.

Updated: October 16, 2026 14 min read – views Vinc Academy Team

Quick summary

A comprehension turns a for loop into one expression: [c["code"] for c in courses if c["published"]]. There are four forms (list, dict, set, generator), differing only in the brackets. A generator produces values on demand, saving memory but usable only once. Together with sorted, filter, map, sum, any and all, this is the list-processing toolkit that Odoo's recordset mapped, filtered and sorted imitate.

List comprehension: a for loop in one line

The syntax is [expression for item in collection if condition], where the if part is optional. Reusing the course list from earlier parts:

courses = [
    {"code": "ODO-F", "name": "Odoo basics", "hours": 24, "published": True},
    {"code": "PY-F", "name": "Python basics", "hours": 16, "published": True},
    {"code": "GIT-T", "name": "Git for teams", "hours": 8, "published": False},
]

codes = [c["code"] for c in courses]
print(codes)          # ['ODO-F', 'PY-F', 'GIT-T']

long_codes = [c["code"] for c in courses if c["hours"] >= 16]
print(long_codes)     # ['ODO-F', 'PY-F']

labels = [f'{c["code"]} ({c["hours"]}h)' for c in courses]
print(labels)         # ['ODO-F (24h)', 'PY-F (16h)', 'GIT-T (8h)']

Read it left to right like a sentence: "take c["code"] for each c in courses if c["hours"] >= 16". It equals the loop you wrote in part 3, shorter and yielding the result list directly:

result = []
for c in courses:
    if c["published"]:
        result.append(c["code"])
print(result)         # ['ODO-F', 'PY-F']

# same result, one line
print([c["code"] for c in courses if c["published"]])

When to use it? When you are building a new list from an old one by transforming or filtering. If the loop has several steps or side effects (writing files, calling an API), keep the plain for loop for readability.

Dict and set comprehensions

Just change the brackets: braces with a key: value pair give a dict, braces with a single value give a set (for example to drop duplicates):

by_code = {c["code"]: c["hours"] for c in courses}
print(by_code)        # {'ODO-F': 24, 'PY-F': 16, 'GIT-T': 8}

hour_set = {c["hours"] // 8 for c in courses}
print(sorted(hour_set))   # [1, 2, 3]

A dict comprehension is great for building a lookup table from a list: here by_code["PY-F"] yields the hours instantly instead of scanning the list each time.

Nested loops

pairs = [(c["code"], t) for c in courses for t in ("A", "B") if c["published"]]
print(pairs)
# [('ODO-F', 'A'), ('ODO-F', 'B'), ('PY-F', 'A'), ('PY-F', 'B')]

The for clauses are listed in the same nesting order as when you write ordinary loops. But if a comprehension needs two for levels plus a complex condition, split it into a plain loop: readable code matters more than short code.

sorted, filter, map and the aggregate functions

FunctionWhat it doesReturns
sorted(items, key=..., reverse=...)Sorts by a keya new list
filter(func, items)Keeps items for which func is truean iterator (wrap in list())
map(func, items)Applies func to each iteman iterator
sum, min, maxTotal, smallest, largestone value
any, allAt least one / every item is trueTrue/False
 
print(sorted(courses, key=lambda c: c["hours"], reverse=True)[0]["code"])   # ODO-F
print(list(filter(lambda c: c["published"], courses))[0]["code"])           # ODO-F
print(list(map(lambda c: c["hours"] * 60, courses)))                        # [1440, 960, 480]

print(sum(c["hours"] for c in courses), max(c["hours"] for c in courses), min(c["hours"] for c in courses))
# 48 24 8
print(any(c["hours"] > 20 for c in courses), all(c["published"] for c in courses))
# True False

filter and map return an iterator object rather than a list, so printing one directly shows <filter object ...>. In practice many people prefer comprehensions over filter/map for readability and keep only sorted, sum, any and all.

Conditional transforms, enumerate and zip

There are two places to put a condition in a comprehension and they differ. An if placed after the for drops items; x if cond else y placed before the for transforms every item depending on the condition. You may also use enumerate and zip inside to get an index or walk two lists side by side:

courses = [
    {"code": "ODO-F", "hours": 24, "published": True},
    {"code": "PY-F", "hours": 16, "published": True},
    {"code": "GIT-T", "hours": 8, "published": False},
    {"code": "SQL-B", "hours": 16, "published": True},
]

# if-else goes BEFORE for: transform by condition
print([c["code"] if c["published"] else c["code"].lower() for c in courses])
# ['ODO-F', 'PY-F', 'git-t', 'SQL-B']

# enumerate and zip inside a comprehension
print([f"{i}. {c['code']}" for i, c in enumerate(courses, start=1)])
# ['1. ODO-F', '2. PY-F', '3. GIT-T', '4. SQL-B']
print({n: h for n, h in zip(["a", "b"], [1, 2])})   # {'a': 1, 'b': 2}

Advanced sorting

The key parameter takes a function returning a "comparison key" for each item. To sort by several criteria, return a tuple; a minus sign reverses a number. The operator module offers itemgetter to do this more tersely than a lambda. Python's sort is stable: items with equal keys keep their original order, so you can sort repeatedly by one criterion at a time.

courses = [
    {"code": "ODO-F", "hours": 24, "published": True},
    {"code": "PY-F", "hours": 16, "published": True},
    {"code": "GIT-T", "hours": 8, "published": False},
    {"code": "SQL-B", "hours": 16, "published": True},
]

from operator import itemgetter

# several keys: hours descending, then code ascending
print([c["code"] for c in sorted(courses, key=lambda c: (-c["hours"], c["code"]))])
# ['ODO-F', 'PY-F', 'SQL-B', 'GIT-T']

print([c["code"] for c in sorted(courses, key=itemgetter("hours", "code"))])
# ['GIT-T', 'PY-F', 'SQL-B', 'ODO-F']

# stable sort: the two 16-hour courses keep their original order
print([c["code"] for c in sorted(courses, key=lambda c: c["hours"])])
# ['GIT-T', 'PY-F', 'SQL-B', 'ODO-F']

print(max(courses, key=lambda c: c["hours"])["code"])   # ODO-F

Grouping and counting

In part 4 you grouped with setdefault. The standard library has more specialized tools: defaultdict(list) creates an empty list for each new key, Counter tallies occurrences, and itertools.groupby groups adjacent items. Beware of the last one: groupby only groups items that sit next to each other, so the data must first be sorted by the same key.

courses = [
    {"code": "ODO-F", "hours": 24, "published": True},
    {"code": "PY-F", "hours": 16, "published": True},
    {"code": "GIT-T", "hours": 8, "published": False},
    {"code": "SQL-B", "hours": 16, "published": True},
]

from collections import defaultdict, Counter
from itertools import groupby
from operator import itemgetter

groups = defaultdict(list)
for c in courses:
    groups[c["hours"]].append(c["code"])
print(dict(groups))   # {24: ['ODO-F'], 16: ['PY-F', 'SQL-B'], 8: ['GIT-T']}

print(Counter(c["hours"] for c in courses))   # Counter({16: 2, 24: 1, 8: 1})

# groupby only groups ADJACENT items: sort first
srt = sorted(courses, key=itemgetter("hours"))
print({h: [c["code"] for c in g] for h, g in groupby(srt, key=itemgetter("hours"))})
# {8: ['GIT-T'], 16: ['PY-F', 'SQL-B'], 24: ['ODO-F']}
print({h: [c["code"] for c in g] for h, g in groupby(courses, key=itemgetter("hours"))})
# {24: ['ODO-F'], 16: ['SQL-B'], 8: ['GIT-T']}   <- wrong: 'PY-F' is lost!

In Odoo, records.grouped(key) does this grouping and returns a dict from key to recordset, so you rarely need to write groupby yourself.

Generators: values produced on demand

Swap a list comprehension's square brackets for round ones and you get a generator expression: it does not build the whole list in memory but produces each value when asked. A function using yield instead of return also makes a generator: each time it is resumed it continues from where it stopped, remembering variable values and the last statement executed.

gen = (c["hours"] for c in courses)    # generator expression: round brackets
print(type(gen))                        # <class 'generator'>
print(next(gen), next(gen), list(gen))  # 24 16 [8]

def hours_gen(items):
    for c in items:
        yield c["hours"]                # yield: hands back one value, remembers its place

g = hours_gen(courses)
print(next(g), sum(g))                  # 24 24

The big win is memory. With a million records a list holds them all while a generator keeps one item at a time. Feeding a generator straight into sum, max or any, as in sum(c["hours"] for c in courses), is a good habit, and you have seen this style in the any(course.is_published for course in self) example of the Odoo series.

import sys
big_list = [i for i in range(100000)]
big_gen = (i for i in range(100000))
print(sys.getsizeof(big_list) > sys.getsizeof(big_gen))    # True
print(sum(i for i in range(10)))                          # 45

The "find the first match" pattern

first = next((c for c in courses if c["hours"] < 10), None)
print(first["code"])                                          # GIT-T
print(next((c for c in courses if c["hours"] > 100), None))   # None

next(generator, default) returns the first item and stops, without scanning the whole list; if nothing matches it returns the default instead of raising an error.

The Odoo counterparts: mapped, filtered, sorted

Odoo recordsets ship methods doing exactly these jobs, accepting both functions and field names. The ORM documentation describes:

Recordset methodPlain-Python equivalentNotes from the documentation
records.mapped('name')[r.name for r in records]Takes a function or a dotted field path ('partner_id.bank_ids'); returns a list, or a recordset when the result is a recordset (order not guaranteed)
records.filtered(f)[r for r in records if f(r)]Takes a function, a domain or a field-path string such as "partner_id.vat"; returns a recordset
records.sorted(key)sorted(records, key=key)key is a function or a string like 'name DESC, id'; without it the model's default order applies
records.grouped(key)a grouping dictReturns a dict from the result of key to recordsets
 
# list of names (plain Python ~ recordset)
names = [c.name for c in courses]            # same as courses.mapped('name')

# filter
published = [c for c in courses if c.is_published]   # same as courses.filtered('is_published')

# sort
ordered = sorted(courses, key=lambda c: c.start_date)   # same as courses.sorted('start_date')

# total the hours
total = sum(c.duration_hours for c in courses)          # same as sum(courses.mapped('duration_hours'))

One important difference: recordset methods return a recordset (you can keep chaining .write() or .mapped()), whereas a comprehension returns a plain list.

Practice: group courses by status

groups = {}
for c in courses:
    groups.setdefault(c["published"], []).append(c["code"])
print(groups)          # {True: ['ODO-F', 'PY-F'], False: ['GIT-T']}

# rewritten with a comprehension + sorted
published_codes = sorted(c["code"] for c in courses if c["published"])
unpublished_codes = sorted(c["code"] for c in courses if not c["published"])
print(published_codes, unpublished_codes)   # ['ODO-F', 'PY-F'] ['GIT-T']

Try writing one more comprehension that builds a {code: name} dict of published courses only, then use next(...) to find the first course longer than 20 hours.

Common mistakes when starting out

  • Reusing an exhausted generator. After it has been consumed a generator is empty; a second pass gives []. Build a list if you need several passes.
  • Forgetting list() around filter/map. You print <filter object at ...> instead of the result.
  • An overly complicated comprehension. Two for levels plus several conditions force the reader to decode it. Split it into a plain loop or a named function.
  • Mixing up brackets. [...] is a list, {...} a set or dict, (...) a generator, not a tuple comprehension.

Summary

  • A comprehension builds a new list/dict/set from old data with one expression; use it only while it stays readable.
  • A generator (( ... ) or yield) produces values on demand, saves memory and works once.
  • sorted, sum, min, max, any, all and next(..., default) are everyday tools.
  • Odoo's mapped, filtered, sorted and grouped do the same jobs but return recordsets.

FAQ

How does a list comprehension differ from a for loop? ▾
A comprehension is an expression that builds a new list from an old one at once, shorter than a for loop with append. Use it for plain transforming or filtering; if the loop has several steps or side effects keep an ordinary for loop.
How does a generator differ from a list? ▾
A generator does not build the whole list in memory but produces each value when asked, saving memory on large data, but it can be consumed only once.
How are Odoo's mapped and filtered like plain Python? ▾
mapped resembles a transforming comprehension and filtered a comprehension with an if condition. The difference is that recordset methods accept field names and return recordsets, while a comprehension returns a list.
How do I get the first item that matches a condition? ▾
Use next with a generator and a default, for example next((c for c in courses if c["hours"] < 10), None). It stops as soon as it finds one and returns None when nothing matches.
