Variables, Data Types and f-strings in Python

Every line of code starts with values and the names you give them. This guide explains variables, basic data types and string handling through a course-code generator, and shows where they appear in Odoo fields.

Updated: October 16, 2026 10 min read – views Vinc Academy Team

Quick summary

A Python variable is just a name pointing at a value; the type belongs to the value, not the variable. The four basic types you use daily are int, float, str and bool, plus None for "no value yet". The modern way to build strings is the f-string: f"{code}-{year}". In Odoo these types map straight onto fields.Integer, Float, Char and Boolean.

Variables: naming a value

You create a variable by assigning to it, with no type declaration. The same name can later be bound to a value of another type, and the type() function tells you what the current value is:

course_name = "Odoo Developer Foundation"
hours = 24
price = 4500000.0
is_published = True
description = None

print(type(course_name), type(hours), type(price), type(is_published), type(description))
# <class 'str'> <class 'int'> <class 'float'> <class 'bool'> <class 'NoneType'>

The Python (and Odoo) community convention is snake_case for variables and functions and CamelCase for classes. Names are case-sensitive and cannot start with a digit. That is why you see is_published and duration_hours on the vinc.course model: every model field is, in effect, a "variable" of the record.

An empty Odoo field is False, not None

On the Odoo side, the data-files reference says that when no value is supplied for a field, an implicit False is set. So when you read a Char field nobody filled in, do not test it with is None; use a "has a value" check such as if not course.name:.

Python treats these values as "false" in conditions: False, None, the number 0, the empty string and the empty list. Everything else is "true". That is why if description: screens out both None and an empty string:

print(bool(""), bool("a"), bool(0), bool([]), bool(None))
# False True False False False

Numbers and arithmetic

print(7 / 2, 7 // 2, 7 % 2, 2 ** 10)
# 3.5 3 1 1024

/ always gives a float, // divides and drops the fraction, % returns the remainder and ** is the power. For converting hours into 8-hour sessions: hours // 8 is the number of full sessions and hours % 8 the leftover hours.

Floats are stored in binary, so tiny errors appear; this is true of every language, not just Python:

print(0.1 + 0.2, 0.1 + 0.2 == 0.3)
# 0.30000000000000004 False

import math
print(math.isclose(0.1 + 0.2, 0.3))
# True

That is why Odoo's documentation tells you to compare floats with float_compare() and float_is_zero() rather than == (part 8 of the Odoo series). For money, use a Monetary field or round to the proper precision.

Strings: what you handle most

Strings go in single or double quotes; multi-line text uses triple quotes. Strings are immutable: processing functions always return a new string and never modify the old one.

Formatting: f-strings, %, format()

An f-string (a string prefixed with f) lets you embed expressions in braces and add a format after a colon:

prefix, year, seq = "ODO", 2026, 7
print(f"{prefix}-{year}-{seq:03d}")        # ODO-2026-007
price, hours = 4500000.0, 24
print(f"{price:,.0f} VND", f"{hours / 8:.1f} days")   # 4,500,000 VND 3.0 days

Two older styles still appear in Odoo code: the % operator (Odoo's docs contain self.message = "Dear %s" % (self.partner_id.name or "")) and "{} - {}".format(...). They give the same results:

print("Dear %s" % "Hien", "%d hours" % 24)    # Dear Hien 24 hours
print("{} - {}".format("ODO-F", hours))        # ODO-F - 24

Comparison and logical operators

Conditions (next part) are built from comparisons and and, or, not. The result is always True or False:

hours = 24
level = "beginner"
print(hours > 20, hours == 24, hours != 24, 10 <= hours < 30)
# True True False True
print(level == "beginner" and hours >= 24, level == "advanced" or hours > 100, not hours > 100)
# True False True
print("odoo" in "odoo developer", "Odoo" in ["odoo", "python"], 24 in [8, 24])
# True False True
  • Comparisons can be chained like 10 <= hours < 30, exactly as you would write them in maths.
  • in tests whether a substring sits inside a string or an item sits inside a list. Note that string comparison is case-sensitive: "python" == "Python" is False, so people normalize with .lower() before comparing.
  • For None, write is None / is not None instead of == None. Both usually agree, but is is the standard, clearer idiom.

These comparisons underpin Odoo domains: [('hours', '>', 20), ('level', '=', 'beginner')] is the "data" spelling of the same condition, which the ORM translates into SQL.

Converting between types

print(int("12") + 1, str(12) + "h", float("3.5"))
# 13 12h 3.5

Data read from CSV files or forms usually arrives as text, so you need int() or float() before computing. A string that is not a valid number raises ValueError (part 10 handles that).

Practice: generate a code and slug for a course

Write a script that takes a raw course name and a sequence number and returns a course code plus a URL-friendly slug:

def make_code(prefix, year, seq):
    return f"{prefix.upper()}-{year}-{seq:03d}"

def make_slug(name):
    return name.strip().lower().replace(" ", "-")

print(make_code("odo", 2026, 7))
print(make_slug("  Odoo Developer Foundation  "))
# ODO-2026-007
# odoo-developer-foundation

Try extending it: add an if not name: check to complain about an empty name. This is exactly the sort of logic you would put in create() or a compute method to auto-generate course codes.

Common mistakes when starting out

  • Adding a string and a number. "5" + 3 raises TypeError: can only concatenate str (not "int") to str. Convert (int("5") + 3) or use an f-string (f"{5}{3}").
  • Changing one character of a string. course_name[0] = "x" raises TypeError: 'str' object does not support item assignment because strings are immutable. Build a new string with replace() or slicing.
  • Comparing floats with ==. 0.1 + 0.2 == 0.3 is False. Use math.isclose() in plain Python or float_compare() in Odoo.
  • Converting a non-numeric string. int("abc") raises ValueError: invalid literal for int() with base 10: 'abc'. Validate or catch the error before converting.

Summary

  • A variable is a name for a value; use snake_case; type() reveals the type.
  • The basic types int, float, str, bool and None map onto Odoo fields.
  • Strings are immutable; work with strip, split, join, replace and f-strings.
  • Never compare floats with ==; data read from outside is often text and needs converting.

FAQ

How do Python variables differ from other languages? ▾
Python needs no type declaration; a variable is just a name bound to a value and can later be rebound to a value of another type. The type function shows the current value's type.
What is an f-string and why use it? ▾
An f-string is a string prefixed with f that embeds expressions in braces and accepts a format after a colon, such as f"{seq:03d}". It is shorter and easier to read than the % operator or format.
Why is 0.1 + 0.2 not equal to 0.3? ▾
Floats are stored in binary so small errors appear. Compare with math.isclose in Python, or float_compare and float_is_zero in Odoo, instead of a double equals sign.
Is an empty Char field in Odoo None or False? ▾
According to Odoo's data-files reference, when no value is given for a field an implicit False is set. Test with if not value rather than is None.
