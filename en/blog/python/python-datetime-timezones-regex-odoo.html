Python Dates, Times, datetime and Regex for Odoo Devs

Dates and strings needing validation are the two kinds of data most prone to input mistakes. This guide teaches datetime, timedelta, time zones and regex in Python, then shows Odoo's Date/Datetime rules such as UTC storage and the fields.Date.add, start_of and end_of helpers.

Updated: October 16, 2026 16 min read Vinc Academy Team

Quick summary

The datetime module gives you date, datetime and timedelta for date arithmetic; strptime/strftime convert between strings and dates. The re module checks and extracts strings by pattern. With Odoo, remember that Datetime is stored in UTC, a Date compares only with date and a Datetime only with datetime, and prefer fields.Date.today(), add, start_of and end_of over hand calculation.

date, datetime and string formats

from datetime import date, datetime, timedelta

d = date(2026, 10, 16)
print(d, d.year, d.month, d.day, d.isoformat())      # 2026-10-16 2026 10 16 2026-10-16

dt = datetime(2026, 10, 16, 9, 30, 15)
print(dt, dt.date(), dt.time())     # 2026-10-16 09:30:15 2026-10-16 09:30:15
print(dt.strftime("%d/%m/%Y %H:%M"))                 # 16/10/2026 09:30
print(datetime.strptime("16/10/2026 09:30", "%d/%m/%Y %H:%M"))   # 2026-10-16 09:30:00
print(date.fromisoformat("2026-10-16"))              # 2026-10-16
Format codeMeaningExample

strftime turns a date into a string using a format; strptime does the reverse and the format must match the input string exactly. When a string already follows ISO (YYYY-MM-DD), date.fromisoformat and datetime.fromisoformat are tidier. ISO is also the form to prefer when exchanging data between systems.

Arithmetic with timedelta

td = timedelta(days=7, hours=3)
print(d + timedelta(days=30), dt + td)     # 2026-11-15 2026-10-23 12:30:15
print(td.days, td.total_seconds())         # 7 615600.0

print(date(2026, 12, 31) - d)              # 76 days, 0:00:00
print((date(2026, 12, 31) - d).days)       # 76

start = date(2026, 11, 3)
print([start + timedelta(weeks=i) for i in range(3)])
# [datetime.date(2026, 11, 3), datetime.date(2026, 11, 10), datetime.date(2026, 11, 17)]
print(d < date(2026, 11, 1), d == date(2026, 10, 16))   # True True

A timedelta is a span of time (days, hours, minutes, weeks...). Adding or subtracting it from a date gives a new date; subtracting two dates gives a timedelta. Familiar problems: a registration deadline is the start date minus 7 days, a course's end date is the start date plus a number of weeks, and days left until a deadline is (deadline - date.today()).days. Note that timedelta has no month or year unit because their lengths vary; Odoo handles that with fields.Date.add(today, months=3).

Everyday date problems

Beyond adding and subtracting, real work often needs: the weekday, the first and last day of a month, the next Monday, adding working days. Python offers weekday() (0 is Monday), isocalendar() and the calendar module:

from datetime import date, timedelta
import calendar

d = date(2026, 10, 16)
print(d.weekday(), calendar.day_name[d.weekday()])        # 4 Friday   (0 = Monday ... 6 = Sunday)
print(d.isocalendar().week)                               # 42   (which week of the year)

print(calendar.monthrange(2026, 2))                       # (6, 28): weekday of the 1st, number of days in the month
first = d.replace(day=1)
last = d.replace(day=calendar.monthrange(d.year, d.month)[1])
print(first, last)                                        # 2026-10-01 2026-10-31

next_monday = d + timedelta(days=(7 - d.weekday()) % 7 or 7)
print(next_monday, next_monday.weekday())                 # 2026-10-19 0

def add_workdays(start, n):                               # add n working days (skipping Saturday and Sunday)
    cur = start
    while n > 0:
        cur += timedelta(days=1)
        if cur.weekday() < 5:
            n -= 1
    return cur

print(add_workdays(d, 5))                                 # 2026-10-23

print(date(2026, 1, 31) + timedelta(days=30))             # 2026-03-02  <- "adding a month" as 30 days is not always right

The last line shows the trap of "adding a month as 30 days": 31 January plus 30 days gives 2 March, skipping February altogether. Because month lengths vary, use a tool that understands calendars. In plain Python that is dateutil.relativedelta (d + relativedelta(months=3), a library that ships with Odoo); in Odoo it is fields.Date.add(d, months=3), which passes its arguments to relativedelta as the documentation describes. Be careful with working days too: the calculation above only skips weekends and knows nothing about public holidays, so a real system needs a list of days off as well.

Time zones: naive and aware

from datetime import timezone, timedelta
from zoneinfo import ZoneInfo

utc = datetime(2026, 10, 16, 2, 0, tzinfo=timezone.utc)
vn = utc.astimezone(timezone(timedelta(hours=7)))
print(utc.isoformat())                  # 2026-10-16T02:00:00+00:00
print(vn.isoformat(), vn.strftime("%H:%M"))   # 2026-10-16T09:00:00+07:00 09:00
print(utc.astimezone(ZoneInfo("Asia/Ho_Chi_Minh")).strftime("%Y-%m-%d %H:%M"))   # 2026-10-16 09:00

naive = datetime(2026, 10, 16, 9, 0)    # no time zone (naive)
naive < utc
# TypeError: can't compare offset-naive and offset-aware datetimes

An object without a time zone is naive, one with a zone is aware. Python refuses to compare the two kinds, so you must align them first. The golden rule for business systems: store and compute in UTC and convert to the user's zone only when displaying. Odoo follows it: the ORM documentation says Datetime columns hold UTC timestamps without a zone, leaving the conversion to the client. QWeb reports provide a context_timestamp function that converts a UTC datetime to the printing user's zone.

Date and Datetime in Odoo

from odoo import fields

today = fields.Date.today()                         # a date, in the format the ORM expects
now = fields.Datetime.now()                         # a datetime (UTC)
end = fields.Date.add(today, months=3)              # add a span, arguments go to relativedelta
first = fields.Date.start_of(today, 'month')        # first day of the month
last = fields.Date.end_of(today, 'month')           # last day of the month
d = fields.Date.to_date("2026-10-16")               # string -> date
s = fields.Date.to_string(today)                    # date -> string 'YYYY-MM-DD'

# the default is today, evaluated when a record is created
start_date = fields.Date(default=fields.Date.today)

Regex: validating and extracting strings by pattern

A regular expression (regex) describes a string pattern. Use a raw string r"..." so backslashes are not processed by Python first. Below, checking a course code and extracting an email and a phone number:

import re

code_re = re.compile(r"^[A-Z]{2,4}-\d{3}$")          # 2-4 capital letters, a dash, exactly 3 digits
for c in ("ODO-001", "odo-1", "PY-12345"):
    print(c, bool(code_re.match(c)))
# ODO-001 True
# odo-1 False
# PY-12345 False

text = "Contact: hien@example.com or sale@example.vn, phone 0900 111 222"
print(re.findall(r"[\w.+-]+@[\w-]+\.[\w.]+", text))     # ['hien@example.com', 'sale@example.vn']
m = re.search(r"(\d{4}) (\d{3}) (\d{3})", text)
print(m.group(0), m.groups())                         # 0900 111 222 ('0900', '111', '222')

print(re.sub(r"\s+", " ", "a   b \n c"))             # a b c
print(re.sub(r"\D", "", "0900 111-222"))              # 0900111222  (chỉ giữ chữ số)
print(re.split(r"[,;]\s*", "a, b;c"))                 # ['a', 'b', 'c']
PatternMatches
\d, \w, \sA digit, a letter-digit-underscore character, whitespace (the capitals \D, \W, \S negate)
.Any single character (except a newline)
*, +, ?, {3}, {2,4}0 or more, 1 or more, 0 or 1, exactly 3, between 2 and 4 times
[A-Z], [^0-9]One character from a set, or not from the set

m = re.match(r"(?P<code>[A-Z]+)-(?P<seq>\d+)", "ODO-007")
print(m["code"], int(m["seq"]), m.groupdict())        # ODO 7 {'code': 'ODO', 'seq': '007'}

print(re.match(r"\d+", "abc"), re.fullmatch(r"\d+", "123x"))   # None None
print(re.findall(r"a.*b", "a1b a2b"))                  # ['a1b a2b']   <- greedy: swallows both
print(re.findall(r"a.*?b", "a1b a2b"))                 # ['a1b', 'a2b'] <- lazy: shortest match
print(bool(re.search("odoo", "Odoo 20", re.IGNORECASE)))   # True
  • re.match matches only at the start of a string, re.search looks anywhere, and re.fullmatch demands that the entire string match.
  • Repetition marks are greedy by default (matching as much as possible); add ? (as in .*?) for the shortest match.
  • re.compile compiles a pattern once for repeated use, faster and tidier.

Regex is powerful but easily unreadable: if a pattern runs past one line, split it, name the constants and add a few test lines. For validating emails to the full standard, a simple pattern like the one above is only a rough filter, not a replacement for real verification.

A few useful regex recipes

The principle: use regex to check shape and let dedicated functions (such as date.fromisoformat and int()) check meaning. A pattern with the right shape but a wrong meaning, like the date 2026-13-45, slips through if regex is all you use.

Practice: validate a code and compute a course end date

import re
from datetime import date, timedelta

CODE_RE = re.compile(r"^[A-Z]{2,4}-\d{3}$")

def validate_course(code, start, weeks):
    """Return (valid, end date or error message)."""
    if not CODE_RE.match(code):
        return False, f"Invalid code: {code}"
    try:
        start_date = date.fromisoformat(start)
    except ValueError:
        return False, f"Invalid date: {start}"
    return True, start_date + timedelta(weeks=weeks)

print(validate_course("ODO-001", "2026-11-03", 8))   # (True, datetime.date(2026, 12, 29))
print(validate_course("odo-1", "2026-11-03", 8))     # (False, 'Invalid code: odo-1')
print(validate_course("ODO-001", "2026-13-03", 8))   # (False, 'Invalid date: 2026-13-03')

This function combines two things you often do with input data: checking a code's format with regex and turning a date string into a date object, then adding a span. Try extending it so the start date must fall on a Monday (start_date.weekday() == 0).

Common mistakes when starting out

datetime.strptime("2026-10-16", "%d/%m/%Y")
# ValueError: time data '2026-10-16' does not match format '%d/%m/%Y'

date(2026, 2, 30)
# ValueError: day is out of range for month
  • A strptime format that does not match the string. Raises ValueError: time data ... does not match format .... Check day-month order and separators.
  • Comparing naive and aware datetimes. Raises TypeError: can't compare offset-naive and offset-aware datetimes. Make both aware, or both UTC without a zone as Odoo does.
  • A date that does not exist. date(2026, 2, 30) raises day is out of range for month.
  • Using re.match to search the middle of a string. It only matches at the start; use re.search.
  • Forgetting raw strings. "\d" in a plain string is easy to get wrong; always write r"\d".
  • Comparing a Date with a Datetime in Odoo. The documentation warns each type compares only with its own kind; use to_date() to align them.

Summary

  • date, datetime, timedelta for arithmetic; strftime/strptime for strings; ISO for data exchange.
  • Compute in UTC and convert zones for display; never mix naive with aware.
  • Odoo: use fields.Date.today/add/start_of/end_of; Date against date, Datetime against datetime.
  • re: use raw strings, know match/search/fullmatch, greedy and lazy.

FAQ

In which time zone does Odoo store a Datetime? ▾
According to the ORM documentation, Datetime fields are stored as timestamps without time zone in UTC, so the database is independent of the server's zone. Time zone conversion is handled by the client side.
Why does Python raise an error when comparing two datetimes? ▾
Python refuses to compare a datetime without a time zone (naive) with one that has a zone (aware) and raises TypeError. Make both naive or both aware, ideally computing in UTC.
How does re.match differ from re.search? ▾
re.match matches only at the start of the string, re.search looks anywhere, and re.fullmatch requires the entire string to match.
How do I add 3 months to a date in Odoo? ▾
Use fields.Date.add(date, months=3). Python's timedelta has no month or year unit because their lengths vary, while Odoo's add passes the arguments to relativedelta.
