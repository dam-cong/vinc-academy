What is Odoo? Fundamentals for Developers (Odoo 20)

Odoo is more than business management software: for developers it is a complete Python framework for building business applications. This guide helps you understand Odoo properly before you write your first line of code.

Updated: October 16, 2026 10 min read Vinc Academy team

Quick answer

Odoo is an open-source ERP platform written in Python, using PostgreSQL as its database. Every feature (sales, accounting, inventory, HR…) is a module. Odoo developers build new modules or extend existing ones with Python, XML and JavaScript (OWL). The latest version is Odoo 20 (September 2026).

What is Odoo?

Picture an office-equipment company: sales tracks orders in Excel, accounting uses its own software, the warehouse uses another tool, and HR records attendance on paper. At the end of every month, someone reconciles numbers across four places. ERP (Enterprise Resource Planning) exists to bring all of that into one system with a single database.

Odoo is such an ERP, with two key differences:

  • Open source: the Community edition publishes its full source code, so anyone can read, install and extend it.
  • Modular architecture: companies install only the apps they need, and each app can be customized by another module without touching the original code.

For end users, Odoo is a management suite. For developers, Odoo is a business application framework: you declare models in Python and Odoo creates the PostgreSQL tables; you describe screens in XML and Odoo renders forms, lists, kanban boards, filters and access control. Most of an Odoo developer's job is writing and customizing such modules.

Because everything shares one database, a sales order can automatically create a delivery, an invoice and accounting entries. Understanding how data flows between modules is what separates a strong Odoo developer from someone who only writes code.

Odoo Community vs Enterprise

Odoo ships two editions side by side. The key point for developers: Enterprise is not a different product, it is a set of modules installed on top of Community.

Odoo 20 technical architecture

Odoo follows a multitier architecture that separates presentation, business logic and storage:

  • Presentation tier runs in the browser. Since version 15, Odoo uses OWL, its own component-based JavaScript framework.
  • Logic tier is written entirely in Python. The Odoo ORM maps Python classes to database tables, so you rarely write SQL by hand.
  • Data tier uses PostgreSQL only, so solid SQL and PostgreSQL skills pay off when tuning performance.

Anatomy of an Odoo module

Everything in Odoo is packaged as a module (also called an addon), placed in directories listed in addons_path. A module is identified by its __manifest__.py file. Here is the structure of vinc_course, a sample course-management module written by Vinc Academy (similar to the Training Management System project in the Odoo Developer Foundation program):

vinc_course/

vinc_course/
├── __init__.py
├── __manifest__.py          # Module declaration
├── models/
│   ├── __init__.py
│   └── course.py            # Python model (ORM)
├── views/
│   ├── course_views.xml     # Form, list, search views
│   └── menus.xml            # Menus & actions
├── security/
│   └── ir.model.access.csv  # Access rights per group
├── data/                    # Initial data (XML/CSV)
└── static/                  # Images, CSS, JavaScript (OWL)

vinc_course/__manifest__.py

vinc_course/models/course.py

from odoo import api, fields, models


class VincCourse(models.Model):
    _name = 'vinc.course'
    _description = 'Course'

    name = fields.Char(string='Course name', required=True)
    session_count = fields.Integer(string='Sessions', default=8)
    student_ids = fields.Many2many('res.partner', string='Students')
    student_count = fields.Integer(compute='_compute_student_count')

    @api.depends('student_ids')
    def _compute_student_count(self):
        for course in self:
            course.student_count = len(course.student_ids)

With a few dozen lines, Odoo creates the vinc_course table in PostgreSQL, a many-to-many relation to contacts and a computed field that updates itself. That is why Odoo lets teams ship business features quickly.

System requirements and hosting options

According to the Odoo 20 source-install guide, a development environment needs Python 3.12 or later and PostgreSQL 16 or later (both raised from previous versions), and runs on Linux, Windows and macOS. Community source code comes from the 20.0 branch of the odoo/odoo repository.

In production, companies choose one of three options, and that choice decides whether developers can deploy custom modules:

OptionDescriptionCustom modules
Odoo OnlineSaaS operated by OdooNot supported
Odoo.shOdoo's cloud platform for code-based projects, managed with branches (development, staging, production)Yes
On-premiseSelf-hosted on the company's own servers, with self-managed backups and operationsYes, full control

In practice

Projects with customizations usually run on Odoo.sh or on-premise. On-premise makes Linux, Docker, Nginx and backups part of the job, which is why Vinc offers a dedicated DevOps for Odoo program.

How is Odoo different from Django?

Both are Python frameworks, so this is a common question for developers moving to Odoo:

AspectDjangoOdoo
GoalGeneral-purpose web frameworkFramework + ready-made business apps
UIBuild your own templates/front-end; basic admin siteForms, lists, kanban, pivot, calendar… declared in XML
ExtendingWrite new apps and integrate them yourselfInherit models/views of other modules without editing their code
Access controlDesign your own or use a libraryBuilt-in access rights and record rules
Best forWebsites, APIs, fully custom productsERP and business workflows

In short: Django hands you bricks to build from the foundation up, while Odoo hands you a finished building to renovate and extend. The most important Odoo skill is therefore understanding existing modules and inheriting from them correctly.

What should an Odoo developer learn?

Based on the Developer section of the Odoo 20 documentation and our teaching experience, Vinc Academy recommends this order:

  1. Foundations: Python (OOP), SQL with PostgreSQL, Git.
  2. Modules & ORM: manifests, models, field types, recordsets, CRUD.
  3. User interface: XML views (form, list, search, kanban), actions and menus.
  4. Security: user groups, access rights, record rules.
  5. Business logic: computed fields, onchange, constraints.
  6. Inheritance: extending models and views of other modules.
  7. Reports: QWeb and PDF reports.
  8. Front-end: OWL components, assets.
  9. Integration: web controllers, External JSON-2 API.
  10. Quality: unit tests, performance, version upgrades.

Frequently asked questions

Is Odoo free? ▾
Odoo Community is open source under the LGPLv3 license, so you can download it, install it and build modules for free. Odoo Enterprise is a paid subscription that adds extra apps, advanced features, support and upgrade services.
What should I know before learning Odoo development? ▾
You should be comfortable with basic Python (functions, classes, inheritance), SQL with PostgreSQL, and Git. Some HTML, XML and JavaScript makes front-end customization much easier.
What is the latest Odoo version and what does it require? ▾
Odoo 20 was released in September 2026. According to the official installation guide, it requires Python 3.12 or later and PostgreSQL 16 or later, and runs on Linux, Windows and macOS.
How long does it take to learn Odoo development? ▾
With a Python background, you can build a complete Odoo module after about 8 guided, hands-on sessions. Complete beginners should add around 5 sessions for Python, PostgreSQL and Git.
Should I learn Odoo Community or Enterprise? ▾
Start with Community: it is open source and covers the whole framework. Enterprise is built as additional modules on top of Community, so your knowledge carries over naturally when you join real projects.
