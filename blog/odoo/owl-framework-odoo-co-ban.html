OWL trong Odoo 20: component, hook và assets cơ bản

OWL là nền tảng của giao diện web Odoo. Bài này giúp bạn hiểu component OWL, viết component đầu tiên, đưa file vào bundle assets và nắm các khối xây dựng của web client: registry, service và hook.

Cập nhật: 16/10/2026 14 phút đọc Đội ngũ Vinc Academy

Tóm tắt nhanh

Giao diện web của Odoo được xây bằng OWL, một framework component khai báo, template viết bằng QWeb. Mỗi component thường gồm một file JavaScript và một file template XML, được thêm vào bundle web.assets_backend qua khóa assets trong manifest. Trong component, khởi tạo trạng thái ở setup() (không dùng constructor) bằng hook như useState.

OWL là gì và nằm ở đâu trong Odoo?

Odoo web client là một ứng dụng một trang (single-page): mỗi lần người dùng thao tác, nó chỉ xin server phần dữ liệu cần thiết rồi cập nhật màn hình, và giữ URL đồng bộ với trạng thái hiện tại. Phần giao diện này dùng OWL, hệ thống component khai báo, lấy cảm hứng từ Vue và React. Component được định nghĩa bằng template QWeb có thêm vài chỉ thị riêng của OWL. Tài liệu Odoo nhấn mạnh: mọi phát triển mới nên viết bằng OWL nếu có thể. Mã nguồn OWL được duy trì ở một kho GitHub riêng, và mọi phiên bản Odoo từ 14 dùng chung phiên bản OWL.

Hai cách hiểu từ "frontend"

Trong hệ sinh thái Odoo, frontend thường chỉ website công khai còn backend chỉ web client, khác với cách dùng thông thường (trình duyệt và server). Trong tài liệu, "component" luôn là component OWL, còn "widget" là cách viết cũ.

Component OWL đầu tiên

Theo khuyến nghị, một component nên gồm 2-3 file đặt cạnh nhau: file JavaScript, file template XML và tùy chọn file SCSS/CSS. Dưới đây là component đếm đơn giản cho module vinc_course:

vinc_course/static/src/components/course_counter/course_counter.js

import { Component, useState } from "@odoo/owl";

export class CourseCounter extends Component {
    static template = "vinc_course.CourseCounter";

    setup() {
        this.state = useState({ value: 0 });
    }

    increment() {
        this.state.value++;
    }
}

vinc_course/static/src/components/course_counter/course_counter.xml

<?xml version="1.0" encoding="UTF-8"?>
<templates xml:space="preserve">
    <t t-name="vinc_course.CourseCounter">
        <button class="btn btn-primary" t-on-click="increment">
            Đã xem: <t t-out="state.value"/>
        </button>
    </t>
</templates>
  • useState tạo trạng thái phản ứng (reactive): khi state.value đổi, giao diện tự cập nhật.
  • t-on-click="increment" là chỉ thị của OWL gắn sự kiện vào method của component.
  • Template nên nằm trong file XML để được dịch thuật, và component chỉ khai báo tên template. Template định nghĩa ngay trong JavaScript bằng helper xml chỉ phù hợp lúc mới làm quen.
  • Quy ước đặt tên template là tên_addon.TênComponent, giúp tránh trùng tên giữa các module.

Dùng setup(), đừng dùng constructor

Component là class nên có constructor, nhưng constructor trong JavaScript không thể ghi đè theo cách Odoo cần. Vì vậy, khởi tạo mọi thứ trong method setup(). Không component nào trong Odoo được dùng trực tiếp constructor(parent, props).

Thêm file vào bundle assets

JavaScript, CSS và template không tự được nạp. Bạn khai báo chúng trong khóa assets của manifest: một từ điển ánh xạ tên bundle tới danh sách file, hỗ trợ glob để gom nhiều file bằng một dòng:

'assets': {
    'web.assets_backend': [
        'vinc_course/static/src/components/**/*',
    ],
},
BundleChứa gì
web.assets_backendMã dành riêng cho web client (action, view, template XML tĩnh)
web.assets_frontendMã dành riêng cho website công khai: thương mại điện tử, portal, diễn đàn, blog
web.assets_commonMã chung cho web client, website và Point of Sale; nền tảng của framework
web.assets_unit_testsToàn bộ mã test JavaScript

Mặc định, file trong /static/src và /static/tests được Odoo chuyển (transpile) từ module JavaScript chuẩn sang module của Odoo. Các file được gộp, minify (trừ khi bật debug=assets) rồi gửi cho trình duyệt; khi cần debug, dùng ?debug=assets để tải bản chưa nén.

Các khối xây dựng của web client

Web client chủ yếu được tạo từ bốn loại đối tượng: registries, services, components và hooks.

  • Registry: ánh xạ khóa-giá trị lưu một loại đối tượng. Khi đã đăng ký, phần còn lại của web client dùng được; ví dụ registry fields chứa các component field dùng trong view. Đây là điểm mở rộng quan trọng của giao diện.
  • Service: đoạn mã chạy lâu dài cung cấp một tính năng, như một hệ thống dependency injection. Ví dụ service notification hiển thị thông báo, service rpc là cách đúng để gọi server. Component lấy service bằng hook useService.
  • Component: các component OWL thuộc web client.
  • Hook: hàm tái sử dụng logic gắn với vòng đời component, như một kiểu mixin theo phong cách hàm. useState là hook, và bạn tự viết được hook của mình bằng onWillStart, onWillUnmount…

Một component truy cập môi trường (this.env) để lấy các service, cờ debug, hàm dịch và cờ isSmall (đúng khi màn hình rộng từ 767px trở xuống).

Gắn component vào giao diện

Cách gắn component vào Odoo phụ thuộc điểm mở rộng bạn chọn: làm field, view, màn hình client action hay thành phần chính của web client (qua registry main_components). Mỗi điểm có API riêng nên bạn nên đọc tiếp tutorial chính thức Discover the web framework (chương Owl components và Build a dashboard), có kèm kho mã mẫu cho Odoo 20. Tutorial này yêu cầu bạn đã quen model, controller và QWeb, đúng với những gì series đã đi qua.

Mã JavaScript của web client nằm ở đâu?

Toàn bộ JavaScript (kèm CSS và template) của module web nằm trong web/static/src. Bạn có thể import mọi thứ trong thư mục này bằng tiền tố @web, ví dụ import { memoize } from "@web/core/utils/functions". Các thư mục chính:

Thư mụcChứa gì
core/Phần lớn tính năng mức thấp
fields/Tất cả component field
views/Các component view bằng JavaScript (form, list…)
search/Control panel, thanh tìm kiếm, search panel
webclient/Mã riêng của web client: navbar, menu người dùng, action service…

Bản thân web client là một ứng dụng OWL. Template của nó (rút gọn) gồm NavBar, ActionContainer (hiển thị controller của action hiện tại, tức client action hoặc một view của action act_window) và MainComponentsContainer (hiển thị mọi component đã đăng ký trong registry main_components, đây là cách các phần khác mở rộng web client). Action service giữ trong bộ nhớ một ngăn xếp các action đang hoạt động, chính là các mục trên breadcrumb.

Môi trường this.env

KhóaGiá trị
qwebOWL yêu cầu; chứa mọi template
busBus chính, điều phối một số sự kiện chung
servicesTất cả service đã triển khai (nên truy cập qua hook useService)
debugChuỗi; khác rỗng nghĩa là web client đang ở chế độ debug
_tHàm dịch chuỗi
isSmallBoolean; đúng khi đang ở chế độ di động (màn hình rộng từ 767px trở xuống)

Template được dịch tự động, nên chỉ cần hàm _t khi dịch chuỗi trong mã JavaScript.

Các thao tác với assets

Thông thường chỉ cần thêm file vào một bundle phổ biến. Với nhu cầu đặc thù, manifest còn hỗ trợ các thao tác sau (thao tác nhắm vào một file cụ thể như before, after, replace, remove yêu cầu file đó đã được khai báo trước, ở manifest cấp trên trong chuỗi phụ thuộc hoặc ở bản ghi ir.asset có sequence thấp hơn):

Thao tácCú phápTác dụng
append'path'Thêm file vào cuối bundle (mặc định)
prepend('prepend', path)Thêm file vào đầu bundle
before('before', target, path)Thêm file ngay trước file đích
after('after', target, path)Thêm file ngay sau file đích
include('include', bundle)Dùng lồng một bundle khác (bundle con thường bắt đầu bằng dấu gạch dưới)
remove('remove', target)Bỏ file khỏi bundle
replace('replace', target, path)Thay file bằng phiên bản của bạn, ở đúng vị trí cũ

Thứ tự nạp rất quan trọng với CSS và script khởi tạo. Quy trình của Odoo: bắt đầu từ danh sách rỗng; áp dụng các bản ghi ir.asset có sequence nhỏ hơn 16; sau đó áp dụng thao tác khai báo trong manifest của từng module theo thứ tự phụ thuộc (module web trước website); cuối cùng áp dụng các bản ghi ir.asset còn lại. Một file đã có trong danh sách thì không được thêm lần nữa, nên chỉ lần xuất hiện đầu tiên được giữ.

Ba loại file JavaScript

  • Module JavaScript chuẩn (native): dùng cho mọi file mới. Odoo tự chuyển file dưới /static/src và /static/tests thành module của Odoo; ở thư mục khác, file chỉ được chuyển nếu dòng đầu chứa chú thích @odoo-module.
  • Module Odoo (hệ thống module riêng): chỉ còn hữu ích cho các file cũ chưa được chuyển đổi.
  • File JavaScript thuần: chỉ dành cho thư viện ngoài và một vài việc mức rất thấp, nên viết dạng IIFE để không làm rò biến ra phạm vi toàn cục. Mọi thư viện ngoài đều nạp dạng này. Muốn Odoo bỏ qua một file, đặt dòng đầu là /** @odoo-module ignore **/.

Component dựng sẵn

Web client cung cấp bộ component tổng quát để dùng lại: ActionSwiper (hành động khi vuốt ngang), CheckBox, ColorList, Dropdown, Notebook (chuyển trang bằng tab), Pager (phân trang), SelectMenu (dropdown chọn một mục) và TagsList (danh sách thẻ dạng viên thuốc). Mỗi component có vị trí import riêng, ví dụ @web/core/action_swiper/action_swiper; hãy tra trang Owl components của tài liệu trước khi tự viết lại những thứ này.

Lỗi hay gặp khi mới học OWL

  • Viết khởi tạo trong constructor. Hãy dùng setup(); tài liệu Odoo khẳng định không component nào được dùng trực tiếp constructor.
  • Tạo xong file JS và XML nhưng giao diện không thay đổi. Thường là file chưa nằm trong bundle: kiểm tra khóa assets trong manifest và glob đường dẫn, nâng cấp module bằng -u, rồi mở ?debug=assets để xem file có được tải không.
  • Đặt tên template quá chung chung như MyComponent. Hãy theo quy ước tên_addon.TênComponent để không trùng với module khác.

Tổng kết

  • Giao diện web Odoo là ứng dụng một trang xây bằng OWL; phát triển mới nên dùng OWL.
  • Component = class JavaScript + template XML (tên_addon.TênComponent), khởi tạo trong setup().
  • File phải nằm trong bundle ở khóa assets; ?debug=assets giúp kiểm tra.
  • Registry, service, hook và this.env là bốn khái niệm cần nắm.

Bài sau quay lại phía server: viết controller và dùng API JSON-2 để tích hợp Odoo với hệ thống khác.

Câu hỏi thường gặp

OWL là gì trong Odoo? ▾
OWL là framework component khai báo, lấy cảm hứng từ Vue và React, dùng để xây giao diện web client của Odoo. Component được định nghĩa bằng template QWeb có thêm một số chỉ thị riêng của OWL.
Vì sao dùng setup() thay vì constructor? ▾
Constructor trong JavaScript không thể ghi đè theo cách Odoo cần, nên tài liệu quy định mọi khởi tạo phải đặt trong method setup() và không component nào được dùng trực tiếp constructor.
File JavaScript và template của component được nạp bằng cách nào? ▾
Bạn khai báo chúng trong khóa assets của manifest, thường vào bundle web.assets_backend cho web client. Framework sẽ nạp file JavaScript, CSS và các template vào OWL.
Registry, service và hook khác nhau thế nào? ▾
Registry là ánh xạ khóa-giá trị lưu các đối tượng mở rộng được. Service là mã chạy lâu dài cung cấp một tính năng như thông báo hay gọi server. Hook là hàm tái sử dụng logic gắn với vòng đời component.
