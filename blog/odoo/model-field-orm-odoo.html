Model, field và ORM trong Odoo 20: tạo model đầu tiên

Model là trái tim của mọi module Odoo. Bài này hướng dẫn khai báo model bằng Python, chọn kiểu field phù hợp, và dùng recordset để thêm, tìm, sửa, xóa dữ liệu mà không phải viết SQL.

Cập nhật: 16/10/2026 13 phút đọc – lượt xem Đội ngũ Vinc Academy

Tóm tắt nhanh

Trong Odoo 20, mỗi bảng dữ liệu được khai báo bằng một class Python kế thừa models.Model, trong đó _name là thuộc tính bắt buộc. Các cột là những fields.* (Char, Integer, Selection…). Sau khi sửa file Python, khởi động lại server kèm -d và -u để ORM tạo bảng và cột trong PostgreSQL. Đọc ghi dữ liệu thông qua recordset với create, search, write, unlink.

Model và ORM là gì?

ORM (Object-Relational Mapping) là lớp trung gian giúp bạn làm việc với dữ liệu bằng đối tượng Python thay vì tự viết phần lớn câu lệnh SQL. Mỗi model là một class kế thừa models.Model; Odoo đọc khai báo đó và tự tạo bảng tương ứng trong PostgreSQL, đồng thời cung cấp sẵn các dịch vụ về phân quyền và mở rộng.

Định nghĩa nhỏ nhất của một model chỉ gồm _name, tên model theo kiểu có dấu chấm. Tài liệu Odoo cho biết chỉ với bấy nhiêu, ORM đã đủ thông tin để tạo bảng; tên bảng lấy từ _name với dấu chấm đổi thành dấu gạch dưới, ví dụ vinc.course sinh ra bảng vinc_course.

Quy ước đặt file

Đặt mọi model trong thư mục models/, mỗi model một file Python. File đó được import trong models/__init__.py, còn thư mục models được import trong __init__.py ở gốc module (khung scaffold ở bài 3 đã làm sẵn bước này).

Tạo model đầu tiên: vinc.course

Chúng ta tiếp tục module vinc_course của bài trước và thêm model khóa học. Tạo file models/course.py:

custom-addons/vinc_course/models/course.py

from odoo import fields, models


class VincCourse(models.Model):
    _name = 'vinc.course'
    _description = "Khóa học"

    name = fields.Char(string="Tên khóa học", required=True)
    description = fields.Text()
    start_date = fields.Date()
    duration_hours = fields.Integer(help="Tổng số giờ học")
    price = fields.Float()
    is_published = fields.Boolean(default=False)
    level = fields.Selection(
        [('beginner', "Cơ bản"), ('intermediate', "Trung cấp"), ('advanced', "Nâng cao")],
        default='beginner',
    )

custom-addons/vinc_course/models/__init__.py

from . import course

File __init__.py do scaffold sinh ra đang import file mẫu models.py; hãy thay dòng đó bằng dòng import course như trên.

Mọi thay đổi trong file Python đều cần khởi động lại server. Vì ta vừa thêm model mới nên cần nâng cấp module để ORM áp dụng thay đổi cấu trúc database. Hãy nhớ -u luôn đi kèm -d:

python3 odoo-bin --addons-path=addons,../custom-addons \
    -d odoo20_dev -u vinc_course

Khi khởi động, log có thể cảnh báo model chưa có quyền truy cập (no access rules). Đó là chuyện bình thường ở bước này và sẽ được giải quyết ở bài 5. Hãy kiểm tra bảng đã được tạo bằng psql:

psql -d odoo20_dev -c "\d vinc_course"

Trong kết quả, ngoài các cột bạn khai báo còn có thêm vài cột bạn chưa viết. Đó là các trường tự động ở mục sau.

Thuộc tính cấu hình của model

Ngoài _name và _description, model còn nhiều thuộc tính tùy chọn bắt đầu bằng dấu gạch dưới:

Có ba lớp cha để tạo model: Model (lưu trong database, dùng hầu hết thời gian), TransientModel (dữ liệu tạm thời, dùng cho wizard) và AbstractModel (không có bảng; làm lớp cơ sở để các model khác kế thừa).

Các kiểu field cơ bản

Field được khai báo như thuộc tính của class và quyết định model lưu được gì, lưu ở đâu. Có hai nhóm: field đơn giản (giá trị đơn lẻ lưu trực tiếp trong bảng) và field quan hệ (nối các bản ghi với nhau, học ở bài 7).

FieldKiểu PythonCột PostgreSQLDùng cho
Charstrcharacter varyingChuỗi một dòng: tên, mã, mã bưu chính
TextstrtextVăn bản dài, nhiều dòng
IntegerintintegerSố nguyên: số giờ, số phòng
Floatfloatdouble precisionSố thực: giá, diện tích
BooleanboolbooleanĐúng/sai: đã xuất bản, có gara
DatedatedateNgày (không có giờ)
Selectionstrcharacter varyingChọn một trong danh sách cố định các cặp (giá trị, nhãn)

Với Selection, thuộc tính selection là bắt buộc (trừ field kế thừa hoặc related). Giá trị lưu xuống database là phần tử đầu của mỗi cặp, còn phần tử thứ hai là nhãn hiển thị cho người dùng.

Thuộc tính thường dùng của field

requiredFalseBắt buộc có giá trị; phải có default hoặc luôn được truyền khi tạo bản ghi. Cột trong database trở thành not null

Thêm vài thuộc tính field hữu ích

  • copy: có sao chép giá trị khi nhân đôi bản ghi hay không (mặc định True với field thường). Field tên name kiểu Char mặc định được đánh dấu để khi sao chép có nhãn "(copy)".
  • groups: chuỗi các nhóm (cách nhau bởi dấu phẩy) được phép truy cập field; chi tiết ở bài 5.
  • index: ngoài True/False, có thể là "btree" (chỉ mục chuẩn, hợp cho Many2one), "btree_not_null" (bỏ qua giá trị NULL) hoặc "trigram" (chỉ mục GIN, hợp cho tìm kiếm văn bản).
  • translate (Char, Text): cho phép dịch giá trị của field; size giới hạn độ dài của Char.
  • digits của Float là cặp (tổng số chữ số, số chữ số thập phân). Với số lượng gắn đơn vị đo, hãy dùng Float.round(), is_zero(), compare() để so sánh đúng độ chính xác.

Các trường tự động

Odoo tự thêm vài field vào mọi model, do hệ thống quản lý, bạn chỉ đọc được chứ không ghi được:

  • id: định danh duy nhất của bản ghi.
  • create_date và create_uid: thời điểm tạo và người tạo.
  • write_date và write_uid: thời điểm và người sửa gần nhất.

Nhờ đó bạn không cần tự thiết kế cột "ngày tạo", "người tạo" cho mỗi bảng.

Recordset và thao tác CRUD với ORM

Mọi thao tác với model đi qua recordset: một tập có thứ tự các bản ghi của cùng một model, có thể chứa từ 0 đến toàn bộ bản ghi. Duyệt recordset bằng vòng for sẽ trả từng bản ghi đơn lẻ. Cách dễ nhất để thử là odoo shell, trong đó env có sẵn:

python3 odoo-bin shell -c ~/odoo-dev/odoo20.conf -d odoo20_dev
Course = env['vinc.course']

# Create: tạo bản ghi từ dict
course = Course.create({'name': "Odoo Developer Foundation", 'duration_hours': 24})

# Read: đọc field như thuộc tính
course.name            # 'Odoo Developer Foundation'
course.level           # 'beginner' (giá trị default)

# Search: lọc theo domain, danh sách các điều kiện
Course.search([('level', '=', 'beginner')])
Course.search_count([])          # đếm bản ghi
Course.browse(course.id)         # lấy theo id

# Update: gán trực tiếp hoặc write
course.duration_hours = 32
course.write({'is_published': True})

# Delete
course.unlink()

env.cr.commit()        # chỉ khi muốn lưu thật xuống database

Một vài điều đáng nhớ về cách dùng recordset:

  • Domain truyền vào search là danh sách các bộ ba (tên field, toán tử, giá trị); danh sách rỗng nghĩa là lấy tất cả. Có thể giới hạn bằng limit, offset và sắp xếp bằng order.
  • Truy cập field quan hệ luôn trả về recordset, rỗng nếu chưa có giá trị.
  • Muốn cộng dồn một field trên nhiều bản ghi, dùng mapped(), ví dụ sum(courses.mapped('duration_hours')).
  • Khi hàm của bạn chỉ chấp nhận một bản ghi, gọi self.ensure_one() ở đầu hàm để báo lỗi sớm nếu nhận nhiều bản ghi.
  • Odoo lưu cache và đọc trước (prefetch) dữ liệu để tránh truy vấn lặp, nên duyệt qua recordset thường nhanh hơn truy vấn từng bản ghi.

Tham số của search

Course.search([('is_published', '=', True)], order='start_date desc', limit=10, offset=20)

order là chuỗi sắp xếp, limit là số bản ghi tối đa trả về (mặc định là tất cả) và offset là số bản ghi bỏ qua (mặc định không bỏ qua), rất hữu ích để phân trang. Nếu người dùng không có quyền đọc, search ném AccessError. Đây là method cấp cao, không nên ghi đè; muốn đếm hãy dùng search_count().

Lỗi hay gặp khi mới học ORM

  • Thêm field vào code nhưng trên giao diện hoặc database vẫn chưa thấy. Với file Python, chỉ tải lại trình duyệt là không đủ: bạn cần khởi động lại server, và để ORM thêm cột mới vào bảng thì phải chạy với -d tên_db -u tên_module.
  • Đọc records.name trên recordset nhiều bản ghi. Với field không phải quan hệ, tài liệu cho biết việc này gây lỗi vì ORM không biết lấy giá trị của bản ghi nào. Hãy duyệt for record in records, hoặc dùng mapped('name') nếu bạn cần danh sách giá trị.
  • Đặt tên field trùng tên một method trong cùng class. Tài liệu cảnh báo cái khai báo sau sẽ ghi đè cái trước mà không có thông báo nào. Hãy đặt tên method bắt đầu bằng _compute_, action_... để tránh trùng.

Đừng dùng biến toàn cục có thể thay đổi

Một tiến trình Odoo có thể chạy nhiều database cùng lúc, mỗi database cài các module khác nhau. Vì vậy không nên lưu trạng thái trong biến global của Python, nó sẽ bị dùng chung giữa các database.

Tổng kết

  • Model là class kế thừa models.Model với _name bắt buộc; ORM sinh bảng tương ứng.
  • Field khai báo cột; thuộc tính như required, default, copy, index tinh chỉnh hành vi.
  • Mọi thao tác dữ liệu đi qua recordset: create, search, browse, write, unlink.
  • Sửa Python phải khởi động lại; thêm cột phải chạy -u với -d.

Câu hỏi thường gặp

Tên bảng trong PostgreSQL được đặt thế nào? ▾
Odoo lấy giá trị _name của model và đổi dấu chấm thành dấu gạch dưới. Ví dụ model vinc.course tạo bảng vinc_course.
Vì sao thêm field mới mà database chưa có cột? ▾
Bạn cần khởi động lại server và chạy với -d và -u kèm tên module để ORM áp dụng thay đổi cấu trúc. Chỉ lưu file Python hoặc tải lại trình duyệt là chưa đủ.
Trường id, create_date, write_date từ đâu ra? ▾
Đây là các trường tự động Odoo thêm vào mọi model: id, create_date, create_uid, write_date, write_uid. Bạn chỉ đọc được, không ghi được.
Dùng search hay browse khi truy vấn bản ghi? ▾
search lọc bản ghi theo một domain, còn browse lấy bản ghi theo danh sách id bạn đã biết. Cả hai đều trả về recordset.
