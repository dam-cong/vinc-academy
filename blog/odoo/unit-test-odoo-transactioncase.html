Unit test trong Odoo 20: TransactionCase, tag và Form

Test tự động giúp bạn nâng cấp Odoo và sửa code mà không lo vỡ quy tắc nghiệp vụ. Bài này hướng dẫn viết test Python với TransactionCase, kiểm tra onchange bằng Form, gắn tag và chạy bằng --test-tags.

Cập nhật: 16/10/2026 14 phút đọc Đội ngũ Vinc Academy

Tóm tắt nhanh

Odoo dùng thư viện unittest của Python. Bạn tạo gói tests/ trong module, đặt file tên test_*.py, import chúng trong tests/__init__.py, rồi viết class kế thừa TransactionCase với các method bắt đầu bằng test_. Chạy test bằng --test-tags /tên_module trên database đã cài module đó. Test không được import trong tests/__init__.py sẽ không chạy.

Odoo có những loại test nào?

Odoo hỗ trợ ba loại kiểm thử: test đơn vị Python (kiểm tra logic nghiệp vụ của model), test đơn vị JavaScript (kiểm tra riêng phần mã JS) và tour (mô phỏng tình huống thật, bảo đảm phần Python và JavaScript nói chuyện đúng với nhau). Bài này tập trung vào test Python, loại bạn sẽ viết nhiều nhất khi phát triển module.

Test là tấm lưới an toàn: khi nâng cấp phiên bản Odoo hoặc sửa một method, bộ test cho bạn biết ngay các quy tắc nghiệp vụ như computed field, constraint và quyền truy cập ở bài trước còn đúng hay không.

Cấu trúc thư mục test

Chỉ cần tạo gói con tests trong module, Odoo sẽ tự dò tìm các file test bên trong. File test phải có tên bắt đầu bằng test_ và được import trong tests/__init__.py:

vinc_course/
├── ...
└── tests/
    ├── __init__.py
    └── test_course.py

custom-addons/vinc_course/tests/__init__.py

from . import test_course

Viết test với TransactionCase

TransactionCase là lớp test dùng nhiều nhất. Mọi method test chạy trong cùng một transaction, mỗi method nằm trong một sub-transaction riêng (savepoint), và con trỏ database luôn bị đóng không commit. Nghĩa là dữ liệu test được dọn sạch tự động, không ảnh hưởng database. Dữ liệu dùng chung cho mọi method nên chuẩn bị một lần trong setUpClass:

custom-addons/vinc_course/tests/test_course.py

from odoo.exceptions import UserError, ValidationError
from odoo.tests import Form, TransactionCase, tagged


@tagged('post_install', '-at_install')
class TestVincCourse(TransactionCase):

    @classmethod
    def setUpClass(cls):
        super().setUpClass()
        cls.course = cls.env['vinc.course'].create({
            'name': "Odoo Foundation",
            'duration_hours': 20,
            'price': 2000,
        })

    def test_price_per_hour(self):
        self.assertEqual(self.course.price_per_hour, 100)

    def test_duration_must_be_positive(self):
        with self.assertRaises(ValidationError):
            self.course.duration_hours = 0

    def test_cannot_delete_published(self):
        self.course.is_published = True
        with self.assertRaises(UserError):
            self.course.unlink()

    def test_publish_sets_start_date(self):
        with Form(self.env['vinc.course']) as form:
            form.name = "Form course"
            form.is_published = True
        self.assertTrue(form.record.start_date)
  • Method test phải bắt đầu bằng test_.
  • Dùng các hàm assert* chuẩn của unittest như assertEqual, assertTrue, assertRaises.
  • self.env là môi trường ORM để tạo và tìm bản ghi; self.ref('module.xml_id') trả id theo external id, self.browse_ref(...) trả luôn bản ghi.
  • Mỗi method kết thúc sẽ dọn cache bản ghi và cache registry.

Kiểm tra onchange với Form

Lớp Form mô phỏng form view ở phía server: gọi các onchange khi tạo bản ghi và khi gán giá trị cho field, xử lý mặc định quanh các field x2many. Vì onchange chỉ chạy trong form (bài 8), đây là cách test chúng. Gán field trực tiếp lên form, dùng form như context manager để tự lưu khi thoát, và lấy bản ghi đã lưu qua form.record. Lưu ý save() báo AssertionError nếu còn field bắt buộc chưa điền.

Form với field nhiều-nhiều và một-nhiều

Lớp Form xử lý cả field quan hệ. Với Many2one, bạn gán thẳng một recordset. Với Many2many, field là một M2MProxy để thêm hoặc bớt bản ghi. Với One2many, vì danh sách này chỉ tồn tại thông qua bản ghi cha, bạn thao tác bằng các "form con" tạo bởi new() và edit(), thường dùng như context manager để form con được lưu vào bản ghi cha:

with Form(self.course) as form:
    form.tag_ids.add(self.tag)             # Many2many: thêm
    form.tag_ids.remove(id=self.old_tag.id)  # Many2many: bớt theo id
    with form.session_ids.new() as line:   # One2many: dòng mới
        line.name = "Buổi 1"
    with form.session_ids.edit(0) as line: # sửa dòng đầu tiên
        line.name = "Buổi mở đầu"
    form.session_ids.remove(index=0)       # xóa dòng đầu tiên

Hai quy tắc nên nhớ khi dùng Form: save() không lưu field chỉ đọc và field không bị sửa (bất kỳ phép gán hay onchange nào cũng đánh dấu field là đã sửa, kể cả khi gán đúng giá trị cũ); và nếu không có gì cần lưu thì save() chỉ trả về bản ghi hiện tại. Có thể truyền view (id, xmlid hoặc đối tượng view) để dùng đúng view cho onchange và ràng buộc của view; không truyền thì dùng form view mặc định của model.

Test giao diện và HTTP với HttpCase

Test Python thuần không chạm tới trình duyệt. Với những gì cần có HTTP hoặc JavaScript, Odoo cung cấp HttpCase: một test case có transaction, kèm hàm url_open để gọi URL và Chrome headless để chạy mã JavaScript. Loại thứ ba, tour, mô phỏng một tình huống thật nhằm bảo đảm phần Python và JavaScript nói chuyện đúng với nhau.

Hàm browser_js(url_path, code, ...) mở trang trong trình duyệt và chạy mã JavaScript. Các tham số hay dùng:

Tham sốÝ nghĩa
url_pathĐường dẫn trang cần mở
codeMã JavaScript cần chạy
readyĐối tượng JavaScript cần chờ sẵn sàng trước khi chạy tiếp
loginNgười dùng đăng nhập để chạy test, ví dụ 'admin'
timeoutThời gian chờ tối đa tính bằng giây, mặc định 60
success_signalChuỗi báo thành công khi gọi console.log(), mặc định "test successful"
error_checkerHàm lọc bớt các log lỗi cần bỏ qua; nếu không có, mọi log lỗi đều làm test thất bại
watch, debugMở cửa sổ trình duyệt để xem test chạy, hoặc mở Chrome toàn màn hình với devtools và breakpoint

Test báo thành công bằng cách ghi console.log() đúng chuỗi success_signal; báo thất bại bằng cách ném ngoại lệ hoặc gọi console.error kèm thông điệp. Với chế độ debug, tour được chạy với tham số debug=assets và dừng ngay tại ngoại lệ.

Chuẩn bị dữ liệu và dọn dẹp

  • Dữ liệu chung cho mọi method nên tạo một lần trong setUpClass; cách này phù hợp với bộ test gồm các test nhanh nhưng cần nhiều dữ liệu nền.
  • Sau mỗi method, Odoo dọn cache bản ghi và cache registry. Tuy nhiên các model và field trong registry thì không được dọn. Nếu test tạo model hoặc field tùy biến, hãy chuẩn bị bước dọn bằng self.env.transaction.will_change_registry().
  • Hai hàm tiện ích sẵn có: self.ref('module.xml_id') trả id, self.browse_ref('module.xml_id') trả bản ghi; cả hai báo ValueError nếu không tìm thấy external id. Phải viết đủ dạng module.identifier.

Ví dụ chọn test bằng tag

Theo mặc định, test kế thừa BaseCase được xem là standard. Bạn có thể loại một class khỏi bộ mặc định, rồi chỉ chạy nó khi cần:

@tagged('-standard', 'nice')
class TestNice(TransactionCase):
    ...

# chạy riêng test gắn tag nice
python3 odoo-bin -d odoo20_test --test-tags nice
# chạy cả nice lẫn standard (các giá trị cộng dồn)
python3 odoo-bin -d odoo20_test --test-tags nice,standard
# chạy standard nhưng bỏ slow
python3 odoo-bin -d odoo20_test --test-tags 'standard,-slow'

@tagged là decorator cho class, không có tác dụng khi gắn lên hàm hay method. Tiền tố - loại bỏ tag hoặc loại các test mang tag đó khỏi tập được chọn, kể cả khi chúng được chọn bởi một tag khác. Trong spec [-][tag][/module][:class][.method], nếu tên method không trùng với test nào khác, bạn có thể chỉ viết .ten_method; nhiều spec ngăn cách bằng dấu phẩy.

Tổng kết

  • Test Python nằm trong gói tests/, file test_*.py, phải được import trong tests/__init__.py.
  • TransactionCase dọn dữ liệu tự động; dùng setUpClass cho dữ liệu chung.
  • Form là cách test onchange và hành vi form, kể cả field x2many.
  • HttpCase và tour kiểm tra phần giao diện và sự phối hợp Python - JavaScript.
  • Chạy bằng --test-tags /module trên database đã cài module.

Bài cuối của series sẽ đưa mọi thứ lên môi trường thật: cấu hình production, Nginx, HTTPS và workers.

Gắn tag và chạy test

Tag giúp chọn test để chạy. Decorator @tagged() áp dụng lên class (không có tác dụng với hàm hoặc method). Tiền tố - bỏ một tag. Các tag đặc biệt:

TagÝ nghĩa
standardTest kế thừa BaseCase ngầm có tag này; --test-tags mặc định cũng là standard
post_installChạy sau khi mọi module đã được cài
at_installChạy ngay sau khi cài module, trước khi cài các module khác. Ít khi cần vì cản trở chạy song song; thường đi kèm -post_install

Cú pháp đầy đủ của --test-tags là [-][tag][/module][:class][.method]:

# cài module (hoặc -u) và chạy test của riêng vinc_course rồi dừng
python3 odoo-bin --addons-path=addons,../custom-addons \
    -d odoo20_test -i vinc_course --test-tags /vinc_course --stop-after-init

# chỉ một class hoặc một method
python3 odoo-bin -d odoo20_test --test-tags /vinc_course:TestVincCourse.test_price_per_hour

# mọi test standard trừ test gắn tag slow
python3 odoo-bin -d odoo20_test --test-tags 'standard,-slow'

Dùng --test-tags thì không cần thêm --test-enable. Hãy chạy test trên một database riêng (ví dụ odoo20_test) thay vì database làm việc hằng ngày.

Lỗi hay gặp khi mới viết test

  • Viết test xong nhưng không thấy chạy. Thường là file test chưa được import trong tests/__init__.py (tài liệu cảnh báo test không được import sẽ không chạy), method không bắt đầu bằng test_, hoặc dùng unittest.TestCase thuần mà không gắn tag standard/post_install nên không nằm trong bộ test mặc định.
  • Chạy --test-tags mà module chưa được cài trong database. Test chỉ chạy trên module đã cài. Với database mới, thêm -i tên_module ít nhất một lần; sau đó nếu sửa code, dùng -u.

Câu hỏi thường gặp

Test của tôi không chạy, nguyên nhân thường gặp là gì? ▾
Hay gặp nhất là file test chưa được import trong tests/__init__.py, tên method không bắt đầu bằng test_, hoặc dùng unittest.TestCase thuần mà không gắn tag standard và post_install.
TransactionCase hoạt động như thế nào? ▾
Mọi method test chạy trong một transaction, mỗi method trong một sub-transaction (savepoint), và con trỏ database luôn đóng mà không commit, nên dữ liệu test được dọn sạch tự động.
Làm sao chạy riêng test của một module? ▾
Dùng --test-tags /ten_module, ví dụ --test-tags /vinc_course. Có thể thu hẹp tới class hoặc method bằng cú pháp [-][tag][/module][:class][.method]. Module phải đã được cài trong database.
Khi nào dùng Form trong test? ▾
Khi cần kiểm tra onchange hoặc hành vi của form view phía server. Form gọi onchange khi tạo bản ghi và khi gán field, giống như người dùng thao tác trên giao diện.
