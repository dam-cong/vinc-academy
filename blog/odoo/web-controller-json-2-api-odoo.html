Web controller và JSON-2 API trong Odoo 20

Muốn Odoo nói chuyện với website, ứng dụng di động hay phần mềm khác thì cần endpoint. Bài này hướng dẫn viết controller với @route, và dùng API JSON-2 có sẵn với API key, quyền truy cập và transaction.

Cập nhật: 16/10/2026 16 phút đọc – lượt xem Đội ngũ Vinc Academy

Tóm tắt nhanh

Odoo có hai cách mở dữ liệu ra bên ngoài: tự viết controller với @route, hoặc dùng API JSON-2 có sẵn. Controller kế thừa http.Controller, mỗi route khai báo auth (public, user, bearer, none) và type (http hoặc jsonrpc). API JSON-2 nhận POST /json/2/<model>/<method> kèm API key trong header Authorization: bearer, và luôn tuân theo quyền truy cập của người dùng sở hữu key.

Web controller: tạo endpoint cho module

Model có sự kế thừa riêng, còn controller có cơ chế mở rộng riêng vì lúc request tới, database và các module có thể chưa sẵn sàng (chưa tạo hay chưa chọn database). Controller được tạo bằng cách kế thừa Controller, và các route được khai báo bằng method gắn decorator route().

Khung scaffold của bài 3 đã có thư mục controllers/. Tạo file controllers/main.py với endpoint trả về danh sách khóa học đã xuất bản dạng JSON:

custom-addons/vinc_course/controllers/main.py

from odoo import http
from odoo.http import request


class VincCourseController(http.Controller):

    @http.route('/vinc_course/courses', auth='public', type='http', methods=['GET'])
    def courses(self, **kw):
        courses = request.env['vinc.course'].sudo().search([('is_published', '=', True)])
        data = [{'id': c.id, 'name': c.name, 'level': c.level} for c in courses]
        return request.make_json_response(data)

Thay dòng import trong controllers/__init__.py bằng from . import main, nâng cấp module rồi mở http://localhost:8069/vinc_course/courses. Một vài điểm cần hiểu:

  • request là đối tượng yêu cầu hiện tại; request.env cho bạn môi trường ORM, request.make_json_response() serialize dữ liệu thành JSON và đặt Content-Type phù hợp, request.render() render một template QWeb.
  • Với người dùng public, request chạy bằng user Public dùng chung. Ở bài 5 ta chỉ cấp quyền cho nhóm nội bộ, nên ví dụ dùng sudo() một cách có chủ đích, chỉ lọc bản ghi đã xuất bản và chỉ trả các field an toàn. Đừng dùng sudo() tràn lan.

Các tùy chọn của @route

Tham sốÝ nghĩa
routeĐường dẫn mà method phục vụ; theo định dạng route của werkzeug
type'http' hoặc 'jsonrpc' (tên cũ 'json' tới Odoo 18); quy định nơi đọc tham số và cách serialize phản hồi
auth'user': bắt buộc đăng nhập; 'bearer': xác thực bằng API key trong header Authorization; 'public': có thể chưa đăng nhập (dùng user Public); 'none': luôn hoạt động kể cả khi không có database, chủ yếu cho framework
bearer_scopePhạm vi của token; bắt buộc đặt khi auth='bearer' và không được đặt với các kiểu xác thực khác
methodsDanh sách HTTP method được phép; không khai báo thì cho phép tất cả
csrfBảo vệ CSRF; mặc định bật với type='http', tắt với type='jsonrpc'
corsGiá trị header Access-Control-Allow-Origin

Route kiểu jsonrpc

Route type='jsonrpc' nói JSON-RPC 2 qua HTTP, với hai khác biệt so với đặc tả: thành viên method trong payload bị bỏ qua (đường dẫn HTTP đã đủ để chọn controller) và params bắt buộc là một đối tượng JSON theo tên chứ không phải mảng. Ngoài ra có thể truyền context thay thế context của session; tham số này bị bỏ trước khi gọi endpoint:

--> {"jsonrpc": "2.0", "method": "call", "params": {"arg1": "val1"}, "id": null}
<-- {"jsonrpc": "2.0", "result": {"res1": "val1"}, "id": null}

Mở rộng controller của module khác

Để ghi đè, kế thừa class controller gốc và định nghĩa lại method. Bắt buộc phải gắn lại @route() (có thể bỏ trống tham số), nếu không method sẽ bị "gỡ" khỏi danh sách route. Tham số của decorator mới được cộng dồn và ghi đè lên cái cũ:

class Restrict(VincCourseController):

    @http.route(auth='user')
    def courses(self, **kw):
        return super().courses(**kw)

Đoạn trên đổi route từ public sang user, tức yêu cầu đăng nhập.

API JSON-2: gọi model từ phần mềm bên ngoài

Ngoài controller tự viết, Odoo cung cấp sẵn một phần Models API qua HTTP với endpoint /json/2 (có từ Odoo 19). Bạn không cần viết thêm code trong module: chỉ cần gửi yêu cầu POST tới /json/2/<model>/<method>.

Điều kiện sử dụng

Theo tài liệu, quyền truy cập dữ liệu qua API ngoài chỉ có ở gói Custom của Odoo (Online); gói One App Free và Standard không hỗ trợ. Hãy kiểm tra gói của bạn trước khi thiết kế tích hợp.

Cấu trúc yêu cầu

PhầnNội dung
Header AuthorizationBắt buộc, bearer kèm API key
Header Content-TypeBắt buộc, application/json (nên kèm charset)
Header X-Odoo-DatabaseTùy chọn, tên database; cần khi một server chứa nhiều database mà dbfilter không dựa vào Host
Đường dẫnmodel là tên kỹ thuật của model, method là method cần chạy
Body JSONids (danh sách id; để trống nếu gọi method @api.model), context (tùy chọn) và các tham số của method

Ví dụ đọc các khóa học đã xuất bản bằng Python:

import requests

BASE_URL = "https://mycompany.example.com/json/2"
headers = {
    "Authorization": "bearer " + API_KEY,   # lấy key từ nơi lưu an toàn
    "X-Odoo-Database": "mycompany",
}
res = requests.post(
    f"{BASE_URL}/vinc.course/search_read",
    headers=headers,
    json={"domain": [["is_published", "=", True]], "fields": ["name", "level"]},
)
res.raise_for_status()
print(res.json())

Thành công trả về HTTP 200 và giá trị trả về của method dưới dạng JSON. Khi lỗi, server trả mã 4xx/5xx kèm đối tượng JSON gồm name, message, arguments, context và debug.

Tạo và quản lý API key

  • Tạo key trong tùy chọn người dùng, mục bảo mật tài khoản, bằng nút tạo key mới. Cần mô tả và thời hạn; key chỉ hiển thị một lần, hãy sao chép và lưu an toàn.
  • Thời hạn tối đa của key là ba tháng, nên key dùng lâu phải được thay mới ít nhất mỗi ba tháng. Với dùng tương tác nên đặt thời hạn ngắn, thường một ngày.
  • Khi xoay vòng key, tạo key mới trước, kiểm tra các dịch vụ đã dùng key mới rồi mới thu hồi key cũ.

Quản lý API key bằng lập trình

Odoo cung cấp phương thức RPC để sinh và thu hồi key. Mặc định chỉ người dùng có quyền quản trị Settings được làm việc này; muốn cho người khác, đặt tham số hệ thống base.enable_programmatic_api_keys là True (trong Settings → Technical → System Parameters).

  • res.users.apikeys.generate() nhận key (một key hợp lệ đang dùng), scope (chuỗi hoặc null), name (nhãn dễ đọc) và expiration_date (định dạng ISO 8601). Phương thức trả về key mới dưới dạng chuỗi và không thể lấy lại.
  • Phạm vi (scope) giới hạn nơi key được dùng. Phạm vi rpc là phạm vi chung cho RPC qua controller có auth='bearer'. Key không có phạm vi dùng null.
  • Mặc định một người dùng sinh tối đa 10 key bằng lập trình (đổi bằng base.programmatic_api_keys_limit); vượt giới hạn sẽ lỗi HTTP 422. Ngày hết hạn được kiểm tra theo thời hạn tối đa mà các vai trò của người dùng cho phép.
  • res.users.apikeys.revoke() thu hồi key ngay lập tức; sai key trả HTTP 403. Key bị thu hồi không nhất thiết phải trùng key trong header Authorization, nên khi xoay vòng, hãy xác thực bằng key mới để thu hồi key cũ.

Bảo mật và giao dịch

  • API tuân theo cơ chế bảo mật chuẩn: mọi thao tác được kiểm tra theo access rights, record rules và quyền theo field của người dùng sở hữu key (nội dung bài 5).
  • Khi tích hợp tự động lâu dài, nên tạo bot user riêng với quyền tối thiểu và để trống mật khẩu để tắt đăng nhập bằng mật khẩu.
  • Mỗi lệnh gọi chạy trong một transaction SQL riêng: thành công thì commit, lỗi thì hủy. Không thể gom nhiều lệnh gọi vào một transaction, nên các thao tác liên quan tới nhau cần được gói trong một method duy nhất trên server (thường đặt tên bắt đầu bằng action_).

Chuyển từ XML-RPC / JSON-RPC

Các endpoint /xmlrpc, /xmlrpc/2 và /jsonrpc đã bị đánh dấu lỗi thời. Dịch vụ db đã bị gỡ từ Odoo 20; các dịch vụ common và object dự kiến gỡ ở Odoo 22. Các controller @route(type='jsonrpc') tự viết không bị ảnh hưởng.

Lỗi hay gặp khi làm API

  • Gọi JSON-2 nhận 401 "Invalid apikey". Kiểm tra header phải có dạng Authorization: bearer <key>, key chưa hết hạn và chưa bị thu hồi. Nhớ rằng key chỉ hiện đúng một lần lúc tạo.
  • Ghi đè method của controller mà route biến mất. Bạn quên gắn lại @route(); không có decorator thì method bị "gỡ" khỏi danh sách route.
  • Gọi nhiều lệnh JSON-2 liên tiếp rồi dữ liệu không nhất quán. Mỗi lệnh là một transaction riêng nên có thể xen kẽ với người khác. Hãy gom các bước thành một method duy nhất trên model.

Tổng kết

  • Controller kế thừa http.Controller; @route khai báo auth, type, methods.
  • Khi ghi đè controller phải gắn lại @route().
  • JSON-2: POST /json/2/<model>/<method>, API key bearer, quyền của chủ key, mỗi lệnh một transaction.
  • Gói các thao tác liên quan vào một method duy nhất để giữ tính nhất quán.

Bài tiếp theo là test tự động để bảo vệ tất cả những gì bạn vừa viết.

Câu hỏi thường gặp

Khác nhau giữa type http và jsonrpc trong @route? ▾
Type quy định nơi đọc tham số yêu cầu và cách serialize phản hồi. Route type http mặc định bật bảo vệ CSRF, còn type jsonrpc (tên cũ là json đến Odoo 18) mặc định tắt.
auth public, user, bearer và none khác nhau thế nào? ▾
user bắt buộc đăng nhập; bearer xác thực bằng API key trong header Authorization; public cho phép chưa đăng nhập và chạy bằng user Public dùng chung; none luôn hoạt động kể cả khi chưa có database và chủ yếu dùng cho framework.
API JSON-2 gọi như thế nào? ▾
Gửi POST tới /json/2/<model>/<method> với header Authorization bearer kèm API key, Content-Type application/json và body JSON gồm ids, context cùng các tham số của method.
API key tạo ở đâu và dùng được bao lâu? ▾
Tạo trong phần tùy chọn người dùng, mục bảo mật tài khoản, bằng nút tạo key mới. Key chỉ hiện một lần và thời hạn tối đa là ba tháng, nên key dùng lâu phải được thay mới định kỳ.
