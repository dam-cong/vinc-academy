Tạo module Odoo 20 đầu tiên: cấu trúc, manifest và cài đặt

Mọi tính năng Odoo đều nằm trong module. Bài này giúp bạn sinh khung module bằng scaffold, hiểu vai trò từng file, viết manifest đúng chuẩn và biết cách cài, nâng cấp module khi phát triển.

Cập nhật: 16/10/2026 11 phút đọc – lượt xem Đội ngũ Vinc Academy

Tóm tắt nhanh

Một module Odoo 20 chỉ cần hai file: __init__.py và __manifest__.py, trong đó manifest chỉ bắt buộc khóa name. Lệnh odoo-bin scaffold sinh sẵn khung thư mục chuẩn. Đặt module vào addons-path, bật developer mode, chọn Update Apps List rồi cài; sau này sửa code thì nâng cấp bằng -u.

Module Odoo tối thiểu gồm những gì?

Mọi tính năng bạn viết cho Odoo đều nằm trong một module, tức một thư mục Python có kèm khai báo riêng cho Odoo. Điều kiện để Odoo nhận ra thư mục đó là module rất ít:

  • __init__.py: biến thư mục thành package Python. Lúc đầu có thể để trống, về sau nơi đây import các thư mục con như models.
  • __manifest__.py: một file chứa duy nhất một dictionary Python mô tả module. Khóa bắt buộc duy nhất là name, nhưng thực tế bạn nên khai báo nhiều hơn.

Có hai file này, đặt thư mục vào một đường dẫn trong addons-path, Odoo đã liệt kê được module, dù nó còn là cái vỏ rỗng chưa có chức năng gì.

Kiểm tra trước khi viết

Trước khi tự viết module mới, hãy chắc chắn Odoo (hoặc kho module cộng đồng) chưa có sẵn giải pháp cho bài toán đó. Viết lại thứ đã có là cách tốn công bảo trì nhất.

Sinh khung module bằng odoo-bin scaffold

Thay vì tạo từng file thủ công, hãy dùng lệnh scaffold. Nó nhận tên module (bắt buộc) và thư mục đích (mặc định là thư mục hiện tại). Trong loạt bài này, module ví dụ tên là vinc_course, dùng để quản lý khóa học:

cd ~/odoo-dev
python3 odoo/odoo-bin scaffold vinc_course custom-addons

Kết quả là thư mục custom-addons/vinc_course với cấu trúc mặc định:

vinc_course/
├── __init__.py
├── __manifest__.py
├── controllers/
│   ├── __init__.py
│   └── controllers.py
├── demo/
│   └── demo.xml
├── models/
│   ├── __init__.py
│   └── models.py
├── security/
│   └── ir.model.access.csv
└── views/
    ├── templates.xml
    └── views.xml

Lưu ý: phần lớn nội dung bên trong các file mẫu đang được comment, nên module vừa sinh ra là một khung gợi ý chứ chưa có tính năng nào. Bạn sẽ bỏ comment hoặc viết lại theo nhu cầu.

Vai trò của từng file và thư mục

Thành phầnVai tròHọc ở bài
__init__.py (gốc)Import controllers và models để Python nạp code của moduleBài này
__manifest__.pyKhai báo tên, phiên bản, phụ thuộc, danh sách file dữ liệuBài này
models/Class Python định nghĩa model và field, ánh xạ sang bảng PostgreSQLBài 4
security/ir.model.access.csvQuyền truy cập cho từng model theo nhóm người dùngBài 5
views/views.xmlKhai báo view, action và menu cho giao diện backendBài 6
views/templates.xmlTemplate QWeb, dùng cho trang web do controller trả vềBài 10, 12
controllers/Route HTTP của moduleBài 12
demo/demo.xmlDữ liệu mẫu, chỉ nạp khi database ở chế độ demoKhi cần

Hãy để ý một chi tiết của khung sinh ra: dòng security/ir.model.access.csv trong danh sách data của manifest đang bị comment. Khi bạn khai báo model đầu tiên, nhớ bỏ comment dòng này, nếu không file quyền sẽ không được nạp.

Các khóa quan trọng trong __manifest__.py

external_dependenciesdictThư viện Python (khóa python) hoặc chương trình (khóa bin) phải có sẵn trên máy, nếu thiếu thì module không cài được

Cách hiểu depends dễ nhất là so sánh với trình quản lý gói như apt: khi cài module của bạn, Odoo cài trước mọi module nó phụ thuộc; khi gỡ một module nền, mọi module phụ thuộc vào nó cũng bị gỡ theo. Riêng base luôn có trong mọi database, nhưng bạn vẫn nên ghi nó vào depends để module được nâng cấp mỗi khi base nâng cấp.

Về khóa version

Tài liệu Odoo chỉ yêu cầu theo semantic versioning. Vinc Academy khuyến nghị thêm tiền tố bản Odoo, ví dụ 20.0.1.0.0, để nhìn là biết module dành cho Odoo 20 và đang ở phiên bản nào. Đây là quy ước của chúng tôi, không phải ràng buộc của framework.

Thực hành: manifest cho vinc_course

Mở custom-addons/vinc_course/__manifest__.py, thay toàn bộ nội dung bằng bản gọn dưới đây. Chúng ta chưa có view hay model nên data tạm để trống:

custom-addons/vinc_course/__manifest__.py

{
    'name': "Vinc Course",
    'version': '20.0.1.0.0',
    'summary': "Quản lý khóa học và học viên",
    'author': "Vinc Academy",
    'website': "https://vinc-academy.vercel.app",
    'category': 'Education',
    'license': 'LGPL-3',
    'depends': ['base'],
    'data': [],
    'application': True,
}

Vì application là True, module sẽ hiện trong Apps ngay cả khi bộ lọc mặc định Apps đang bật. Nếu để False, bạn phải bỏ bộ lọc đó mới thấy module.

Thư mục controllers của khung sinh ra mà bạn chưa dùng có thể giữ nguyên. Nếu muốn module thật gọn, hãy xóa dòng from . import controllers trong __init__.py chứ đừng xóa thư mục trước, để tránh lỗi import.

Cài đặt và nâng cấp module

Cài từ giao diện

  1. Khởi động lại server để Odoo thấy file mới, với đường dẫn chứa custom-addons trong --addons-path.
  2. Bật developer mode (đã hướng dẫn ở bài 2). Không bật thì bạn sẽ không thấy nút cần dùng ở bước sau.
  3. Vào Apps, chọn Update Apps List, xác nhận.
  4. Tìm Vinc Course rồi bấm cài đặt.

Cài và nâng cấp bằng dòng lệnh

Khi phát triển hằng ngày, dòng lệnh nhanh hơn thao tác chuột. Cả hai tham số đều đi kèm -d (tên database):

# cài lần đầu
python3 odoo-bin --addons-path=addons,../custom-addons \
    -d odoo20_dev -i vinc_course

# sau khi sửa code hoặc file XML/CSV, nâng cấp module
python3 odoo-bin --addons-path=addons,../custom-addons \
    -d odoo20_dev -u vinc_course
Tham sốDùng khi
-i vinc_courseCài module lần đầu; nhiều module cách nhau bằng dấu phẩy
-u vinc_courseCập nhật module sau khi thay đổi; -u all cập nhật tất cả
--reinit vinc_courseNạp lại giống nâng cấp nhưng không chạy script nâng cấp, ảnh hưởng cả dữ liệu đánh dấu noupdate
--dev=xmlĐọc view trực tiếp từ file XML, đỡ phải nâng cấp khi chỉnh giao diện

Quy tắc nhớ nhanh: đổi code Python thì khởi động lại server (hoặc dùng --dev=reload); đổi file trong data thì nâng cấp module bằng -u. Đừng dùng --dev trên môi trường production.

Module không hiện hoặc không cài được?

Hiện tượngCần kiểm tra
Không thấy module trong AppsĐã bỏ bộ lọc Apps chưa (hoặc đặt application: True)? Đã bật developer mode và bấm Update Apps List chưa?
Không có nút Update Apps ListChưa bật developer mode
Odoo không tìm thấy thư mục moduleThư mục chứa module phải nằm trong --addons-path; có __init__.py và __manifest__.py ở thư mục gốc module
Sửa file trong data nhưng không có tác dụngChưa nâng cấp bằng -u
Module không cài do thiếu thư việnKiểm tra external_dependencies: thư viện Python hoặc chương trình khai báo ở đó phải có sẵn trên máy

Hai lỗi người mới hay vấp

  • Tạo file XML/CSV mới nhưng quên khai báo trong data. Chỉ những file có trong danh sách data mới được nạp khi cài hoặc nâng cấp. Thêm đường dẫn (tính từ thư mục gốc module, ví dụ views/course_views.xml) rồi nâng cấp bằng -u.
  • Dùng thư viện Python ngoài nhưng không khai báo. Hãy ghi tên thư viện vào external_dependencies; khi máy thiếu thư viện đó, Odoo sẽ không cài module và bạn biết ngay nguyên nhân thay vì lỗi muộn lúc chạy.

Câu hỏi thường gặp

Module Odoo cần tối thiểu những file nào? ▾
Hai file: __init__.py và __manifest__.py. Manifest chỉ bắt buộc khóa name, tuy nhiên nên khai báo thêm phiên bản, tác giả, phụ thuộc và danh sách file dữ liệu.
Vì sao module mới của tôi không hiện trong Apps? ▾
Có ba nguyên nhân hay gặp: đang bật bộ lọc Apps trong khi module chưa đặt application là True, chưa bật developer mode hoặc chưa bấm Update Apps List, hoặc thư mục module chưa nằm trong --addons-path.
Khác nhau giữa -i và -u khi chạy odoo-bin? ▾
-i cài module lần đầu, -u cập nhật module đã cài sau khi bạn sửa code hoặc file dữ liệu. Cả hai đều cần đi kèm -d để chỉ định database.
Có bắt buộc ghi base vào depends không? ▾
Odoo luôn cài sẵn base, nhưng tài liệu khuyến nghị vẫn khai báo nó trong depends để module được nâng cấp mỗi khi base được nâng cấp.
