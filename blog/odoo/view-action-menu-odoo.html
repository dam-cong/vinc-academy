View, action và menu trong Odoo 20: list, form, search

Giao diện Odoo được dựng từ các bản ghi XML. Bài này hướng dẫn bạn nối menu, action và view, thiết kế list, form, search view cho model khóa học, và hiểu domain để lọc dữ liệu.

Cập nhật: 16/10/2026 15 phút đọc – lượt xem Đội ngũ Vinc Academy

Tóm tắt nhanh

Giao diện Odoo được dựng từ các bản ghi XML theo chuỗi Menu → Action → View. Menu mở một action (ir.actions.act_window), action trỏ tới model và danh sách chế độ xem (list,form), mỗi chế độ là một view (ir.ui.view) có root <list>, <form> hoặc <search>. File XML phải được khai báo trong data của manifest, và chỉ nạp lại khi nâng cấp bằng -u.

Chuỗi Menu → Action → View

Ở bài 5 chúng ta đã nạp dữ liệu bằng CSV. Khi dữ liệu có cấu trúc phức tạp hơn, ví dụ cấu trúc một view, Odoo dùng file XML. File XML đặt cùng thư mục với CSV (file liên quan giao diện đặt trong views/), khai báo trong data giống nhau và cũng được nạp tuần tự theo thứ tự trong manifest.

Phần lớn giao diện Odoo được tạo bằng cách ghép các bản ghi XML với nhau theo mô hình quen thuộc:

  1. Menu: mục người dùng bấm vào.
  2. Action: cầu nối giữa menu và model, quyết định mở model nào, bằng những view nào.
  3. View: cách hiển thị các bản ghi (danh sách, form, tìm kiếm…).

Mẹo thực tế

Khi dữ liệu thuần túy và cần nạp nhanh, CSV được ưu tiên vì tốc độ nạp nhanh hơn XML. Với giao diện, XML là lựa chọn gần như duy nhất.

Action: nối menu với model

Action có thể được kích hoạt bằng ba cách: bấm vào menu, bấm nút trong view (nếu nút nối với action), hoặc là hành động ngữ cảnh trên bản ghi. Bài này chỉ dùng cách đầu tiên. Ví dụ action mở model vinc.course ở dạng danh sách và form:

custom-addons/vinc_course/views/vinc_course_views.xml

<odoo>
    <record id="vinc_course_action" model="ir.actions.act_window">
        <field name="name">Khóa học</field>
        <field name="res_model">vinc.course</field>
        <field name="view_mode">list,form</field>
    </record>
</odoo>
  • id: external id, dùng để tham chiếu bản ghi mà không cần biết id trong database.
  • model="ir.actions.act_window": loại action mở cửa sổ hiển thị bản ghi.
  • res_model: model mà action áp dụng.
  • view_mode: các chế độ xem được phép, cách nhau bởi dấu phẩy; mặc định là list,form.

Các loại action

Mọi action đều có hai thuộc tính bắt buộc: type (loại action, quyết định field nào dùng được và cách diễn giải) và name (mô tả ngắn cho người dùng). Action ra mắt dưới nhiều dạng, chẳng hạn bản ghi trong database hoặc từ điển do một method nút bấm trả về.

LoạiDùng để
Window (ir.actions.act_window)Loại phổ biến nhất: hiển thị một model qua các view
URL (ir.actions.act_url)Mở một địa chỉ web; target là new (mặc định, cửa sổ mới), self (thay nội dung hiện tại) hoặc download
Server (ir.actions.server)Chạy tự động (ví dụ qua action rule) hoặc thủ công từ menu ngữ cảnh
Report (ir.actions.report)In báo cáo; xem bài 10
Client (ir.actions.client)Hành động do phía client xử lý hoàn toàn, nhận diện bằng tag
Scheduled (ir.cron)Tự chạy theo tần suất định sẵn

Ngoài ra, action có thể gắn vào menu ngữ cảnh của một model bằng binding_model_id: binding_type là action (mặc định, menu Action) hoặc report (menu Print), và binding_view_types mặc định là list,form.

Chỉ định view cụ thể cho action

Với action window, view_mode là chuỗi các loại view cách nhau bởi dấu phẩy, không có khoảng trắng. Nếu muốn dùng một view cụ thể thay vì view mặc định, đặt view_id. Khi model có nhiều view và bạn muốn kiểm soát thứ tự, nên dùng bản ghi ir.actions.act_window.view thay cho view_ids:

<record id="vinc_course_action_list" model="ir.actions.act_window.view">
    <field name="sequence" eval="1"/>
    <field name="view_mode">list</field>
    <field name="view_id" ref="vinc_course_view_list"/>
    <field name="act_window_id" ref="vinc_course_action"/>
</record>

Phía server ghép danh sách view theo thứ tự: lấy từng cặp (id, loại) trong view_ids theo sequence; thêm view_id nếu loại của nó chưa có; rồi với mỗi loại còn thiếu trong view_mode thêm một mục không có id, để client lấy view mặc định. Loại đầu tiên trong danh sách là view mở ra đầu tiên.

Menu: ba cấp

Menu là bản ghi của model ir.ui.menu, nhưng ta dùng thẻ rút gọn <menuitem> cho gọn. Trong thực tế có ba cấp: menu gốc (hiện trong bộ chuyển ứng dụng), menu cấp một (hiện trên thanh trên cùng) và menu action. Cách dễ nhất là khai báo lồng nhau trong XML:

custom-addons/vinc_course/views/vinc_course_menus.xml

<odoo>
    <menuitem id="vinc_course_menu_root" name="Vinc Course">
        <menuitem id="vinc_course_menu_main" name="Khóa học">
            <menuitem id="vinc_course_menu_action" action="vinc_course_action"/>
        </menuitem>
    </menuitem>
</odoo>

Tên của menu cấp ba lấy từ tên của action. Khai báo hai file mới trong manifest, đặt file view chứa action trước file menu vì menu tham chiếu tới action:

'data': [
    'security/ir.model.access.csv',
    'views/vinc_course_views.xml',
    'views/vinc_course_menus.xml',
],

Chạy -u vinc_course, tải lại trình duyệt (web client lưu cache menu và view) rồi vào menu mới, bạn đã có thể tạo khóa học bằng view mặc định do Odoo sinh sẵn.

Tự thiết kế view: list, form, search

View là bản ghi của model ir.ui.view, thường nằm chung file XML với action và menu. Mỗi view có name, model và arch (cấu trúc XML của view). Thêm các bản ghi sau vào vinc_course_views.xml, bên trong thẻ <odoo>:

List view

Hiển thị bản ghi dạng bảng, root là <list>, mỗi field là một cột:

<record id="vinc_course_view_list" model="ir.ui.view">
    <field name="name">vinc.course.list</field>
    <field name="model">vinc.course</field>
    <field name="arch" type="xml">
        <list>
            <field name="name"/>
            <field name="level"/>
            <field name="start_date"/>
            <field name="duration_hours"/>
            <field name="price"/>
            <field name="is_published"/>
        </list>
    </field>
</record>

Form view

Dùng để tạo và sửa một bản ghi, root là <form>. Các phần tử cấu trúc là group và notebook; có thể dùng cả thẻ HTML như div, h1 và thuộc tính class:

<record id="vinc_course_view_form" model="ir.ui.view">
    <field name="name">vinc.course.form</field>
    <field name="model">vinc.course</field>
    <field name="arch" type="xml">
        <form>
            <sheet>
                <h1><field name="name"/></h1>
                <group>
                    <group>
                        <field name="level"/>
                        <field name="start_date"/>
                    </group>
                    <group>
                        <field name="duration_hours"/>
                        <field name="price"/>
                        <field name="is_published"/>
                    </group>
                </group>
                <notebook>
                    <page string="Mô tả">
                        <field name="description"/>
                    </page>
                </notebook>
            </sheet>
        </form>
    </field>
</record>

Search view

Khác với list và form, search view không hiển thị dữ liệu; nó lọc nội dung của các view khác. Root là <search>. Các field tạo ô tìm nhanh; filter là công tắc cho một lần tìm định sẵn, bắt buộc có domain (thêm điều kiện lọc) hoặc context (với khóa group_by để nhóm kết quả):

<record id="vinc_course_view_search" model="ir.ui.view">
    <field name="name">vinc.course.search</field>
    <field name="model">vinc.course</field>
    <field name="arch" type="xml">
        <search>
            <field name="name"/>
            <field name="level"/>
            <filter name="published" string="Đã xuất bản"
                    domain="[('is_published', '=', True)]"/>
            <filter name="group_level" string="Theo cấp độ"
                    context="{'group_by': 'level'}"/>
        </search>
    </field>
</record>

Domain: ngôn ngữ của điều kiện lọc

Domain là danh sách các tiêu chí chọn một tập con bản ghi. Mỗi tiêu chí là bộ ba (tên field, toán tử, giá trị). Mặc định các tiêu chí kết hợp bằng AND; muốn rõ ràng hơn, dùng các toán tử & (và), | (hoặc), ! (phủ định) đặt trước các toán hạng của chúng:

[('level', '=', 'beginner'), ('price', '>', 0)]

['|', ('level', '=', 'beginner'), ('is_published', '=', True)]

Trong XML, ký tự < và & không được viết trực tiếp. Hãy dùng &lt; và &amp;, ví dụ domain="[('price', '&lt;', 1000)]".

Còn kanban thì sao?

Kanban là view dạng bảng thẻ (card): mỗi bản ghi là một thẻ, có thể gom thành cột để theo dõi tiến độ công việc. Root là <kanban>, và Odoo chỉ mở mười cột đầu tiên, các cột sau được thu gọn cho tới khi người dùng mở ra. Cách dựng thẻ cần hiểu QWeb nên chúng ta để dành cho các bài sau; để dùng, bạn chỉ cần thêm kanban vào view_mode của action khi đã có view tương ứng.

Sửa view nhanh với --dev=xml

Mỗi lần sửa view mà phải khởi động lại server rất mất thời gian. Hãy chạy với tham số --dev=xml: sau khi sửa file XML, bạn chỉ cần tải lại trang để thấy thay đổi.

python3 odoo-bin --addons-path=addons,../custom-addons \
    -d odoo20_dev -u vinc_course --dev=xml

Field đặc biệt: active

Một vài tên field được dành riêng cho hành vi định sẵn. Điển hình là active: khi một bản ghi có active=False, nó tự động bị loại khỏi mọi kết quả tìm kiếm, và để thấy lại bạn phải tìm riêng các bản ghi không hoạt động. Nếu bạn thêm field này, hãy đặt mặc định default=True để bản ghi mới không biến mất.

Lỗi hay gặp khi mới viết view

  • Sao chép một view rồi quên đổi id. Mỗi view phải có external id riêng; khi copy-paste, luôn sửa id (và nên sửa cả name) để không ghi đè view cũ.
  • Viết < hoặc & thẳng trong domain của file XML. XML không cho phép hai ký tự này trong nội dung phần tử và thuộc tính; hãy đổi thành &lt; và &amp;.
  • Đã sửa file XML nhưng giao diện vẫn như cũ. Hãy chạy lại với -u (hoặc dùng --dev=xml) và tải lại trình duyệt, vì web client lưu cache menu và view.
  • Không thấy nút Tạo. Nếu người dùng chỉ có quyền đọc, nút này không hiện. Kiểm tra lại ir.model.access.csv ở bài 5.

Tổng kết

  • Giao diện Odoo: Menu mở Action, Action chọn Model và view_mode, mỗi chế độ là một View.
  • File XML phải khai báo trong data theo thứ tự (action trước menu) và nâng cấp bằng -u.
  • List, form, search là ba view cơ bản; search dùng filter với domain hoặc group_by.
  • Domain là danh sách điều kiện; trong XML nhớ escape &lt; và &amp;.

Bài tiếp theo kết nối các model với nhau bằng field quan hệ.

Câu hỏi thường gặp

Chuỗi Menu, Action, View hoạt động thế nào? ▾
Người dùng bấm menu, menu mở một action, action chỉ ra model và các chế độ xem như list và form, mỗi chế độ xem là một view. Action là cầu nối giữa menu và model.
Vì sao sửa file XML mà giao diện không đổi? ▾
File dữ liệu chỉ được nạp khi cài hoặc nâng cấp module, nên bạn cần chạy lại với -u. Trình duyệt cũng lưu cache menu và view, hãy tải lại trang. Có thể dùng --dev=xml để đỡ phải nâng cấp.
Domain trong Odoo là gì? ▾
Domain là danh sách các tiêu chí chọn một tập con bản ghi, mỗi tiêu chí là bộ ba gồm tên field, toán tử và giá trị. Các tiêu chí mặc định kết hợp bằng AND và có thể dùng các toán tử &, | và !.
Search view khác list view ở điểm nào? ▾
List view hiển thị bản ghi dạng bảng, còn search view không hiển thị dữ liệu mà dùng để lọc và nhóm nội dung của các view khác.
