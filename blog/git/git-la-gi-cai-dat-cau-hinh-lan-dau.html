Git là gì? Cài đặt và cấu hình lần đầu cho dev

Bài đầu của series Git: phân biệt Git với GitLab, cài đặt, khai báo tên và email, hiểu ba vùng làm việc rồi tạo repo và commit đầu tiên cho module vinc_course.

Cập nhật: 16/10/2026 9 phút đọc Đội ngũ Vinc Academy

Tóm tắt nhanh

Git là công cụ lưu lịch sử thay đổi của mã nguồn ngay trên máy bạn, còn GitLab hay GitHub là nơi cả nhóm chia sẻ và review. Bài này đưa bạn từ máy trống đến commit đầu tiên của repo vinc_course: cài Git, khai báo tên và email, tạo repo bằng git init, hiểu ba vùng (thư mục làm việc, staging, repo) và biết tự tra cứu bằng git help. Mọi lệnh trong bài đều đã chạy thật trên Git 2.47.

Git là gì và vì sao nhóm nào cũng dùng

Hãy hình dung module vinc_course của bạn đang có 20 file Python và XML. Hôm nay bạn sửa model, mai sửa view, tuần sau đồng nghiệp thêm báo cáo. Nếu chỉ dùng thư mục thường, bạn sẽ có những thứ như vinc_course_final, vinc_course_final_2 hay vinc_course_dung_that, và khi lỗi xuất hiện thì không ai biết ai đã đổi dòng nào. Git giải quyết đúng chỗ đó: nó chụp lại trạng thái của cả dự án mỗi khi bạn commit, kèm tên người sửa, thời điểm và lời nhắn giải thích.

Git là hệ thống quản lý phiên bản phân tán: mỗi máy giữ một bản sao đầy đủ của lịch sử, nên bạn xem log, so sánh hay tạo nhánh ngay cả khi không có mạng. Mạng chỉ cần khi bạn muốn đồng bộ với đồng nghiệp. Trong doanh nghiệp, điều này đi kèm một quy trình quen thuộc: mỗi người làm trên nhánh riêng, đẩy lên GitLab, mở merge request để đồng nghiệp xem lại rồi mới gộp vào nhánh chính. Cả quy trình đó sẽ được mở dần qua 12 bài của series; bài này đặt nền móng.

TênLà gìBạn dùng để

Điểm cần nhớ: Git không phụ thuộc GitLab. Bạn có thể dùng Git hoàn toàn trên máy, rồi sau này mới nối với GitLab hay GitHub. Series dùng GitLab vì nhiều doanh nghiệp tự dựng GitLab nội bộ cho code của khách hàng; mọi lệnh Git đều dùng được nguyên vẹn với GitHub.

Cài đặt Git

Cài một lần, dùng mãi. Theo trang tải về chính thức của Git, mỗi hệ điều hành có một cách quen thuộc:

Hệ điều hànhCách cài
WindowsTải Git for Windows từ git-scm.com, giữ các tùy chọn mặc định, dùng Git Bash hoặc terminal của VS Code
Ubuntu / Debiansudo apt install git
macOSbrew install git, hoặc chạy git lần đầu để hệ thống mời cài Xcode Command Line Tools

Sau khi cài, mở terminal và chạy git --version. Series này kiểm thử trên Git 2.47; các lệnh hiện đại như git switch và git restore có từ bản 2.23, nên bất kỳ bản 2.30 trở lên đều đủ dùng.

Cấu hình lần đầu: tên, email, nhánh mặc định

Mỗi commit ghi lại tác giả, nên việc đầu tiên là nói cho Git biết bạn là ai. Hãy dùng đúng email bạn đăng ký trên GitLab để commit được gắn vào tài khoản của bạn. Ba cài đặt khác cũng nên đặt ngay: nhánh mặc định của repo mới (main), và trình soạn thảo mà Git mở khi cần bạn gõ lời nhắn dài.

$ git --version
git version 2.47.3
$ git config --global user.name "Nguyễn Văn An"
$ git config --global user.email "an.nguyen@example.com"
$ git config --global init.defaultBranch main
$ git config --global core.editor "code --wait"
$ git config --global --list --show-origin
file:~/.gitconfig	user.name=Nguyễn Văn An
file:~/.gitconfig	user.email=an.nguyen@example.com
file:~/.gitconfig	init.defaultbranch=main
file:~/.gitconfig	core.editor=code --wait

Cờ --global lưu vào file .gitconfig trong thư mục home của bạn (kết quả trên cho thấy nguồn nhờ --show-origin). Git còn hai tầng nữa, tầng sau ghi đè tầng trước:

TầngCờLưu ởPhạm vi
system--systemFile cấu hình của hệ thốngMọi người dùng trên máy
global--global~/.gitconfigMọi repo của bạn
local--local (mặc định).git/configChỉ repo hiện tại

Tầng local rất hữu ích khi bạn dùng một máy cho cả dự án công ty lẫn dự án cá nhân: đặt email công ty ở global, rồi trong repo cá nhân chạy git config user.email "ban@example.com" (không cờ) để chỉ repo đó dùng email khác.

Ba vùng làm việc: hiểu một lần dùng cả đời

Hầu hết nhầm lẫn của người mới đều đến từ việc không phân biệt ba nơi mà file có thể nằm:

  • Thư mục làm việc là các file bạn thấy và sửa hằng ngày.
  • Staging (còn gọi là index) là “giỏ hàng” chứa những thay đổi bạn đã chọn cho lần commit kế tiếp, nhờ git add.
  • Repo cục bộ là lịch sử commit, nằm trong thư mục ẩn .git. Xóa .git là mất toàn bộ lịch sử, nên đừng nghịch thư mục này.

Tách staging khỏi commit nghe thừa, nhưng đó là lợi thế lớn: bạn có thể sửa năm file mà chỉ commit hai file liên quan, giữ mỗi commit làm đúng một việc. Vùng thứ tư, remote, chỉ xuất hiện khi bạn nối repo với GitLab ở bài 4.

Tạo repo đầu tiên cho vinc_course

git init biến một thư mục thành repo bằng cách tạo thư mục .git bên trong. git status là lệnh bạn sẽ gõ nhiều nhất: nó luôn cho biết bạn đang ở nhánh nào và cái gì đang chờ xử lý.

$ mkdir vinc_course
$ cd vinc_course
$ git init
Initialized empty Git repository in ~/work/vinc_course/.git/
$ git status
On branch main

No commits yet

nothing to commit (create/copy files and use "git add" to track)
$ ls -A
.git
$ cat .git/HEAD
ref: refs/heads/main

Tệp .git/HEAD cho biết nhánh hiện tại là main, đúng như ta đã đặt ở init.defaultBranch. Giờ thử vòng đời nhỏ nhất: tạo file, đưa vào staging, commit.

$ echo "# vinc_course" > README.md
$ git status -s
?? README.md
$ git add README.md
$ git status -s
A  README.md
$ git commit -m "Thêm README cho vinc_course"
[main (root-commit) dce25f0] Thêm README cho vinc_course
 1 file changed, 1 insertion(+)
 create mode 100644 README.md
$ git log --oneline
dce25f0 Thêm README cho vinc_course
$ git status
On branch main
nothing to commit, working tree clean

Hãy đọc kỹ hai lần git status -s: dấu ?? nghĩa là file chưa được theo dõi, còn A ở cột đầu nghĩa là file đã nằm trong staging. Mã băm như dce25f0 là định danh ngắn của commit; trên máy bạn nó sẽ khác vì phụ thuộc thời gian và tác giả.

Tự tra cứu khi quên lệnh

Không ai nhớ hết tùy chọn của Git, kể cả người dùng lâu năm. Có hai thói quen cứu bạn: git help <lệnh> (hoặc git <lệnh> --help) mở trang hướng dẫn đầy đủ, còn git <lệnh> -h in nhanh cú pháp ngay trong terminal. Gõ sai tên lệnh, Git còn gợi ý lệnh gần giống bằng thông báo “is not a git command”.

Muốn gõ ít hơn, bạn đặt alias cho lệnh hay dùng. Ví dụ dưới đây biến git st thành bản rút gọn của git status, rồi dùng git config --get và --show-origin để biết một giá trị đang lấy từ đâu:

$ git config --global alias.st "status -sb"
$ git st
## main
$ git config --get user.name
Nguyễn Văn An
$ git config --show-origin user.email
file:~/.gitconfig	an.nguyen@example.com

Lỗi hay gặp khi mới học

  • Commit bằng danh tính sai. Nếu chưa cấu hình, nhiều máy vẫn commit được vì Git tự đoán tên và email từ tài khoản máy, nhưng sẽ in cảnh báo “Your name and email address were configured automatically based on your username and hostname. Please check that they are accurate.” Đừng bỏ qua dòng này. Cách sửa commit vừa tạo là git commit --amend --reset-author sau khi đã đặt đúng user.name và user.email.
  • Gặp “Author identity unknown”. Khi Git không đoán được (hoặc bạn bật user.useConfigOnly để cấm đoán), commit bị từ chối với thông báo dưới đây. Chỉ cần chạy hai lệnh git config mà nó gợi ý.
$ git commit -m "Thêm README"
Author identity unknown

*** Please tell me who you are.

Run

  git config --global user.email "you@example.com"
  git config --global user.name "Your Name"

to set your account's default identity.
Omit --global to set the identity only in this repository.

fatal: no email was given and auto-detection is disabled
  • Tạo repo trong repo. Chạy git init bên trong một thư mục đã nằm trong repo khác sẽ tạo repo lồng nhau và làm git status khó hiểu. Hãy kiểm tra bằng git status trước khi init.

Tổng kết

  • Git lưu lịch sử ngay trên máy bạn; GitLab/GitHub chỉ là nơi chia sẻ và review.
  • Cấu hình một lần: user.name, user.email, init.defaultBranch; tầng local ghi đè global.
  • Ba vùng: thư mục làm việc → staging (git add) → repo (git commit); thêm remote khi đẩy lên GitLab.
  • git status luôn cho bạn biết bước tiếp theo; git help và -h giúp tự tra cứu.

Bạn đã có repo và commit đầu tiên. Bài tiếp theo đi vào vòng lặp hằng ngày: sửa file, xem khác biệt bằng git diff, chọn thứ cần commit, đọc git log và loại những file không bao giờ nên vào repo bằng .gitignore.

Câu hỏi thường gặp

Git và GitLab khác nhau thế nào? ▾
Git là chương trình cài trên máy bạn để lưu lịch sử thay đổi của mã nguồn. GitLab là dịch vụ lưu repo trên máy chủ cho cả nhóm, có thêm merge request, phân quyền và CI. Bạn dùng Git trọn vẹn mà không cần GitLab; GitHub là dịch vụ tương tự GitLab.
Có bắt buộc phải đặt user.name và user.email không? ▾
Mỗi commit ghi tên và email tác giả, nên nên đặt ngay. Nếu bạn chưa đặt, nhiều máy vẫn commit được vì Git tự đoán từ tài khoản máy và in cảnh báo; nếu bật user.useConfigOnly hoặc Git không đoán được, commit bị từ chối với thông báo Author identity unknown.
Nên dùng nhánh mặc định là main hay master? ▾
Cả hai đều chạy được; Git cho phép tự chọn bằng init.defaultBranch. Nhiều nhóm dùng main và GitLab cũng đặt main cho dự án mới, nên bạn đặt git config --global init.defaultBranch main để thống nhất với nhóm.
Staging area dùng để làm gì? ▾
Staging (index) là nơi bạn chọn những thay đổi sẽ vào commit kế tiếp bằng git add. Nhờ đó bạn sửa nhiều file nhưng chỉ commit những file liên quan nhau, giữ mỗi commit làm đúng một việc.
