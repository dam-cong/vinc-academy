Git hoàn tác: restore, reset, revert, reflog khi lỡ sai

Bài 7 chỉ cách chọn đúng lệnh hoàn tác Git: restore cho file, commit --amend, reset với ba cờ, revert cho commit đã push và reflog để cứu lại commit tưởng đã mất, chạy thật trên repo vinc_course.

Cập nhật: 16/10/2026 13 phút đọc Đội ngũ Vinc Academy

Tóm tắt nhanh

Mỗi loại sai lầm có một lệnh hoàn tác riêng; chọn đúng lệnh quan trọng hơn là nhớ nhiều lệnh. Sửa nhầm file: git restore. Lỡ git add: git restore --staged. Commit chưa push: git commit --amend hoặc git reset (--soft, mặc định --mixed, --hard). Commit đã push: git revert. Lỡ mất commit: git reflog. Bài này chạy từng lệnh trên repo vinc_course để bạn thấy chính xác cái gì mất, cái gì còn.

Chọn đúng lệnh theo “mình đang ở đâu”

Bí quyết là xác định sai lầm đang nằm ở vùng nào trong ba vùng của bài 1, rồi lùi từ vùng đó. Có thêm một câu hỏi quyết định: commit đã được push lên GitLab chưa? Commit chưa push chỉ nằm trên máy bạn nên sửa lịch sử thoải mái; commit đã push là của cả nhóm, và viết lại lịch sử sẽ gây rối cho người khác.

Hoàn tác thay đổi chưa commit: git restore

git restore <file> đưa file trong thư mục làm việc về đúng như trong staging (hoặc commit gần nhất nếu chưa staging). Hãy nhớ: thay đổi chưa commit mà bị restore thì không có cách nào cứu lại, vì Git chưa từng lưu nó. Còn git restore --staged chỉ rút file khỏi staging, thay đổi vẫn còn trong file nên hoàn toàn an toàn:

$ echo "# lỡ tay" >> models/course.py
$ git status -s
 M models/course.py
$ git restore models/course.py
$ git status -s
$ echo "# lỡ tay" >> models/course.py
$ git add models/course.py
$ git status -s
M  models/course.py
$ git restore --staged models/course.py
$ git status -s
 M models/course.py
$ git restore models/course.py

Muốn lấy lại một file từ commit cũ, thêm --source: git restore --source=HEAD~2 models/course.py đưa file về phiên bản cách đây hai commit (vẫn là thay đổi chưa commit để bạn xem rồi quyết định).

Sửa commit mới nhất: git commit --amend

Gõ sai message hay quên một file? Đừng tạo thêm commit “fix typo”. --amend thay commit mới nhất bằng một commit mới có nội dung đã chỉnh. Mã băm đổi (trong ví dụ 87e… thành mã khác), nghĩa là đây là commit khác; vì vậy chỉ nên amend khi chưa push:

$ echo "# vinc_course" > README.md
$ git add README.md
$ git commit -m "[ADD] vinc_corse: README"
[main 87e323f] [ADD] vinc_corse: README
 1 file changed, 1 insertion(+)
 create mode 100644 README.md
$ git commit --amend -m "[ADD] vinc_course: README"
[main f7f143d] [ADD] vinc_course: README
 Date: Mon Oct 12 11:20:00 2026 +0700
 1 file changed, 1 insertion(+)
 create mode 100644 README.md
$ echo "Module quản lý khóa học." >> README.md
$ git commit -qa --amend --no-edit
$ git log --oneline -n 2
b7b55df [ADD] vinc_course: README
47905cb [IMP] vinc_course: thêm trường số giờ
$ git show --stat --oneline HEAD
b7b55df [ADD] vinc_course: README
 README.md | 2 ++
 1 file changed, 2 insertions(+)

Bỏ commit chưa push: git reset

git reset <commit> di chuyển nhánh hiện tại về commit đó. Ba cờ quyết định phần còn lại (theo tài liệu): --soft giữ nguyên cả staging lẫn thư mục làm việc; --mixed (mặc định) cập nhật staging theo commit mới, giữ thư mục làm việc; --hard ghi đè cả thư mục làm việc. Thử với hai commit học phí và cấp độ:

CờHEAD / nhánhStagingThư mục làm việc
--softlùigiữgiữ
--mixedlùitheo commit mớigiữ
--hardlùitheo commit mớibị ghi đè
 
$ echo "    price = fields.Float(string='Học phí')" >> models/course.py
$ git commit -qam "[IMP] vinc_course: thêm học phí"
$ echo "    level = fields.Char(string='Cấp độ')" >> models/course.py
$ git commit -qam "[IMP] vinc_course: thêm cấp độ"
$ git reset --soft HEAD~1
$ git status -s
M  models/course.py
$ git log --oneline -n 2
907ebca [IMP] vinc_course: thêm học phí
b7b55df [ADD] vinc_course: README

--soft đưa thay đổi của commit bị bỏ trở lại staging (M ở cột trái), tiện khi bạn muốn gộp lại hoặc viết lại commit. Commit lại rồi thử --mixed: thay đổi chuyển thành chưa staging:

$ git commit -qm "[IMP] vinc_course: thêm cấp độ"
$ git reset HEAD~1
Unstaged changes after reset:
M	models/course.py
$ git status -s
 M models/course.py

Cuối cùng là --hard: vừa lùi nhánh vừa xóa thay đổi khỏi thư mục làm việc (grep đếm 0 vì dòng level đã biến mất):

$ git commit -qam "[IMP] vinc_course: thêm cấp độ"
$ git reset --hard HEAD~1
HEAD is now at 907ebca [IMP] vinc_course: thêm học phí
$ git status -sb
## main
$ grep -c level models/course.py
0

Cứu commit “đã mất”: git reflog

Commit vừa bị reset --hard thật ra chưa biến mất: Git ghi lại mọi lần HEAD di chuyển trong reflog. Chỉ cần tìm dòng HEAD@{n} trước khi sai và đưa nhánh về đó. Theo tài liệu git config, mục reflog được giữ mặc định 90 ngày (30 ngày cho mục không còn nối với nhánh nào), nên hãy cứu sớm:

$ git reflog -n 3
907ebca HEAD@{0}: reset: moving to HEAD~1
9f21257 HEAD@{1}: commit: [IMP] vinc_course: thêm cấp độ
907ebca HEAD@{2}: reset: moving to HEAD~1
$ git reset --hard HEAD@{1}
HEAD is now at 9f21257 [IMP] vinc_course: thêm cấp độ
$ grep -c level models/course.py
1
$ git log --oneline -n 2
9f21257 [IMP] vinc_course: thêm cấp độ
907ebca [IMP] vinc_course: thêm học phí

Hai cách đếm này hay bị nhầm. HEAD~1, HEAD~2 đếm lùi theo lịch sử commit của nhánh (cha, ông). HEAD@{1} đếm lùi theo reflog, tức là vị trí HEAD ở những lần di chuyển trước đó, kể cả những commit giờ không còn nằm trên nhánh. Vì vậy sau một lần reset --hard, HEAD~1 đưa bạn lùi tiếp, còn HEAD@{1} đưa bạn quay về chỗ cũ.

Đảo ngược commit đã push: git revert

Khi commit đã lên GitLab, đừng reset rồi ép push: người khác đã có commit đó. Hãy dùng git revert, lệnh tạo một commit mới làm điều ngược lại. Lịch sử giữ nguyên, ai kéo về cũng nhận được bản sửa:

$ git revert --no-edit HEAD
[main ddec0fc] Revert "[IMP] vinc_course: thêm cấp độ"
 Date: Mon Oct 12 14:08:00 2026 +0700
 1 file changed, 1 deletion(-)
$ git log --oneline -n 3
ddec0fc Revert "[IMP] vinc_course: thêm cấp độ"
9f21257 [IMP] vinc_course: thêm cấp độ
907ebca [IMP] vinc_course: thêm học phí
$ grep -c level models/course.py
0

Để revert một merge commit bạn phải chỉ rõ nhánh cha nào là “dòng chính” bằng -m 1 (tham số --mainline trong tài liệu), thường là phía main. Revert merge là cách xử lý chuẩn khi một merge request đã vào main mà gây lỗi trên môi trường thử.

Hai tình huống thường gặp khác

Commit nhầm lên main (nhắc ở bài 3). Giữ công việc bằng cách tạo nhánh tại commit hiện tại, rồi đưa main lùi lại. Cả hai cùng trỏ đúng thứ tự an toàn, không mất commit nào:

$ echo "    code = fields.Char(string='Mã')" >> models/course.py
$ git commit -qam "[IMP] vinc_course: thêm mã khóa (lẽ ra phải ở nhánh riêng)"
$ git branch feature/course-code
$ git reset --hard HEAD~1
HEAD is now at ddec0fc Revert "[IMP] vinc_course: thêm cấp độ"
$ git log --oneline --graph --all --decorate -n 4
* 7bfb9cd (feature/course-code) [IMP] vinc_course: thêm mã khóa (lẽ ra phải ở nhánh riêng)
* ddec0fc (HEAD -> main) Revert "[IMP] vinc_course: thêm cấp độ"
* 9f21257 [IMP] vinc_course: thêm cấp độ
* 907ebca [IMP] vinc_course: thêm học phí

Dọn file chưa theo dõi. git clean xóa file untracked; hãy luôn chạy -n (dry-run) trước để xem nó sẽ xóa gì, vì file đã xóa kiểu này không nằm trong reflog:

$ echo "x" > tam.txt
$ git clean -n
Would remove tam.txt
$ git clean -f
Removing tam.txt
$ git status -s

Lưới an toàn trước khi làm điều mạo hiểm

Reflog là lưới cuối cùng, nhưng có cách rẻ hơn để không phải dùng đến nó: trước khi chạy một lệnh bạn chưa chắc (reset --hard, rebase, clean), hãy tạo một nhánh sao lưu tại vị trí hiện tại. Nhánh chỉ là con trỏ nên tạo tức thì, và nếu mọi thứ ổn bạn xóa nó đi. Nếu hỏng, bạn đưa nhánh làm việc về lại đúng chỗ đã đánh dấu:

$ git branch backup/truoc-reset
$ git reset --hard HEAD~1
HEAD is now at 9f21257 [IMP] vinc_course: thêm cấp độ
$ git log --oneline -n 1
9f21257 [IMP] vinc_course: thêm cấp độ
$ git reset --hard backup/truoc-reset
HEAD is now at ddec0fc Revert "[IMP] vinc_course: thêm cấp độ"
$ git log --oneline -n 1
ddec0fc Revert "[IMP] vinc_course: thêm cấp độ"
$ git branch -d backup/truoc-reset
Deleted branch backup/truoc-reset (was ddec0fc).

Thói quen này đặc biệt đáng giá trong tuần phát hành, khi áp lực cao và bạn dễ gõ nhầm. Cùng với việc luôn đọc git status và git log --oneline trước khi hoàn tác, nó biến những lệnh “đáng sợ” thành thao tác thường nhật.

Lỗi hay gặp khi mới học

  • git reset --hard khi còn việc dang dở. Lệnh này xóa thay đổi chưa commit và reflog không cứu được vì Git chưa từng lưu chúng. Trong ví dụ dưới, dòng dang dở biến mất hoàn toàn, reflog chỉ ghi lần di chuyển HEAD, không có nội dung file:
$ echo "# việc dang dở" >> models/course.py
$ git reset --hard HEAD
HEAD is now at ddec0fc Revert "[IMP] vinc_course: thêm cấp độ"
$ grep -c dang models/course.py
0
$ git reflog -n 2
ddec0fc HEAD@{0}: reset: moving to HEAD
ddec0fc HEAD@{1}: reset: moving to HEAD~1
  • Amend hoặc reset commit đã push rồi ép push. Người khác đã kéo commit cũ nên lịch sử của họ lệch với remote và rất dễ mất công việc. Với commit đã push, hãy revert.
  • Nhầm restore với reset. restore thao tác trên file, reset di chuyển nhánh. Khi chỉ muốn hủy một file, đừng dùng reset --hard vì nó đụng tới mọi file.
  • Hoảng khi thấy “mất” commit. Hãy dừng lại, chạy git reflog và tìm mã băm; chừng nào còn trong reflog, bạn vẫn lấy lại được bằng git reset --hard <mã> hoặc git switch -c cứu <mã>.

Tổng kết

  • Chưa commit: restore (file) và restore --staged (staging).
  • Commit chưa push: --amend hoặc reset (--soft giữ staging, --mixed giữ file, --hard xóa hết).
  • Commit đã push: revert, đừng viết lại lịch sử chung.
  • Mất commit: git reflog (còn 90 ngày mặc định), nhưng không cứu được thay đổi chưa từng commit.

Bạn đã biết sửa sai an toàn. Bài tiếp theo là thao tác mà nhiều người e ngại nhưng nhóm nào cũng dùng: rebase để làm gọn lịch sử trước khi mở merge request, và quy tắc vàng để không bao giờ gây họa với nó.

Câu hỏi thường gặp

Khác nhau giữa git reset và git revert là gì? ▾
git reset di chuyển nhánh về một commit cũ, nên viết lại lịch sử và chỉ nên dùng khi chưa push. git revert thêm một commit mới làm điều ngược lại, giữ nguyên lịch sử, nên dùng cho commit đã push.
git reset --soft, --mixed và --hard khác nhau thế nào? ▾
Cả ba đều lùi nhánh. --soft giữ nguyên staging và thư mục làm việc; --mixed (mặc định) cập nhật staging theo commit mới nhưng giữ file; --hard ghi đè cả thư mục làm việc nên mất thay đổi chưa commit.
Lỡ git reset --hard thì lấy lại commit bằng cách nào? ▾
Chạy git reflog để tìm dòng HEAD@{n} trước khi reset rồi git reset --hard HEAD@{n} hoặc git switch -c tên-mới <mã>. Mục reflog được giữ mặc định 90 ngày, nhưng thay đổi chưa từng commit thì không cứu được.
Khi nào được dùng git commit --amend? ▾
Khi commit mới nhất chưa được push. Amend tạo ra commit khác (mã băm đổi), nên nếu đã push thì người khác đã có commit cũ và bạn sẽ phải ép push; trường hợp đó hãy dùng git revert hoặc commit sửa bổ sung.
