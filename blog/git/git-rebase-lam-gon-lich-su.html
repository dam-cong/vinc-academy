Git rebase: làm gọn lịch sử và quy tắc vàng cho nhóm

Bài 8 cho thấy rebase khác merge thế nào: cập nhật nhánh bằng git rebase main, gộp commit lẻ với rebase -i và autosquash, xử lý xung đột khi rebase và nắm quy tắc vàng: không rebase thứ đã chia sẻ.

Cập nhật: 16/10/2026 13 phút đọc – lượt xem Đội ngũ Vinc Academy

Tóm tắt nhanh

Rebase “viết lại” các commit của nhánh để chúng nối tiếp trên đỉnh mới nhất của nhánh khác, cho lịch sử thẳng và gọn. Bài này dùng git rebase main để cập nhật nhánh tính năng, git rebase -i để gộp commit lẻ (fixup, squash, reword), --autosquash để tự gộp commit sửa nhỏ, xử lý xung đột khi rebase (hai bên ours/theirs bị đảo) và nắm quy tắc vàng: không rebase commit đã chia sẻ. Mọi lệnh chạy thật trên repo vinc_course.

Rebase là gì và khác merge ở đâu

Ở bài 3 bạn thấy merge ghép hai nhánh bằng một merge commit, giữ nguyên lịch sử “đã rẽ rồi nhập lại”. rebase làm khác: nó lấy các commit riêng của nhánh bạn, tạm cất đi, đưa nhánh về đỉnh mới của nhánh đích rồi phát lại từng commit lên trên. Kết quả là lịch sử một đường thẳng như thể bạn bắt đầu làm việc từ đỉnh mới ngay từ đầu.

Điều cần ghi nhớ nhất: commit phát lại không còn là commit cũ. Nội dung thay đổi giống nhau nhưng cha khác, nên mã băm mới (F1', F2' trong sơ đồ). Đó là lý do rebase chỉ an toàn với commit chưa ai khác dựa vào.

Khi nào dùngGộp nhánh đã chia sẻ, giữ bằng chứng lịch sửLàm gọn nhánh riêng của bạn trước khi review

Cập nhật nhánh tính năng bằng rebase

Giả sử bạn làm nhánh học phí với ba commit lộn xộn (một “wip”, một “fix typo”) và đã push để sao lưu. Trong lúc đó main có thêm một commit README, nên nhánh của bạn lệch phía sau. Đồ thị cho thấy hai đường rẽ:

$ git switch -c feature/course-price
Switched to a new branch 'feature/course-price'
$ echo "    price = fields.Float(string='Học phí')" >> models/course.py
$ git commit -qam "[IMP] vinc_course: thêm trường học phí"
$ echo "# wip" >> models/course.py
$ git commit -qam "wip"
$ echo "# sửa lỗi gõ" >> models/course.py
$ git commit -qam "fix typo"
$ git push -q -u origin feature/course-price
$ git switch main
Your branch is up to date with 'origin/main'.
Switched to branch 'main'
$ echo "# vinc_course" > README.md
$ git add README.md
$ git commit -qm "[ADD] vinc_course: README"
$ git push -q
$ git switch feature/course-price
Your branch is up to date with 'origin/feature/course-price'.
Switched to branch 'feature/course-price'
$ git log --oneline --graph --all
* eeb11a2 [ADD] vinc_course: README
| * cffbf1a fix typo
| * 394aee0 wip
| * 4815c9b [IMP] vinc_course: thêm trường học phí
|/  
* 47905cb [IMP] vinc_course: thêm trường số giờ
* 847d6e3 [ADD] vinc_course: khung module và model vinc.course

Chạy git rebase main từ nhánh tính năng. Git phát lại từng commit lên sau commit README; đồ thị giờ là một đường thẳng và cả ba commit có mã băm mới:

$ git rebase main
Rebasing (1/3)
Rebasing (2/3)
Rebasing (3/3)
Successfully rebased and updated refs/heads/feature/course-price.
$ git log --oneline --graph
* 5ab820d fix typo
* de07295 wip
* 371e622 [IMP] vinc_course: thêm trường học phí
* eeb11a2 [ADD] vinc_course: README
* 47905cb [IMP] vinc_course: thêm trường số giờ
* 847d6e3 [ADD] vinc_course: khung module và model vinc.course

Một lưu ý thực tế: rebase không có xung đột về chữ vẫn có thể gây lỗi logic, vì code của bạn giờ chạy trên nền mới của đồng nghiệp. Hãy chạy lại test hoặc nâng cấp thử module (-u vinc_course) trước khi push.

Vì commit đã đổi mã băm mà bản trên GitLab vẫn là bản cũ, git push thường sẽ bị từ chối. Với nhánh riêng của bạn, cách đúng là --force-with-lease: nó ghi đè nhánh remote nhưng từ chối nếu remote có commit bạn chưa thấy, nên không đè nhầm công việc của người khác:

$ git push
To git@gitlab.example.com:vinc/vinc_course.git
 ! [rejected]        feature/course-price -> feature/course-price (non-fast-forward)
error: failed to push some refs to 'git@gitlab.example.com:vinc/vinc_course.git'
hint: Updates were rejected because the tip of your current branch is behind
hint: its remote counterpart. If you want to integrate the remote changes,
hint: use 'git pull' before pushing again.
hint: See the 'Note about fast-forwards' in 'git push --help' for details.
$ git push --force-with-lease
To git@gitlab.example.com:vinc/vinc_course.git
 + cffbf1a...5ab820d feature/course-price -> feature/course-price (forced update)

Gộp commit lẻ bằng rebase tương tác

Review dễ hơn khi nhánh kể một câu chuyện gọn. git rebase -i main mở một danh sách (trong editor) gồm các commit của nhánh, mỗi dòng bắt đầu bằng một lệnh. Bạn đổi chữ đầu dòng rồi lưu; Git thực hiện từ trên xuống:

LệnhTác dụng
pickGiữ commit như cũ
rewordGiữ nội dung, sửa lời nhắn
editDừng lại để bạn sửa nội dung commit
squashGộp vào commit trước, ghép cả hai lời nhắn
fixupGộp vào commit trước, bỏ lời nhắn của nó
dropBỏ hẳn commit

Các dòng bắt đầu bằng # editor: dưới đây là danh sách mà Git đã mở. Ta đổi pick ở dòng 2 và 3 thành fixup để “wip” và “fix typo” hòa vào commit đầu:

$ git rebase -i main
# editor: pick 371e622 [IMP] vinc_course: thêm trường học phí
# editor: pick de07295 wip
# editor: pick 5ab820d fix typo
Rebasing (2/3)
Rebasing (3/3)
Successfully rebased and updated refs/heads/feature/course-price.
$ git log --oneline --graph
* 16412cc [IMP] vinc_course: thêm trường học phí
* eeb11a2 [ADD] vinc_course: README
* 47905cb [IMP] vinc_course: thêm trường số giờ
* 847d6e3 [ADD] vinc_course: khung module và model vinc.course
$ git push --force-with-lease
To git@gitlab.example.com:vinc/vinc_course.git
 + 5ab820d...16412cc feature/course-price -> feature/course-price (forced update)

Ba commit thành một, và vì đã viết lại nên cần --force-with-lease khi push. Nếu bạn biết trước một commit nhỏ sửa cho commit nào, hãy tạo nó bằng git commit --fixup; sau đó rebase -i --autosquash tự đặt commit sửa vào đúng chỗ và đổi nó thành fixup (xem dòng cuối của danh sách):

$ echo "    level = fields.Char(string='Cấp độ')" >> models/course.py
$ git commit -qam "[IMP] vinc_course: thêm cấp độ"
$ echo "# thiếu dấu" >> models/course.py
$ git commit -q --fixup HEAD -a
$ git log --oneline -n 3
e12996a fixup! [IMP] vinc_course: thêm cấp độ
01b13bf [IMP] vinc_course: thêm cấp độ
16412cc [IMP] vinc_course: thêm trường học phí
$ git rebase -i --autosquash main
# editor: pick 16412cc [IMP] vinc_course: thêm trường học phí
# editor: pick 01b13bf [IMP] vinc_course: thêm cấp độ
# editor: fixup e12996a fixup! [IMP] vinc_course: thêm cấp độ
Rebasing (3/3)
Successfully rebased and updated refs/heads/feature/course-price.
$ git log --oneline -n 3
f5dc751 [IMP] vinc_course: thêm cấp độ
16412cc [IMP] vinc_course: thêm trường học phí
eeb11a2 [ADD] vinc_course: README

GitLab cũng có tùy chọn squash khi merge một merge request, nên nhiều nhóm không bắt buộc rebase tương tác. Dù vậy, biết tự làm gọn nhánh vẫn hữu ích vì bạn kiểm soát được lời nhắn của từng commit.

Xung đột khi rebase: bên “ours” và “theirs” bị đảo

Rebase phát lại từng commit nên xung đột có thể xảy ra ở từng bước. Cách xử lý giống bài 6, nhưng kết thúc bằng git rebase --continue thay vì git commit. Một điểm gây nhầm: theo tài liệu, khi rebase phía ours là chuỗi đã rebase tính từ nhánh đích, còn theirs là nhánh làm việc của bạn, tức hai bên bị đảo so với merge. Ví dụ: main đổi nhãn thành “Tổng số giờ”, nhánh của bạn đổi thành “Số giờ học”:

$ git rebase main
Auto-merging models/course.py
CONFLICT (content): Merge conflict in models/course.py
Rebasing (1/1)
error: could not apply 5f72b8e... [IMP] vinc_course: đổi nhãn số giờ học
hint: Resolve all conflicts manually, mark them as resolved with
hint: "git add/rm <conflicted_files>", then run "git rebase --continue".
hint: You can instead skip this commit: run "git rebase --skip".
hint: To abort and get back to the state before "git rebase", run "git rebase --abort".
hint: Disable this message with "git config advice.mergeConflict false"
Could not apply 5f72b8e... [IMP] vinc_course: đổi nhãn số giờ học
$ git status -sb
## HEAD (no branch)
UU models/course.py
$ grep -n -A5 "<<<<<<<" models/course.py
9:<<<<<<< HEAD
10-    hours = fields.Integer(string='Tổng số giờ')
11-=======
12-    hours = fields.Integer(string='Số giờ học')
13->>>>>>> 5f72b8e ([IMP] vinc_course: đổi nhãn số giờ học)

Phần sau HEAD là phiên bản của main (đích), phần dưới là commit của bạn đang được phát lại. Ta chọn nhãn kết hợp, rồi báo đã xử lý và cho rebase đi tiếp:

$ grep hours models/course.py
    hours = fields.Integer(string='Tổng số giờ học')
$ git add models/course.py
$ git rebase --continue
[detached HEAD aaf80fe] [IMP] vinc_course: đổi nhãn số giờ học
 1 file changed, 1 insertion(+), 1 deletion(-)
Successfully rebased and updated refs/heads/feature/hours-label.
$ git log --oneline --graph
* aaf80fe [IMP] vinc_course: đổi nhãn số giờ học
* fa3c870 [IMP] vinc_course: đổi nhãn tổng số giờ
* 47905cb [IMP] vinc_course: thêm trường số giờ
* 847d6e3 [ADD] vinc_course: khung module và model vinc.course

Nếu thấy rối, git rebase --abort trả nhánh về đúng như trước khi rebase; git rebase --skip bỏ qua commit đang gây xung đột.

git pull --rebase: kéo về mà không sinh merge commit

Ở bài 4, khi An có commit cục bộ còn Bình đã push, git pull --no-rebase tạo ra một merge commit tên “Merge branch 'main' of …” chỉ để nối hai đường. Nếu bạn muốn lịch sử thẳng, hãy dùng git pull --rebase: Git fetch rồi phát lại commit cục bộ của bạn lên trên commit mới của remote. Vì commit của bạn chưa push nên đây là cách rebase an toàn nhất:

$ echo "    price = fields.Float(string='Học phí')" >> models/course.py
$ git commit -qam "[IMP] vinc_course: thêm trường học phí"
$ git pull --rebase
From git@gitlab.example.com:vinc/vinc_course
   47905cb..4c7a4cb  main       -> origin/main
Rebasing (1/1)
Successfully rebased and updated refs/heads/main.
$ git log --oneline --graph
* b7faa54 [IMP] vinc_course: thêm trường học phí
* 4c7a4cb [ADD] vinc_course: README
* 47905cb [IMP] vinc_course: thêm trường số giờ
* 847d6e3 [ADD] vinc_course: khung module và model vinc.course
$ git push
To git@gitlab.example.com:vinc/vinc_course.git
   4c7a4cb..b7faa54  main -> main

Không có merge commit nào, và git push sau đó chạy suôn sẻ vì lịch sử của bạn giờ là hậu duệ trực tiếp của remote. Đây cũng là cấu hình mà nhóm chọn khi đặt pull.rebase true.

Quy tắc vàng: đừng rebase thứ đã chia sẻ

Tài liệu Git nói thẳng: rebase một nhánh mà người khác đã dựa vào là ý tồi, vì mọi người ở hạ nguồn buộc phải tự sửa lịch sử của họ. Quy tắc thực tế cho nhóm:

  • Rebase thoải mái nhánh tính năng riêng của bạn, trước khi hoặc trong lúc mở merge request.
  • Không rebase main, nhánh phát hành hay bất kỳ nhánh nào có người khác đang làm trên đó.
  • Đã rebase nhánh riêng thì push bằng --force-with-lease, không dùng --force trần.
  • Muốn git pull luôn rebase thay vì merge: đặt git config --global pull.rebase true (nhớ thống nhất với nhóm, như ở bài 4).

Lỗi hay gặp khi mới học

  • Push thường bị từ chối sau rebase. Đó là điều bình thường vì mã băm đã đổi (xem phần push ở trên). Dùng --force-with-lease trên nhánh riêng; nếu nhánh có người khác cùng làm thì dừng lại và trao đổi.
  • Rebase lên nhánh chung rồi ép push. Đồng nghiệp kéo về sẽ thấy các commit trùng lặp hoặc xung đột lạ. Nếu lỡ làm, báo ngay cho nhóm và dùng reflog (bài 7) để khôi phục trạng thái cũ.
  • Nhầm “ours” và “theirs”. Khi rebase, git restore --theirs lấy phiên bản của bạn, ngược với merge. Hãy đọc file kết quả thay vì tin vào tên cờ.
  • Quên mình đang giữa một rebase. git status sẽ ghi rebase in progress; hoàn tất bằng --continue hoặc thoát bằng --abort chứ đừng commit lung tung.

Tổng kết

  • Rebase phát lại commit của nhánh lên đỉnh mới, cho lịch sử thẳng; commit sau rebase có mã băm mới.
  • rebase -i với fixup/squash/reword/drop làm gọn nhánh; --autosquash lo các commit --fixup.
  • Xung đột khi rebase: sửa, git add, git rebase --continue; “ours” và “theirs” bị đảo.
  • Chỉ rebase nhánh riêng; push lại bằng --force-with-lease.

Bài tiếp theo giải quyết những tình huống “giữa chừng” của đời thực: đang dở tay thì có hotfix gấp (stash), cần mang đúng một commit sang nhánh khác (cherry-pick) và đánh dấu bản phát hành (tag).

Câu hỏi thường gặp

Rebase khác merge ở điểm nào? ▾
Merge ghép hai nhánh bằng một merge commit và giữ nguyên lịch sử đã rẽ. Rebase phát lại các commit của nhánh bạn lên đỉnh mới của nhánh đích, cho lịch sử thẳng nhưng các commit đó có mã băm mới.
Khi nào không nên dùng rebase? ▾
Không rebase những commit mà người khác đã dựa vào, như main hoặc nhánh chung. Tài liệu Git cảnh báo điều này buộc mọi người ở hạ nguồn phải tự sửa lịch sử của họ. Rebase thoải mái nhánh riêng của bạn.
Vì sao sau khi rebase tôi phải push --force-with-lease? ▾
Vì rebase đổi mã băm của các commit, bản trên remote không còn là tổ tiên của nhánh bạn nên push thường bị từ chối. --force-with-lease ghi đè nhưng từ chối nếu remote có commit bạn chưa thấy, an toàn hơn --force.
squash và fixup trong rebase -i khác nhau thế nào? ▾
Cả hai gộp commit vào commit đứng trước. squash giữ và ghép cả hai lời nhắn để bạn chỉnh; fixup bỏ lời nhắn của commit được gộp. Dùng fixup cho các commit sửa nhỏ như wip hay fix typo.
