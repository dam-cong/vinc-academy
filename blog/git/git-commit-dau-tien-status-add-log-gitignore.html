Git commit đầu tiên: status, add, diff, log và .gitignore

Bài 2 chạy vòng lặp Git hằng ngày trên module vinc_course: đọc git status, phân biệt git diff với --staged, viết commit gọn, xem lại bằng git log và loại file không nên vào repo bằng .gitignore.

Cập nhật: 16/10/2026 11 phút đọc – lượt xem Đội ngũ Vinc Academy

Tóm tắt nhanh

Hằng ngày bạn chỉ lặp một vòng: sửa file → git status → git diff → git add → git commit. Bài này chạy vòng đó trên module vinc_course: đọc ký hiệu của git status -s, phân biệt git diff với git diff --staged, viết commit theo quy ước [TAG] module: của Odoo, xem lại bằng git log/git show và dùng .gitignore để __pycache__, odoo.conf không lọt vào repo.

Vòng lặp hằng ngày trên module vinc_course

Giả sử bạn vừa dựng khung module với cấu trúc dưới đây (nội dung từng file như series Odoo). Repo đã git init nhưng chưa có commit nào, nên git status liệt kê mọi thứ là untracked: Git thấy file nhưng chưa theo dõi.

vinc_course/
├── __init__.py
├── __manifest__.py
└── models/
    ├── __init__.py
    └── course.py
from odoo import fields, models


class VincCourse(models.Model):
    _name = 'vinc.course'
    _description = 'Khóa học'

    name = fields.Char(required=True)

Dùng git add . để đưa tất cả vào staging rồi commit. Với lần đầu tiên thì như vậy là ổn, nhưng từ lần sau hãy tập thói quen xem git status trước khi add . để chắc không kéo theo file rác.

$ git status
On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
	__init__.py
	__manifest__.py
	models/

nothing added to commit but untracked files present (use "git add" to track)
$ git add .
$ git status -s
A  __init__.py
A  __manifest__.py
A  models/__init__.py
A  models/course.py
$ git commit -m "[ADD] vinc_course: khung module và model vinc.course"
[main (root-commit) a79a9aa] [ADD] vinc_course: khung module và model vinc.course
 4 files changed, 17 insertions(+)
 create mode 100644 __init__.py
 create mode 100644 __manifest__.py
 create mode 100644 models/__init__.py
 create mode 100644 models/course.py
$ git log --oneline
a79a9aa [ADD] vinc_course: khung module và model vinc.course

Dòng đầu của commit message ([ADD] vinc_course: ...) là thông lệ trong các repo Odoo; ta sẽ nói kỹ ở bài 10. Hiện tại chỉ cần nhớ: -m cho thông điệp một dòng, và mỗi commit nên làm đúng một việc.

Đọc git status -s như đọc bảng điểm

Bản đầy đủ của git status dễ đọc cho người mới, nhưng bản rút gọn -s (--short) nhanh hơn nhiều khi dự án lớn. Mỗi dòng có hai cột ký hiệu: cột trái là trạng thái trong staging, cột phải là trạng thái trong thư mục làm việc.

Hiển thịÝ nghĩaLàm gì tiếp
?? fileFile mới, Git chưa theo dõigit add nếu cần commit, hoặc thêm vào .gitignore
A  fileFile mới đã vào stagingSẵn sàng commit
 M fileĐã sửa trong thư mục làm việc, chưa staginggit diff để xem, git add để chọn
M  fileĐã sửa và đã stagingSẵn sàng commit
 D fileĐã xóa trong thư mục làm việcgit add hoặc git rm để ghi nhận việc xóa

Xem mình đã đổi gì: git diff và git diff --staged

Hai lệnh này hay bị nhầm. git diff (không cờ) so thư mục làm việc với staging, tức là những thay đổi chưa được add. git diff --staged (đồng nghĩa với --cached) so staging với commit gần nhất, tức là đúng thứ sẽ vào commit tiếp theo. Hãy thêm trường hours vào model và theo dõi:

$ echo "    hours = fields.Integer(string='Số giờ')" >> models/course.py
$ git status -s
 M models/course.py
$ git diff
diff --git a/models/course.py b/models/course.py
index 86951c7..781c9a6 100644
--- a/models/course.py
+++ b/models/course.py
@@ -6,3 +6,4 @@ class VincCourse(models.Model):
     _description = 'Khóa học'
 
     name = fields.Char(required=True)
+    hours = fields.Integer(string='Số giờ')
$ git add models/course.py
$ git status -s
M  models/course.py
$ git diff
$ git diff --staged
diff --git a/models/course.py b/models/course.py
index 86951c7..781c9a6 100644
--- a/models/course.py
+++ b/models/course.py
@@ -6,3 +6,4 @@ class VincCourse(models.Model):
     _description = 'Khóa học'
 
     name = fields.Char(required=True)
+    hours = fields.Integer(string='Số giờ')
$ git commit -m "[IMP] vinc_course: thêm trường số giờ"
[main ef00810] [IMP] vinc_course: thêm trường số giờ
 1 file changed, 1 insertion(+)

Cách đọc: dòng bắt đầu bằng + là dòng thêm, - là dòng xóa, dòng @@ cho biết vị trí trong file. Để ý lần git diff thứ hai không in gì: mọi thay đổi đã nằm trong staging nên không còn khác biệt giữa thư mục làm việc và staging. Thói quen tốt trước mỗi lần commit là chạy git diff --staged để tự review lần cuối, giống như đọc lại email trước khi gửi.

Đọc lại lịch sử: git log và git show

$ git log --stat --oneline
ef00810 [IMP] vinc_course: thêm trường số giờ
 models/course.py | 1 +
 1 file changed, 1 insertion(+)
a79a9aa [ADD] vinc_course: khung module và model vinc.course
 __init__.py        | 1 +
 __manifest__.py    | 7 +++++++
 models/__init__.py | 1 +
 models/course.py   | 8 ++++++++
 4 files changed, 17 insertions(+)
$ git show --stat HEAD
commit ef00810db8c3ba15ee2751bb6e570d7e13495d19
Author: Nguyễn Văn An <an.nguyen@example.com>
Date:   Mon Oct 12 11:06:00 2026 +0700

    [IMP] vinc_course: thêm trường số giờ

 models/course.py | 1 +
 1 file changed, 1 insertion(+)
$ git log --oneline -n 1
ef00810 [IMP] vinc_course: thêm trường số giờ

git log liệt kê commit từ mới đến cũ; --oneline rút mỗi commit còn một dòng, --stat thêm thống kê file đã đổi, -n 1 giới hạn số commit. git show in chi tiết một commit (mặc định là HEAD, commit mới nhất): tác giả, thời gian, lời nhắn và thay đổi.

LệnhTác dụng
git log --onelineMỗi commit một dòng: mã ngắn + tiêu đề
git log -p -- đường/dẫnXem thay đổi chi tiết của riêng một file
git log --author="An"Lọc theo tác giả
git log --since="1 week ago"Lọc theo thời gian
git show <mã>Chi tiết một commit bất kỳ

.gitignore: giữ file rác và file bí mật ngoài repo

Khi chạy Odoo, Python tự sinh thư mục __pycache__, server ghi file log, và bạn có thể có file cấu hình odoo.conf chứa admin_passwd. Không thứ nào nên nằm trong repo: rác làm lịch sử nhiễu, còn mật khẩu một khi đã lên GitLab thì nhiều người nhìn thấy. File .gitignore ở thư mục gốc repo liệt kê mẫu tên mà Git sẽ lờ đi:

$ git status -s
?? models/__pycache__/
?? odoo.conf
?? odoo.log
$ printf "__pycache__/\n*.pyc\n*.log\nodoo.conf\n.venv/\n" > .gitignore
$ git status -s
?? .gitignore
$ git check-ignore -v odoo.conf models/__pycache__/course.cpython-312.pyc
.gitignore:4:odoo.conf	odoo.conf
.gitignore:1:__pycache__/	models/__pycache__/course.cpython-312.pyc
$ git add .gitignore
$ git commit -m "[ADD] vinc_course: .gitignore"
[main e945725] [ADD] vinc_course: .gitignore
 1 file changed, 5 insertions(+)
 create mode 100644 .gitignore

git check-ignore -v cho biết file nào bị luật nào chặn (cột đầu là file:dòng:mẫu), rất tiện khi bạn không hiểu vì sao một file không hiện trong status. Nhớ commit cả chính .gitignore để cả nhóm dùng chung luật.

MẫuKhớp với
*.pycMọi file có đuôi .pyc
__pycache__/Thư mục tên __pycache__ (dấu / cuối chỉ khớp thư mục)
odoo.confFile tên đó ở mọi cấp thư mục
!keep.logDấu ! đảo ngược: không bỏ qua file này
# ghi chúDòng bắt đầu bằng # là chú thích

Gợi ý .gitignore cho dự án Odoo

MẫuVì sao nên bỏ qua
__pycache__/, *.pycBytecode Python tự sinh, khác nhau giữa máy
.venv/Môi trường ảo (bài 1 series Python): dựng lại được từ requirements.txt
odoo.conf, .envChứa mật khẩu và API key; commit file mẫu odoo.conf.example thay thế
*.logLog chạy server, lớn và đổi liên tục
.idea/, .vscode/Cấu hình riêng của editor mỗi người

Một commit tốt trông như thế nào

Git không ép bạn viết gì trong lời nhắn, nhưng sáu tháng sau chính bạn sẽ cảm ơn (hoặc trách) lời nhắn đó khi tìm vì sao một dòng code tồn tại. Hướng dẫn Git của Odoo gợi ý tiêu đề khoảng dưới 50 ký tự, mô tả lý do thay đổi chứ không chỉ liệt kê thao tác, và tránh những tiêu đề chung chung như “bugfix” hay “improvements”. Một vài so sánh trên module của chúng ta:

TránhNên viết
update[IMP] vinc_course: thêm trường số giờ cho khóa học
fix bug[FIX] vinc_course: không cho tạo hai khóa trùng mã
sửa nhiều thứTách thành từng commit, mỗi commit một việc

Quy tắc thực dụng: nếu bạn không thể mô tả commit trong một câu mà không dùng chữ “và”, rất có thể nó đang làm hai việc và nên tách bằng cách git add từng file. Khi cần viết nhiều dòng, bỏ cờ -m để Git mở trình soạn thảo bạn đã chọn ở bài 1 (core.editor): dòng đầu là tiêu đề, cách một dòng trống rồi tới phần mô tả.

Đổi tên và xóa file đúng cách

Git không lưu “đổi tên” như một thao tác riêng; nó so nội dung rồi tự nhận ra file đã được chuyển. Dù vậy dùng git mv và git rm giúp thay đổi vào staging ngay, đỡ một bước git add. Hướng dẫn của Odoo còn nhắc: khi chuyển file (tag [MOV]), đừng sửa nội dung cùng lúc, nếu không Git có thể mất dấu lịch sử của file.

$ git mv README.md README.rst
$ git status -s
R  README.md -> README.rst
$ git commit -m "[MOV] vinc_course: đổi README.md thành README.rst"
[main 2cf6824] [MOV] vinc_course: đổi README.md thành README.rst
 1 file changed, 0 insertions(+), 0 deletions(-)
 rename README.md => README.rst (100%)
$ git log --oneline --follow -- README.rst
2cf6824 [MOV] vinc_course: đổi README.md thành README.rst
a232969 [ADD] vinc_course: README

Ký hiệu R là rename. Cờ --follow của git log đi theo file qua lần đổi tên, nên bạn vẫn thấy lịch sử cũ của README.md.

Lỗi hay gặp khi mới học

  • Thêm .gitignore rồi mà file vẫn hiện M. .gitignore chỉ áp dụng cho file chưa được theo dõi; file đã commit từ trước vẫn bị theo dõi. Tài liệu gitignore hướng dẫn dùng git rm --cached để dừng theo dõi mà vẫn giữ file trên đĩa. Minh họa với odoo.conf lỡ commit từ đầu:
$ printf "odoo.conf\n" > .gitignore
$ echo "db_name = vinc" >> odoo.conf
$ git status -s
 M odoo.conf
?? .gitignore
$ git rm --cached odoo.conf
rm 'odoo.conf'
$ git add .gitignore
$ git status -s
A  .gitignore
D  odoo.conf
$ git commit -m "[FIX] vinc_course: bỏ odoo.conf khỏi repo"
[main 527fefc] [FIX] vinc_course: bỏ odoo.conf khỏi repo
 2 files changed, 1 insertion(+), 1 deletion(-)
 create mode 100644 .gitignore
 delete mode 100644 odoo.conf
$ git status -s
  • Mật khẩu đã commit thì xóa file chưa đủ. Commit xóa chỉ là một commit mới; nội dung cũ vẫn nằm trong lịch sử. Nếu bí mật đã được đẩy lên GitLab, hãy đổi mật khẩu/khóa đó ngay, rồi nhờ quản trị viên xử lý lịch sử.
  • git commit -a không lấy file mới. Cờ -a chỉ tự staging file đã theo dõi (đã sửa hoặc xóa); tài liệu nói rõ file chưa được Git biết đến không bị ảnh hưởng. Trong ví dụ, NOTE.md vẫn còn ?? sau commit:
$ echo "# ghi chú" > NOTE.md
$ echo "y = 2" >> models.py
$ git commit -am "[IMP] vinc_course: sửa models"
[main 264ae18] [IMP] vinc_course: sửa models
 1 file changed, 1 insertion(+)
$ git status -s
?? NOTE.md
  • git add . mà không nhìn status. Bạn dễ kéo cả file tạm, dump database hay ảnh chụp màn hình vào commit. Hãy git status -s trước, rồi git add đích danh từng file hoặc thư mục.

Tổng kết

  • Vòng lặp: sửa → status → diff → add → commit.
  • git diff xem thay đổi chưa staging; git diff --staged xem thứ sẽ vào commit.
  • git log --oneline và git show để đọc lịch sử.
  • .gitignore chỉ tác dụng với file chưa theo dõi; lỡ commit thì dùng git rm --cached.
  • Mật khẩu đã vào lịch sử thì phải đổi mật khẩu, không chỉ xóa file.

Bạn đã commit được trên một đường thẳng. Nhưng làm việc nhóm nghĩa là nhiều việc chạy song song: một người sửa model, người khác làm báo cáo. Bài tiếp theo giới thiệu nhánh để mỗi việc có đường đi riêng, rồi merge để gộp lại.

Câu hỏi thường gặp

git diff và git diff --staged khác nhau thế nào? ▾
git diff so thư mục làm việc với staging, tức những thay đổi chưa git add. git diff --staged (hay --cached) so staging với commit gần nhất, tức đúng nội dung sẽ vào commit tiếp theo.
Vì sao thêm .gitignore rồi mà file vẫn hiện trong git status? ▾
.gitignore chỉ áp dụng cho file chưa được Git theo dõi. Với file đã commit từ trước, hãy chạy git rm --cached tên_file rồi commit để dừng theo dõi mà vẫn giữ file trên đĩa.
git commit -a có thêm cả file mới không? ▾
Không. Cờ -a chỉ tự đưa vào staging các file đã được theo dõi và đã sửa hoặc xóa. File mới (hiện ?? trong git status -s) vẫn phải git add trước.
Nên commit file odoo.conf không? ▾
Không nên nếu file chứa mật khẩu như admin_passwd hay thông tin kết nối. Hãy đưa odoo.conf vào .gitignore và commit một file mẫu như odoo.conf.example không có bí mật.
