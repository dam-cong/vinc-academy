Git conflict: cách giải quyết xung đột khi merge

Bài 6 xử lý một xung đột thật trong __manifest__.py của vinc_course: đọc các dấu conflict, sửa tay, kiểm tra, git add và commit, biết khi nào dùng merge --abort và bật kiểu zdiff3 cho dễ đọc.

Cập nhật: 16/10/2026 11 phút đọc Đội ngũ Vinc Academy

Tóm tắt nhanh

Xung đột (conflict) xảy ra khi Git không thể tự quyết định giữ phiên bản nào, thường vì hai nhánh sửa cùng một dòng; đó không phải lỗi mà là Git hỏi ý bạn. Bài này xử lý một xung đột có thật ở __manifest__.py của vinc_course: đọc ba loại dấu <<<<<<<, =======, >>>>>>>, sửa tay, kiểm tra bằng py_compile và git diff --check, rồi git add và commit. Bạn cũng học cách git merge --abort để làm lại và bật kiểu hiển thị zdiff3 cho dễ đọc.

Xung đột là gì và khi nào xảy ra

Git gộp rất giỏi: nếu hai người sửa hai file khác nhau, hoặc cùng file nhưng ở hai vùng xa nhau, nó tự ghép mà không hỏi. Xung đột chỉ xuất hiện khi cả hai nhánh động vào cùng vùng dòng, hoặc một bên xóa file trong khi bên kia sửa nó. Lúc đó Git dừng việc merge giữa chừng, đánh dấu chỗ không chắc vào file và chờ bạn quyết định.

Trong module Odoo, vài chỗ “nóng” dễ xung đột vì mọi người cùng thêm vào một vị trí:

Chỗ hay xung độtVì sao
__manifest__.py → dataHai tính năng cùng thêm file vào danh sách; nếu cả danh sách nằm trên một dòng, hai thay đổi chạm đúng dòng đó
security/ir.model.access.csvMỗi model mới thêm một dòng ở cuối file nên hai nhánh cùng chèn vào một chỗ
View XML của cùng một modelHai người cùng sửa một khối <field>
File dịch .poĐược cập nhật hàng loạt nên nhiều nhánh cùng đổi các dòng giống nhau

Đọc các dấu đánh dấu xung đột

Hãy làm một xung đột thật. Nhánh feature/security khai báo file quyền truy cập, nhánh feature/views khai báo file view, và cả hai sửa dòng 'data': []. Merge nhánh đầu thì suôn sẻ (fast-forward) vì main chưa đổi gì; merge nhánh thứ hai thì đụng nhau:

$ git switch main
Switched to branch 'main'
$ git merge feature/security
Updating 47905cb..3c18c3d
Fast-forward
 __manifest__.py | 2 +-
 1 file changed, 1 insertion(+), 1 deletion(-)
$ git merge feature/views
Auto-merging __manifest__.py
CONFLICT (content): Merge conflict in __manifest__.py
Automatic merge failed; fix conflicts and then commit the result.
$ git status
On branch main
You have unmerged paths.
  (fix conflicts and run "git commit")
  (use "git merge --abort" to abort the merge)

Unmerged paths:
  (use "git add <file>..." to mark resolution)
	both modified:   __manifest__.py

no changes added to commit (use "git add" and/or "git commit -a")
$ git diff

git status liệt kê file ở mục Unmerged paths với nhãn both modified, và gợi ý luôn hai lối thoát (sửa rồi commit, hoặc --abort). Bên trong file, Git chèn ba loại dấu:

DấuÝ nghĩa
<<<<<<< HEADBắt đầu phần của nhánh bạn đang đứng (ở đây là main)
=======Ranh giới giữa hai phiên bản
>>>>>>> feature/viewsKết thúc phần của nhánh đang được gộp vào

Lệnh git diff trong lúc đang xung đột in một dạng khác thường (combined diff): mỗi dòng có hai cột ký hiệu, cột trái so với nhánh của bạn, cột phải so với nhánh được gộp vào. Bạn không cần thuộc cách đọc; chỉ cần biết dạng này cho thấy chính xác những dòng còn tranh chấp và sẽ ngắn lại khi bạn giải quyết xong.

Giải quyết từng bước

Quy trình luôn giống nhau, dù xung đột nhỏ hay lớn:

  • Mở file và tìm các dấu (hoặc dùng editor có giao diện merge, như VS Code với các nút Accept Current/Incoming/Both).
  • Quyết định kết quả cuối: giữ một bên, giữ cả hai, hoặc viết lại. Ở đây cả hai đều đúng nên ta giữ cả hai file trong danh sách.
  • Xóa hết dấu <<<<<<<, =======, >>>>>>> khỏi file.
  • Kiểm tra file còn chạy được (với Python: py_compile; với module Odoo: nâng cấp thử -u vinc_course).
  • git add file đó để báo “đã xử lý xong”, rồi git commit để hoàn tất merge.
$ cat __manifest__.py
{
    'name': 'Vinc Course',
    'version': '1.0',
    'depends': ['base'],
    'data': [
        'security/ir.model.access.csv',
        'views/course_views.xml',
    ],
    'license': 'LGPL-3',
}
$ python3 -m py_compile __manifest__.py && echo OK
OK
$ git add __manifest__.py
$ git status -s
M  __manifest__.py
$ git commit
[main 4fb4729] Merge branch 'feature/views'
$ git log --oneline --graph -n 5
*   4fb4729 Merge branch 'feature/views'
|\  
| * 250f5a1 [ADD] vinc_course: khai báo view
* | 3c18c3d [ADD] vinc_course: khai báo quyền truy cập
|/  
* 47905cb [IMP] vinc_course: thêm trường số giờ
* 847d6e3 [ADD] vinc_course: khung module và model vinc.course

Khi chạy git commit không có -m, Git mở trình soạn thảo với lời nhắn sẵn “Merge branch …”; bạn lưu và đóng là xong (trong ví dụ, editor được thay bằng lệnh rỗng nên không thấy). Theo quy ước Odoo, merge commit có thể gắn thẻ [MERGE].

Sợ quá thì hủy: git merge --abort

Bạn luôn có thể quay về trạng thái trước khi merge, miễn là chưa commit. git merge --abort đưa mọi thứ về như chưa từng chạy lệnh merge, và bạn có thể bắt đầu lại sau khi hỏi đồng nghiệp xem nên giữ phiên bản nào. Ví dụ dưới đây dùng một xung đột khác: hai nhánh cùng đổi nhãn trường hours.

$ git switch -c feature/hours-label
Switched to a new branch 'feature/hours-label'
$ sed -i "s/Số giờ/Số giờ học/" models/course.py
$ git commit -qam "[IMP] vinc_course: đổi nhãn số giờ"
$ git switch main
Switched to branch 'main'
$ sed -i "s/Số giờ/Tổng số giờ/" models/course.py
$ git commit -qam "[IMP] vinc_course: đổi nhãn tổng số giờ"
$ git merge feature/hours-label
Auto-merging models/course.py
CONFLICT (content): Merge conflict in models/course.py
Automatic merge failed; fix conflicts and then commit the result.
$ git merge --abort
$ git status -sb
## main

Khi chỉ cần lấy trọn một bên

Nếu quyết định là giữ nguyên phiên bản của một nhánh cho cả file, không cần sửa tay. git restore --theirs <file> lấy phiên bản của nhánh đang gộp vào, còn --ours lấy phiên bản của nhánh bạn đứng. Sau đó vẫn phải git add và commit. Hãy dùng thận trọng vì cách này bỏ toàn bộ thay đổi của bên còn lại trong file đó:

$ git merge feature/hours-label
Auto-merging models/course.py
CONFLICT (content): Merge conflict in models/course.py
Automatic merge failed; fix conflicts and then commit the result.
$ git restore --theirs models/course.py
$ grep hours models/course.py
    hours = fields.Integer(string='Số giờ học')
$ git add models/course.py
$ git commit -m "[MERGE] vinc_course: chọn nhãn số giờ học"
[main 45067cb] [MERGE] vinc_course: chọn nhãn số giờ học

Hiển thị dễ đọc hơn với zdiff3

Kiểu mặc định chỉ cho thấy hai phiên bản, nên đôi khi bạn không biết ban đầu dòng đó như thế nào. Tài liệu git config mô tả các kiểu diff3 và zdiff3 thêm vào phần gốc chung giữa hai nhánh (sau dấu |||||||), giúp bạn thấy mỗi bên đã đổi gì so với bản gốc. Bật bằng git config --global merge.conflictStyle zdiff3:

$ git config merge.conflictStyle zdiff3
$ git merge feature/hours-label
Auto-merging models/course.py
CONFLICT (content): Merge conflict in models/course.py
Automatic merge failed; fix conflicts and then commit the result.
$ grep -n -A8 "<<<<<<<" models/course.py
9:<<<<<<< HEAD
10-    hours = fields.Integer(string='Tổng số giờ')
11-||||||| 4fb4729
12-    hours = fields.Integer(string='Số giờ')
13-=======
14-    hours = fields.Integer(string='Số giờ học')
15->>>>>>> feature/hours-label
$ git merge --abort

Đọc kết quả trên: bản gốc là “Số giờ”, main đổi thành “Tổng số giờ”, nhánh kia đổi thành “Số giờ học”. Biết bản gốc, bạn nhanh chóng thấy hai bên đang cố nói cùng một ý khác từ ngữ, và chỉ cần chọn một cách gọi.

Ngoài việc sửa tay, bạn có thể dùng công cụ trực quan. Hầu hết editor hiện đại (VS Code, các IDE của JetBrains) hiển thị xung đột thành ba khung: bản của bạn, bản đến và kết quả, với nút chọn từng phần. Git còn có lệnh git mergetool mở công cụ hợp nhất mà bạn khai báo trong cấu hình merge.tool. Công cụ nào cũng chỉ giúp bạn chọn nhanh hơn; quyết định giữ gì vẫn là của bạn, nên hãy đọc kỹ kết quả cuối trước khi git add.

Xung đột kiểu một bên xóa, một bên sửa

Không phải xung đột nào cũng có dấu trong file. Khi một nhánh xóa file còn nhánh kia vẫn sửa nó, Git báo modify/delete và để nguyên phiên bản đã sửa trong thư mục làm việc. git status -s hiện cặp chữ UD (đã xóa ở phía được gộp vào). Bạn chọn: giữ file thì git add, bỏ file thì git rm, rồi commit:

$ git switch -c feature/rm-notes
Switched to a new branch 'feature/rm-notes'
$ git rm -q NOTES.md
$ git commit -qm "[REM] vinc_course: bỏ ghi chú"
$ git switch main
Switched to branch 'main'
$ echo "thêm một dòng" >> NOTES.md
$ git commit -qam "[IMP] vinc_course: bổ sung ghi chú"
$ git merge feature/rm-notes
CONFLICT (modify/delete): NOTES.md deleted in feature/rm-notes and modified in HEAD.  Version HEAD of NOTES.md left in tree.
Automatic merge failed; fix conflicts and then commit the result.
$ git status -s
UD NOTES.md
$ git rm -q NOTES.md
$ git commit -m "[MERGE] vinc_course: bỏ ghi chú"
[main bf19726] [MERGE] vinc_course: bỏ ghi chú

Giảm xung đột ngay từ cách làm việc

  • Kéo main về nhánh của bạn thường xuyên (bài 3) để xung đột nhỏ và xuất hiện sớm.
  • Merge request nhỏ, nhánh ngắn hạn (bài 5): ít thời gian để người khác chạm vào cùng chỗ.
  • Mỗi mục một dòng trong danh sách data hay depends: hai thay đổi ở hai vị trí khác nhau sẽ tự gộp, không đụng nhau như khi cả danh sách nằm trên một dòng.
  • Thông báo cho nhau khi cùng sửa một file lớn như view chính hay file dịch.

Lỗi hay gặp khi mới học

  • Để sót dấu xung đột trong file. Nếu bạn quên xóa dấu, file hỏng ngay. Với Python, trình biên dịch báo lỗi cú pháp ở đúng dòng dấu; git diff --check cũng cảnh báo leftover conflict marker trước khi bạn commit:
$ python3 -m py_compile __manifest__.py
  File "__manifest__.py", line 5
    <<<<<<< HEAD
    ^^
SyntaxError: invalid syntax
$ git diff --check
__manifest__.py:5: leftover conflict marker
__manifest__.py:7: leftover conflict marker
__manifest__.py:9: leftover conflict marker
$ git commit -m "merge"
U	__manifest__.py
error: Committing is not possible because you have unmerged files.
hint: Fix them up in the work tree, and then use 'git add/rm <file>'
hint: as appropriate to mark resolution and make a commit.
fatal: Exiting because of an unresolved conflict.
  • Ví dụ trên cũng cho thấy một lỗi thứ hai: gõ git commit khi chưa git add file đã sửa sẽ bị từ chối với “Committing is not possible because you have unmerged files”. Hãy git add để báo đã giải quyết.
  • Chọn bừa một bên cho nhanh. Mất thay đổi của đồng nghiệp là lỗi khó phát hiện nhất vì không có thông báo nào. Khi chưa chắc, hãy hỏi tác giả của commit bên kia (xem git log --merge hoặc git blame ở bài 12).
  • Hoảng và xóa cả repo. Bạn gần như không bao giờ cần làm vậy: git merge --abort đưa mọi thứ về lại, và dữ liệu đã commit luôn còn trong .git.

Tổng kết

  • Xung đột = hai bên sửa cùng dòng (hoặc sửa/xóa file); Git dừng và chờ bạn.
  • Dấu: <<<<<<< HEAD (bên bạn) · ======= · >>>>>>> nhánh (bên được gộp).
  • Sửa → xóa dấu → kiểm tra → git add → git commit; không chắc thì git merge --abort.
  • git diff --check bắt dấu sót; merge.conflictStyle zdiff3 cho thấy cả bản gốc.

Bạn đã biết xử lý khi mọi thứ va chạm. Còn khi chính bạn làm sai, lỡ sửa, lỡ commit hay lỡ đẩy? Bài 7 giới thiệu bộ công cụ hoàn tác: restore, reset, revert và reflog để cứu lại cả commit tưởng đã mất.

Câu hỏi thường gặp

Merge conflict là gì và có phải lỗi không? ▾
Không phải lỗi. Đó là lúc Git không tự quyết định được phiên bản nào đúng, thường vì hai nhánh sửa cùng dòng hoặc một bên xóa file bên kia sửa. Git dừng merge, đánh dấu chỗ tranh chấp và chờ bạn quyết định.
Làm sao hủy merge đang xung đột để làm lại? ▾
Chạy git merge --abort. Lệnh này đưa repo về trạng thái trước khi merge, miễn là bạn chưa commit kết quả merge.
Sao git commit báo unmerged files dù tôi đã sửa file? ▾
Vì bạn chưa git add file đã sửa. Git chỉ coi xung đột là đã giải quyết khi file được đưa vào staging bằng git add (hoặc git rm với file bị xóa).
Làm sao biết còn sót dấu xung đột trong code? ▾
Chạy git diff --check: Git cảnh báo leftover conflict marker kèm số dòng. Với file Python, py_compile hoặc việc chạy chương trình cũng báo lỗi cú pháp ở đúng dòng dấu.
