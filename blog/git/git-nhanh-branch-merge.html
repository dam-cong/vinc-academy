Git branch và merge: làm việc song song không lo đụng nhau

Bài 3 tạo nhánh cho từng tính năng của module vinc_course, gộp lại bằng git merge (fast-forward và merge commit), dọn nhánh xong việc và xử lý hai lỗi hay gặp: chuyển nhánh khi còn sửa dở và detached HEAD.

Cập nhật: 16/10/2026 11 phút đọc Đội ngũ Vinc Academy

Tóm tắt nhanh

Nhánh là một con trỏ nhẹ tới commit, nên tạo nhánh gần như tức thì và rẻ như xóa nhánh. Nhóm nào cũng quy định mỗi tính năng một nhánh, để việc dang dở của người này không làm hỏng việc của người kia. Bài này dùng git switch -c để tạo nhánh cho trường mới của vinc_course, gộp lại bằng git merge (fast-forward và merge commit), xóa nhánh xong việc và cách xử lý hai tình huống hay gặp: chuyển nhánh khi còn sửa dở và detached HEAD.

Nhánh là gì và vì sao mỗi việc một nhánh

Hãy tưởng tượng nhóm có ba việc đang chạy: thêm trường học phí, thêm cấp độ khóa học và sửa tài liệu. Nếu cả ba cùng commit lên một đường duy nhất, một việc dang dở sẽ lẫn vào các việc khác, và bạn không thể phát hành chỉ riêng việc đã xong. Git giải bằng nhánh: mỗi việc có một đường lịch sử riêng xuất phát từ cùng một điểm, và khi xong thì gộp (merge) lại vào nhánh chính.

Về kỹ thuật, nhánh chỉ là tên gắn với một commit. Khi bạn commit, tên nhánh hiện tại tự dịch chuyển sang commit mới. HEAD là con trỏ cho biết bạn đang đứng ở nhánh nào. Vì không có thư mục nào được sao chép, tạo nhánh mất chưa tới một giây dù repo lớn thế nào.

LệnhTác dụng
git branchLiệt kê nhánh cục bộ, dấu * là nhánh hiện tại
git branch -aLiệt kê cả nhánh remote (bài 4)
git switch <nhánh>Chuyển sang nhánh có sẵn
git switch -c <nhánh>Tạo nhánh mới từ vị trí hiện tại và chuyển sang đó
git merge <nhánh>Gộp nhánh đó vào nhánh hiện tại
git branch -d <nhánh>Xóa nhánh đã merge (an toàn)
git branch -m <mới>Đổi tên nhánh hiện tại

Bạn có thể tự nhìn thấy điều đó: file .git/HEAD chứa tên nhánh hiện tại, và git rev-parse cho biết commit mà tên nhánh đang trỏ tới.

$ cat .git/HEAD
ref: refs/heads/main
$ git rev-parse --short main
58544f6
$ git branch -v
* main 58544f6 Merge branch 'feature/course-code'

Từ Git 2.23 có hai lệnh git switch (chuyển nhánh) và git restore (khôi phục file) tách nhỏ vai trò của git checkout vốn làm quá nhiều việc. Các hướng dẫn cũ vẫn dùng git checkout và lệnh đó vẫn chạy, nhưng series này dùng lệnh mới vì tên gọi nói đúng việc làm.

Tạo nhánh và chuyển qua lại

Quy ước chung là đặt tên nhánh theo loại việc: feature/ cho tính năng, fix/ cho sửa lỗi. Ta tạo nhánh cho trường học phí, commit một thay đổi, rồi chuyển về main. Chú ý hai lần grep: nội dung file thật sự đổi theo nhánh bạn đang đứng.

$ git branch
* main
$ git switch -c feature/course-price
Switched to a new branch 'feature/course-price'
$ git branch
* feature/course-price
  main
$ echo "    price = fields.Float(string='Học phí')" >> models/course.py
$ git commit -am "[IMP] vinc_course: thêm trường học phí"
[feature/course-price 3d09a30] [IMP] vinc_course: thêm trường học phí
 1 file changed, 1 insertion(+)
$ git log --oneline --graph --all
* 3d09a30 [IMP] vinc_course: thêm trường học phí
* 47905cb [IMP] vinc_course: thêm trường số giờ
* 847d6e3 [ADD] vinc_course: khung module và model vinc.course
$ git switch main
Switched to branch 'main'
$ grep -c price models/course.py
0
$ git switch feature/course-price
Switched to branch 'feature/course-price'
$ grep -c price models/course.py
1

Đồ thị --graph cho thấy nhánh mới đi trước main đúng một commit. Việc cần làm tiếp là gộp nhánh vào main.

Hai mẹo nhỏ giúp thao tác nhanh hơn. Thứ nhất, git switch - quay về nhánh bạn vừa rời, tiện khi nhảy qua lại giữa hai nhánh. Thứ hai, git switch -c <tên> <điểm-bắt-đầu> cho phép tạo nhánh từ một commit hay nhánh khác thay vì từ vị trí hiện tại, như ví dụ main~2 ở phần sau. Nhớ rằng nhánh luôn bắt đầu từ chỗ bạn chỉ định, nên hãy chuyển về main đã cập nhật trước khi tạo nhánh tính năng mới.

Merge: fast-forward và merge commit

Lệnh git merge luôn chạy từ nhánh nhận thay đổi: bạn đứng ở main rồi gọi tên nhánh cần gộp. Có hai kết quả tùy hình dạng lịch sử. Nếu main không có commit nào mới kể từ lúc tách nhánh, Git chỉ cần đẩy con trỏ main tới trước: đó là fast-forward, không sinh commit mới.

$ git switch main
Switched to branch 'main'
$ git merge feature/course-price
Updating 47905cb..3d09a30
Fast-forward
 models/course.py | 1 +
 1 file changed, 1 insertion(+)
$ git log --oneline --graph
* 3d09a30 [IMP] vinc_course: thêm trường học phí
* 47905cb [IMP] vinc_course: thêm trường số giờ
* 847d6e3 [ADD] vinc_course: khung module và model vinc.course
$ git branch -d feature/course-price
Deleted branch feature/course-price (was 3d09a30).
$ git branch
* main

Tình huống thực tế hơn: trong lúc bạn làm nhánh cấp độ, đồng nghiệp đã commit thêm lên main. Hai đường lịch sử đã rẽ, nên Git tạo một merge commit có hai commit cha để nối chúng lại. Sơ đồ ở đầu bài chính là tình huống này.

$ git switch -c feature/course-level
Switched to a new branch 'feature/course-level'
$ echo "    level = fields.Selection([('basic', 'Cơ bản'), ('adv', 'Nâng cao')])" >> models/course.py
$ git commit -am "[IMP] vinc_course: thêm trường cấp độ"
[feature/course-level 82624ed] [IMP] vinc_course: thêm trường cấp độ
 1 file changed, 1 insertion(+)
$ git switch main
Switched to branch 'main'
$ echo "# vinc_course" > README.md
$ git add README.md
$ git commit -m "[ADD] vinc_course: README"
[main e26c754] [ADD] vinc_course: README
 1 file changed, 1 insertion(+)
 create mode 100644 README.md
$ git merge feature/course-level
Merge made by the 'ort' strategy.
 models/course.py | 1 +
 1 file changed, 1 insertion(+)
$ git log --oneline --graph
*   f2e2ab5 Merge branch 'feature/course-level'
|\  
| * 82624ed [IMP] vinc_course: thêm trường cấp độ
* | e26c754 [ADD] vinc_course: README
|/  
* 3d09a30 [IMP] vinc_course: thêm trường học phí
* 47905cb [IMP] vinc_course: thêm trường số giờ
* 847d6e3 [ADD] vinc_course: khung module và model vinc.course
$ git branch --merged
  feature/course-level
* main
$ git branch -d feature/course-level
Deleted branch feature/course-level (was 82624ed).

Hãy đọc đồ thị: ngôi sao thứ hai bên trái là commit README trên main, nhánh bên phải là commit cấp độ, và dòng trên cùng là merge commit nối cả hai. Vì hai thay đổi nằm ở file khác nhau (hoặc khác dòng), Git tự gộp được; khi chúng đụng cùng một dòng sẽ có xung đột, chủ đề của bài 6. git branch --merged liệt kê nhánh đã nằm gọn trong nhánh hiện tại, tức là an toàn để xóa.

Nhiều nhóm muốn luôn có merge commit để lịch sử ghi lại “tính năng này được gộp lúc nào”, kể cả khi fast-forward được. Cờ --no-ff làm đúng việc đó:

$ git switch -c feature/course-code
Switched to a new branch 'feature/course-code'
$ echo "    code = fields.Char(string='Mã khóa')" >> models/course.py
$ git commit -am "[IMP] vinc_course: thêm mã khóa học"
[feature/course-code 303f5c8] [IMP] vinc_course: thêm mã khóa học
 1 file changed, 1 insertion(+)
$ git switch main
Switched to branch 'main'
$ git merge --no-ff feature/course-code
Merge made by the 'ort' strategy.
 models/course.py | 1 +
 1 file changed, 1 insertion(+)
$ git log --oneline --graph -n 4
*   58544f6 Merge branch 'feature/course-code'
|\  
| * 303f5c8 [IMP] vinc_course: thêm mã khóa học
|/  
*   f2e2ab5 Merge branch 'feature/course-level'
|\  
| * 82624ed [IMP] vinc_course: thêm trường cấp độ
$ git branch -d feature/course-code
Deleted branch feature/course-code (was 303f5c8).

Dọn nhánh sau khi xong việc

Nhánh đã merge không còn giá trị, nên xóa để danh sách gọn. git branch -d chỉ xóa nhánh đã được merge và từ chối nếu bạn sẽ mất commit. Muốn bỏ hẳn một thử nghiệm, dùng -D (viết hoa) để ép xóa, nhưng hãy chắc chắn rằng bạn không cần các commit đó nữa.

$ git switch -c experiment/video
Switched to a new branch 'experiment/video'
$ echo "# thử video" >> README.md
$ git commit -am "[IMP] vinc_course: thử nhúng video"
[experiment/video 9a15432] [IMP] vinc_course: thử nhúng video
 1 file changed, 1 insertion(+)
$ git switch main
Switched to branch 'main'
$ git branch -d experiment/video
error: the branch 'experiment/video' is not fully merged
hint: If you are sure you want to delete it, run 'git branch -D experiment/video'
hint: Disable this message with "git config advice.forceDeleteBranch false"
$ git branch -D experiment/video
Deleted branch experiment/video (was 9a15432).

Thói quen giữ nhánh gọn gàng

  • Nhánh ngắn hạn. Nhánh sống càng lâu càng lệch xa main, nên việc merge càng đau. Chia việc để nhánh sống vài ngày, không phải vài tuần.
  • Một nhánh một mục đích. Đừng gom “thêm trường học phí” và “sửa báo cáo” vào cùng nhánh; khi cần hoàn tác hay review sẽ khó tách.
  • Không commit trực tiếp lên main. Hầu hết nhóm bảo vệ nhánh chính và chỉ cho gộp qua merge request (bài 5).
  • Cập nhật từ main thường xuyên. Khi main có thay đổi mới, kéo chúng vào nhánh của bạn để phát hiện xung đột sớm:
$ git switch -c feature/course-sync main~2
Switched to a new branch 'feature/course-sync'
$ echo "ghi chú đồng bộ" > SYNC.md
$ git add SYNC.md
$ git commit -m "[ADD] vinc_course: ghi chú đồng bộ"
[feature/course-sync e6ebc3c] [ADD] vinc_course: ghi chú đồng bộ
 1 file changed, 1 insertion(+)
 create mode 100644 SYNC.md
$ git merge main
Merge made by the 'ort' strategy.
 models/course.py | 2 ++
 1 file changed, 2 insertions(+)
$ git log --oneline --graph -n 1
*   fd027f5 Merge branch 'main' into feature/course-sync
|\  
$ git switch main
Switched to branch 'main'
$ git branch -D feature/course-sync
Deleted branch feature/course-sync (was fd027f5).

Lần này git merge main được chạy từ nhánh tính năng, nghĩa là nhánh tính năng là bên nhận. Cách này không đụng gì tới main, nên an toàn. Bài 8 sẽ cho thấy lựa chọn khác là rebase.

Với module tùy biến cho khách hàng, nhiều nhóm giữ một nhánh ổn định cho mỗi phiên bản Odoo mà khách đang chạy (ví dụ 20.0) và tách nhánh tính năng từ đó. Chi tiết chiến lược nhánh nằm ở bài 10.

Lỗi hay gặp khi mới học

  • Chuyển nhánh khi còn sửa dở. Nếu file bạn sửa khác nhau giữa hai nhánh, Git từ chối để bảo vệ công việc của bạn:
$ git switch -c feature/x
Switched to a new branch 'feature/x'
$ echo "    x = fields.Char()" >> models/course.py
$ git commit -qam "[IMP] vinc_course: thêm trường x"
$ git switch main
Switched to branch 'main'
$ echo "    y = fields.Char()" >> models/course.py
$ git switch feature/x
error: Your local changes to the following files would be overwritten by checkout:
	models/course.py
Please commit your changes or stash them before you switch branches.
Aborting
  • Có ba lối thoát: commit tạm, git stash (bài 9), hoặc bỏ thay đổi bằng git restore (bài 7). Đừng ép chuyển bằng cờ -f khi chưa hiểu nó vứt gì.
  • Rơi vào “detached HEAD”. Gõ git checkout <commit> hay git switch --detach đưa HEAD tới một commit không thuộc nhánh nào. Commit tạo ra lúc này dễ bị “lạc”. Muốn giữ, hãy git switch -c <tên-nhánh>; muốn quay lại, git switch -:
$ git stash -q
$ git checkout HEAD~1 2>&1 | head -5
Note: switching to 'HEAD~1'.

You are in 'detached HEAD' state. You can look around, make experimental
changes and commit them, and you can discard any commits you make in this
state without impacting any branches by switching back to a branch.
$ git switch -
Previous HEAD position was 847d6e3 [ADD] vinc_course: khung module và model vinc.course
Switched to branch 'feature/course-price'
  • Tên nhánh có dấu cách. Tên nhánh không được chứa khoảng trắng; hãy nối bằng dấu gạch ngang (và dùng chữ thường không dấu để dễ gõ trong terminal):
$ git switch -c "feature/course price"
fatal: 'feature/course price' is not a valid branch name
hint: See `man git check-ref-format`
hint: Disable this message with "git config advice.refSyntax false"
$ git switch -c feature/course-price
Switched to a new branch 'feature/course-price'
  • Commit nhầm lên main. Quên tạo nhánh rồi commit thẳng lên main là lỗi phổ biến; hãy nhìn dấu * của git branch hoặc dòng đầu của git status trước khi commit. Cách cứu nằm ở bài 7.

Tổng kết

  • Nhánh là con trỏ nhẹ; mỗi việc một nhánh, đặt tên feature/..., fix/....
  • git switch -c tạo và chuyển nhánh; nội dung file đổi theo nhánh.
  • git merge chạy từ nhánh nhận: fast-forward khi lịch sử thẳng, merge commit khi đã rẽ; --no-ff ép luôn có merge commit.
  • -d xóa nhánh đã merge, -D ép xóa.
  • Còn sửa dở thì commit hoặc stash trước khi đổi nhánh.

Tất cả mới diễn ra trên máy bạn. Bài tiếp theo nối repo với GitLab: clone, fetch, pull, push, và tạo SSH key để không phải gõ mật khẩu mỗi lần.

Câu hỏi thường gặp

Git branch là gì, nó có sao chép code không? ▾
Nhánh chỉ là một cái tên trỏ tới một commit, không sao chép file. Khi bạn commit, tên nhánh hiện tại tự dịch sang commit mới. Vì vậy tạo hay xóa nhánh gần như tức thì.
Fast-forward và merge commit khác nhau thế nào? ▾
Fast-forward xảy ra khi nhánh nhận không có commit mới: Git chỉ đẩy con trỏ nhánh tới trước và không tạo commit. Nếu hai nhánh đã rẽ, Git tạo một merge commit có hai commit cha. Cờ --no-ff buộc luôn tạo merge commit.
git switch khác git checkout ra sao? ▾
git switch (từ Git 2.23) chỉ làm việc chuyển và tạo nhánh; git restore làm việc khôi phục file. Cả hai tách ra từ git checkout vốn đảm nhiệm quá nhiều việc. git checkout vẫn chạy bình thường.
Khi nào dùng git branch -D thay vì -d? ▾
-d chỉ xóa nhánh đã được merge và từ chối nếu bạn sẽ mất commit. -D ép xóa bất kể trạng thái merge, dùng khi bạn chắc chắn muốn bỏ hẳn nhánh thử nghiệm.
