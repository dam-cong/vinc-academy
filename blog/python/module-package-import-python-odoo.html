Python module, package và import: hiểu __init__.py của Odoo

Mỗi lần bạn thêm model hay controller vào module Odoo, bạn lại phải sửa một file __init__.py. Bài này giải thích module, package, import tương đối và cách Python tìm mã, để bạn hiểu vì sao thiếu một dòng import là model biến mất.

Cập nhật: 16/10/2026 13 phút đọc Đội ngũ Vinc Academy

Tóm tắt nhanh

Một file .py là một module, một thư mục có __init__.py là một package. Bạn dùng import để lấy code từ module khác. Với module Odoo, __init__.py ở thư mục gốc và ở models/ chính là chuỗi import đưa file model vào hệ thống: thiếu một dòng from . import course là model không tồn tại. Python tìm module theo sys.path, và file có dòng if __name__ == "__main__": vừa chạy được trực tiếp vừa import được.

Module: một file Python là một thư viện nhỏ

Bất kỳ file .py nào cũng có thể được nạp bởi file khác. Có ba cách viết lệnh import:

import math                         # nạp cả module, dùng math.sqrt(...)
import math as m                    # đặt bí danh
from math import sqrt, pi           # lấy tên cụ thể

print(math.sqrt(16), m.sqrt(25), sqrt(9), round(pi, 2))
# 4.0 5.0 3.0 3.14
  • import math nạp cả module; bạn gọi qua tên module (math.sqrt), rất rõ nguồn gốc.
  • import math as m đặt tên ngắn; hay gặp ở thư viện dài tên.
  • from math import sqrt lấy trực tiếp một tên vào chỗ dùng; ngắn nhưng dễ gây trùng tên nếu import nhiều.

Thư viện chuẩn có hàng trăm module sẵn (math, json, datetime, csv, re...), và bạn sẽ dùng nhiều ở các bài sau. Thư viện bên ngoài (như requests) cài bằng pip như bài 1 rồi import theo cách tương tự.

Package: thư mục chứa nhiều module

Khi dự án lớn dần, bạn gom các file liên quan vào một thư mục và thêm file __init__.py để Python coi nó là package. Đó là cách bạn tổ chức một công cụ nhỏ cho dự án khóa học:

vinc-tools/
├── main.py
└── vinc_tools/
    ├── __init__.py
    ├── courses.py
    └── report.py
# vinc_tools/courses.py
PREFIX = "ODO"

def make_code(seq):
    return f"{PREFIX}-{seq:03d}"

if __name__ == "__main__":
    print("chạy trực tiếp:", make_code(1))
# vinc_tools/__init__.py
from .courses import make_code
# vinc_tools/report.py
from . import courses
from .courses import make_code as mk

def line(seq):
    return courses.PREFIX + ":" + mk(seq)
# main.py (cùng cấp với thư mục vinc_tools)
import vinc_tools
from vinc_tools import report
from vinc_tools.courses import PREFIX
import vinc_tools.courses as vc

print(vinc_tools.make_code(7), report.line(2), PREFIX, vc.PREFIX)
print(__name__)
$ python3 main.py
ODO-007 ODO:ODO-002 ODO ODO
__main__

$ python3 vinc_tools/courses.py
chạy trực tiếp: ODO-001
  • from .courses import make_code trong __init__.py là import tương đối: dấu chấm nghĩa là "trong cùng package này". Nhờ đó người dùng gọi được vinc_tools.make_code thay vì phải biết nó nằm trong file nào.
  • from . import courses nạp module courses của cùng package, còn from .courses import make_code as mk lấy một tên và đổi tên.
  • __init__.py chạy một lần ngay khi package được nạp.

Khối if __name__ == "__main__"

Mỗi module có biến __name__. Khi file được chạy trực tiếp bằng python file.py, __name__ bằng "__main__"; khi nó được import, __name__ là tên module. Khối if __name__ == "__main__": vì vậy chỉ chạy khi bạn chạy file như script, rất hợp để đặt đoạn thử nhanh hoặc điểm vào của chương trình (bạn sẽ dùng ở bài 14). Hãy so sánh kết quả của hai lệnh trong ví dụ trên: main.py in __main__, còn khi import vinc_tools.courses, dòng "chạy trực tiếp" không xuất hiện.

Python tìm module ở đâu?

Khi gặp import x, Python tìm lần lượt trong danh sách sys.path: thư mục chứa script đang chạy (hoặc thư mục hiện tại ở chế độ tương tác, phần tử đầu là chuỗi rỗng), rồi thư viện chuẩn và nơi cài thư viện của môi trường ảo. Đó là lý do chạy python3 main.py từ thư mục dự án thì import vinc_tools thành công, còn chạy từ thư mục khác thì có thể không tìm thấy. Môi trường ảo ở bài 1 cũng thay đổi nơi tìm: pip install trong venv đặt gói vào thư mục riêng của venv.

Odoo dùng một cơ chế khác nhưng cùng tinh thần: danh sách thư mục module được khai báo bằng --addons-path (bài 2 của series Odoo), và Odoo tìm các thư mục có __manifest__.py trong đó.

Khám phá một module: dir, help và __file__

Khi gặp module lạ, bạn không cần mở tài liệu ngay. Ba công cụ có sẵn trả lời hầu hết câu hỏi: dir(module) liệt kê các tên bên trong, help(module.ham) hoặc thuộc tính __doc__ in phần mô tả, và module.__file__ cho biết file nguồn nằm đâu (rất tiện khi muốn đọc mã của Odoo hay một thư viện). Python cũng lưu các module đã nạp trong sys.modules, nên import lần thứ hai gần như không tốn thời gian và code của module chỉ chạy một lần.

import math
print([n for n in dir(math) if n in ("sqrt", "pi", "floor", "ceil")])
# ['ceil', 'floor', 'pi', 'sqrt']
print(math.sqrt.__doc__.splitlines()[0])
# Return the square root of x.

import sys
print("math" in sys.modules, "requests" in sys.modules)
# True False   (module đã import thì được lưu lại, import lần hai rất nhanh)

Một quy ước thông thường là xếp các dòng import ở đầu file theo nhóm: thư viện chuẩn trước, thư viện bên ngoài sau, module của dự án cuối cùng, mỗi nhóm cách nhau một dòng trống. Nhìn vào đầu file, người đọc biết ngay file phụ thuộc vào những gì, và đó cũng là lý do bạn thấy các dòng from odoo import ... luôn nằm trên cùng.

Chuỗi import trong module Odoo

# vinc_course/__init__.py
from . import models

# vinc_course/models/__init__.py
from . import course
from . import course_category

# vinc_course/models/course.py
from odoo import api, fields, models
from odoo.exceptions import ValidationError

Hai file __init__.py này là chỗ nhiều người mới "đau" nhất. Tạo file models/course.py xong mà quên from . import course thì class VincCourse không bao giờ được Python chạy, Odoo không biết có model vinc.course, và bảng cũng không được tạo khi nâng cấp. Tutorial chính thức của Odoo mô tả đúng chuỗi này: model nằm trong models/, file được import trong models/__init__.py, và thư mục models được import trong __init__.py gốc. Các dòng from odoo import api, fields, models ở đầu file là import từ thư viện của chính Odoo.

Bạn muốnViết
Thêm model mớiTạo models/ten.py + from . import ten trong models/__init__.py
Thêm controllerTạo controllers/main.py + from . import main trong controllers/__init__.py
Thêm testFile tests/test_x.py + from . import test_x trong tests/__init__.py

Mẫu "mỗi thư mục con có __init__.py import các file của nó" lặp lại cho controllers và tests; riêng test còn có quy ước tên file test_*.py (bài 13 series Odoo).

Thực hành: dựng package công cụ

  1. Tạo cấu trúc vinc-tools/vinc_tools/ như trên với ba file.
  2. Từ thư mục vinc-tools, chạy python3 main.py và kiểm tra dòng đầu ra ODO-007 ODO:ODO-002 ODO ODO.
  3. Chạy python3 vinc_tools/courses.py và thấy dòng "chạy trực tiếp".
  4. Thử bỏ dòng import trong __init__.py và quan sát lỗi khi main.py gọi vinc_tools.make_code.

Lỗi hay gặp khi mới học

import nonexistent_mod
# ModuleNotFoundError: No module named 'nonexistent_mod'

from vinc_tools import nothing
# ImportError: cannot import name 'nothing' from 'vinc_tools' (.../vinc_tools/__init__.py)

# chạy file có import tương đối trực tiếp:
# $ python3 vinc_tools/report.py
# ImportError: attempted relative import with no known parent package
  • ModuleNotFoundError. Python không tìm thấy module: chưa cài bằng pip (hoặc đang ở sai môi trường ảo), sai tên, hoặc đang chạy từ thư mục khiến sys.path không chứa dự án.
  • Chạy trực tiếp file có import tương đối. python3 vinc_tools/report.py báo "attempted relative import with no known parent package" vì file không được nạp như một phần package. Hãy chạy qua file ngoài package (như main.py).
  • Import vòng tròn. Hai module import lẫn nhau gây ImportError: cannot import name ... (most likely due to a circular import):
# circ/a.py
from circ.b import fb
def fa(): return "a"

# circ/b.py
from circ.a import fa
def fb(): return "b"

# import circ.a  ->
# ImportError: cannot import name 'fa' from partially initialized module 'circ.a'
#   (most likely due to a circular import)

# Cách gỡ: chuyển import vào bên trong hàm
# circ/b.py
def fb():
    from circ.a import fa      # chỉ import khi hàm chạy
    return "b" + fa()

Cách tốt nhất là cấu trúc lại để phụ thuộc đi một chiều (đưa phần dùng chung ra module thứ ba); đưa import vào trong hàm chỉ là cách chữa nhanh.

Tổng kết

  • File .py = module; thư mục có __init__.py = package; import kéo code từ nơi khác.
  • Dùng import tương đối (from . import x) trong cùng package.
  • if __name__ == "__main__": chỉ chạy khi file được chạy trực tiếp.
  • Module Odoo: mỗi __init__.py phải import các file con, thiếu dòng là model không tồn tại.

Câu hỏi thường gặp

Vì sao module Odoo cần file __init__.py? ▾
__init__.py biến thư mục thành package và chứa các dòng import (như from . import models) để Python nạp file model, controller. Nếu thiếu dòng import, class model không bao giờ được chạy nên Odoo không biết model tồn tại.
if __name__ == "__main__" dùng để làm gì? ▾
Khối này chỉ chạy khi file được chạy trực tiếp bằng python file.py, và không chạy khi file được import. Nó thường chứa đoạn thử nhanh hoặc điểm vào của một script.
Khác nhau giữa import tương đối và tuyệt đối? ▾
Import tương đối dùng dấu chấm để chỉ vị trí trong cùng package, ví dụ from . import course. Import tuyệt đối ghi đầy đủ đường dẫn từ gốc, ví dụ from vinc_tools.courses import make_code.
Làm sao xử lý lỗi circular import? ▾
Cấu trúc lại để các module phụ thuộc một chiều, ví dụ đưa phần dùng chung ra module thứ ba. Cách chữa nhanh là chuyển lệnh import vào bên trong hàm cần dùng.
