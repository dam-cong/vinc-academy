Kế thừa, super() và decorator trong Python

Ghi đè create hay viết @api.depends đều dựa trên hai kỹ thuật Python: kế thừa với super() và decorator. Bài này dạy chúng bằng ví dụ chạy được, rồi chỉ ra quy tắc vàng khi ghi đè method trong Odoo.

Cập nhật: 16/10/2026 16 phút đọc – lượt xem Đội ngũ Vinc Academy

Tóm tắt nhanh

Kế thừa cho phép class con dùng lại và mở rộng class cha: class OnlineCourse(Course). Khi ghi đè method, hãy gọi super() để chạy logic của class cha. Decorator là hàm bọc hàm khác để thêm hành vi, viết bằng @ten ngay trên dòng def. Odoo dùng cả hai ở khắp nơi: super().create(vals_list) khi ghi đè, @api.depends, @api.model, @api.constrains, @http.route.

Kế thừa class và super()

Class con khai báo class cha trong ngoặc. Nó nhận mọi thuộc tính và method của cha, và có thể ghi đè method nào cần thay đổi. Hàm super() trả về một "cầu nối" tới class cha để bạn gọi lại method gốc:

class Course:
    def __init__(self, name, hours):
        self.name, self.hours = name, hours

    def describe(self):
        return f"{self.name} - {self.hours}h"

class OnlineCourse(Course):                  # kế thừa Course
    def __init__(self, name, hours, platform="Zoom"):
        super().__init__(name, hours)        # gọi __init__ của class cha
        self.platform = platform

    def describe(self):                      # ghi đè method cha
        base = super().describe()            # tái sử dụng kết quả của cha
        return f"{base} (online: {self.platform})"

c = OnlineCourse("Odoo", 24)
print(c.describe())     # Odoo - 24h (online: Zoom)
print(isinstance(c, Course), issubclass(OnlineCourse, Course))   # True True
print([k.__name__ for k in OnlineCourse.__mro__])   # ['OnlineCourse', 'Course', 'object']
  • super().__init__(name, hours) chạy phần khởi tạo của cha, nên class con không phải lặp lại việc gán name, hours.
  • super().describe() lấy kết quả của method cha rồi bạn bổ sung thêm, thay vì viết lại từ đầu.
  • isinstance(c, Course) là True với đối tượng của class con: đối tượng OnlineCourse "cũng là" một Course.
  • __mro__ (method resolution order) cho biết Python tìm method theo thứ tự nào: class con trước, rồi cha, cuối cùng là object.

Đa kế thừa và mixin

Một class có thể kế thừa nhiều class. Mẫu hữu ích nhất là mixin: class nhỏ chỉ cung cấp một khả năng (ghi log, đánh dấu thời gian...), được "trộn" vào class khác:

class LogMixin:
    def log(self, msg):
        print(f"[{type(self).__name__}] {msg}")

class Tracked(LogMixin, Course):
    def describe(self):
        self.log("describe được gọi")
        return super().describe()

print(Tracked("Git", 8).describe())
# [Tracked] describe được gọi
# Git - 8h
print([k.__name__ for k in Tracked.__mro__])
# ['Tracked', 'LogMixin', 'Course', 'object']

Python tìm method theo __mro__, và super() đi theo đúng thứ tự đó, nên mixin và class chính phối hợp được với nhau. Odoo dùng nguyên lý này rất nhiều: tài liệu mô tả _inherit nhận một danh sách model cha khi model mới có _name, chính là đa kế thừa ở tầng model.

Ghi đè method và quy tắc vàng khi dùng super()

Ghi đè create, write là việc dev Odoo làm hằng ngày (bài 9 của series Odoo). Cấu trúc luôn giống nhau: xử lý dữ liệu đầu vào, gọi cha, xử lý kết quả, trả về. Mô phỏng thuần Python:

class Base:
    @classmethod
    def create(cls, vals):
        print("Base.create", vals)
        return vals

class MyModel(Base):
    @classmethod
    def create(cls, vals):
        vals = dict(vals)                 # làm việc trên bản sao
        vals.setdefault("code", "AUTO")   # logic của bạn trước
        result = super().create(vals)     # gọi cha: KHÔNG được quên
        print("sau khi tạo")
        return result                     # trả đúng kiểu như cha

print(MyModel.create({"name": "x"}))
# Base.create {'name': 'x', 'code': 'AUTO'}
# sau khi tạo
# {'name': 'x', 'code': 'AUTO'}

Tài liệu Odoo nhấn mạnh hai điều: luôn gọi super() để không phá vỡ luồng xử lý (chỉ rất ít trường hợp đặc biệt mới không gọi), và trả về dữ liệu cùng kiểu với method cha: cha trả dict thì bản ghi đè cũng phải trả dict. Hãy làm việc trên bản sao của đối số (như dict(vals) ở bài 5) để không đổi dữ liệu của nơi gọi.

super() và thứ tự MRO khi đa kế thừa

Với đa kế thừa có "hình thoi", super() không đơn giản là "gọi cha trực tiếp" mà là "gọi class kế tiếp trong __mro__". Nhờ vậy mỗi class trong chuỗi chạy đúng một lần, và các class cùng ghi đè một method phối hợp được với nhau:

class A:
    def hello(self):
        return ["A"]

class B(A):
    def hello(self):
        return ["B"] + super().hello()

class C(A):
    def hello(self):
        return ["C"] + super().hello()

class D(B, C):
    def hello(self):
        return ["D"] + super().hello()

print(D().hello())                       # ['D', 'B', 'C', 'A']
print([k.__name__ for k in D.__mro__])   # ['D', 'B', 'C', 'A', 'object']

Chính vì vậy quy tắc "luôn gọi super()" quan trọng: nếu một class trong chuỗi bỏ qua nó, mọi class phía sau trong __mro__ sẽ không bao giờ được chạy. Mô hình tương tự áp dụng khi nhiều module cùng mở rộng một model Odoo: mỗi module ghi đè method và phải gọi super() để phần của module khác vẫn hoạt động.

Kế thừa hay thành phần?

Kế thừa diễn tả quan hệ "là một" (OnlineCourse là một Course). Khi quan hệ chỉ là "có một", hãy dùng thành phần: lưu đối tượng kia làm thuộc tính. Lạm dụng kế thừa tạo ra cây class sâu, khó hiểu và khó đổi; thành phần linh hoạt hơn:

class Instructor:
    def __init__(self, name):
        self.name = name

class Offering:                          # thành phần: "có một", không phải "là một"
    def __init__(self, course, instructor):
        self.course = course
        self.instructor = instructor

    def title(self):
        return f"{self.course.name} - {self.instructor.name}"

print(Offering(Course("Odoo", 24), Instructor("Hiền")).title())   # Odoo - Hiền

Trong Odoo, quan hệ "có một" chính là Many2one (instructor_id) và "có nhiều" là One2many: model dùng thành phần qua field quan hệ, còn _inherit dành cho khi bạn thực sự muốn mở rộng hoặc tái sử dụng chính model đó.

Decorator: hàm bọc hàm

Decorator là một hàm nhận hàm khác và trả về hàm mới thêm hành vi. Cú pháp @timer trên dòng def là cách viết gọn của slow_sum = timer(slow_sum). Nó dựa trên closure bạn đã gặp ở bài 5:

import functools

def timer(func):
    @functools.wraps(func)                # giữ tên và docstring của hàm gốc
    def wrapper(*args, **kwargs):
        result = func(*args, **kwargs)
        print(f"{func.__name__} xong")
        return result
    return wrapper

@timer                                    # tương đương slow_sum = timer(slow_sum)
def slow_sum(n):
    """Cộng 1..n"""
    return sum(range(n + 1))

print(slow_sum(10), slow_sum.__name__, slow_sum.__doc__)
# slow_sum xong
# 55 slow_sum Cộng 1..n

functools.wraps rất quan trọng: nó sao chép tên và docstring của hàm gốc lên hàm bọc. Thiếu nó, hàm bị đổi thành wrapper và mất docstring, gây khó khăn khi debug và với mọi công cụ hay framework đọc tên hàm (log, debugger, bộ đăng ký route...):

def no_wraps(func):
    def wrapper(*a, **k):
        return func(*a, **k)
    return wrapper

@no_wraps
def f():
    "doc"

print(f.__name__, f.__doc__)     # wrapper None   <- mất tên và docstring

Decorator có tham số

Muốn truyền tham số như @retry(3), bạn cần thêm một tầng hàm: retry(3) trả về decorator thật. Đây chính là cấu trúc của @api.depends('a', 'b') hay @http.route('/x', auth='public'):

def retry(times):
    def deco(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            last = None
            for i in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except ValueError as e:
                    last = e
                    print(f"lần {i} lỗi: {e}")
            raise last
        return wrapper
    return deco

calls = {"n": 0}

@retry(3)                                 # decorator có tham số: retry(3) trả về deco
def flaky():
    calls["n"] += 1
    if calls["n"] < 3:
        raise ValueError("chưa được")
    return "ok"

print(flaky())
# lần 1 lỗi: chưa được
# lần 2 lỗi: chưa được
# ok

Thứ tự nhiều decorator

def deco(tag):
    def d(f):
        def w():
            return f"<{tag}>" + f() + f"</{tag}>"
        return w
    return d

@deco("a")
@deco("b")
def x():
    return "x"

print(x())    # <a><b>x</b></a>   (decorator gần hàm nhất áp dụng trước)

Hai decorator hữu ích tự viết hoặc dùng sẵn

Ngoài ghi log, decorator hay dùng nhất là nhớ kết quả (cache) cho hàm tốn thời gian và kiểm tra đối số trước khi chạy hàm. Thư viện chuẩn có sẵn functools.cache (và lru_cache giới hạn kích thước):

import functools

@functools.cache                         # nhớ kết quả theo đối số
def course_price(code):
    print("đang tra", code)              # chỉ in ở lần gọi đầu
    return {"ODO-F": 100}.get(code, 0)

print(course_price("ODO-F"), course_price("ODO-F"))
# đang tra ODO-F
# 100 100

def require_positive(func):              # decorator kiểm tra đối số
    @functools.wraps(func)
    def wrapper(hours, *args, **kwargs):
        if hours <= 0:
            raise ValueError("hours phải > 0")
        return func(hours, *args, **kwargs)
    return wrapper

@require_positive
def sessions(hours):
    return hours // 8

print(sessions(24))                      # 3
sessions(0)
# ValueError: hours phải > 0

Hãy cẩn thận khi cache hàm có tác dụng phụ hoặc phụ thuộc dữ liệu thay đổi: kết quả cũ sẽ được trả lại dù dữ liệu gốc đã đổi. Cache hợp với hàm "thuần" như tra bảng cố định.

@classmethod và @staticmethod

class Tool:
    @staticmethod
    def hours_to_days(h):                 # không cần self hay cls
        return h / 8

    @classmethod
    def from_string(cls, s):              # nhận class, hay dùng làm "hàm tạo" thứ hai
        name, hours = s.split(":")
        return Course(name, int(hours))

print(Tool.hours_to_days(24))             # 3.0
print(Tool.from_string("Odoo:24").describe())   # Odoo - 24h

@staticmethod là hàm thường nằm trong class (không nhận self hay cls). @classmethod nhận chính class làm tham số đầu tiên, thường dùng làm "hàm tạo thay thế" như from_string. Hai decorator này cùng @property ở bài 8 là các decorator dựng sẵn bạn gặp nhiều nhất.

Decorator bạn gặp trong code Odoo

# 1. decorator có tham số: khai báo phụ thuộc của computed field
@api.depends('price', 'duration_hours')
def _compute_price_per_hour(self):
    ...

# 2. decorator không tham số: create nhận list vals
@api.model
def create(self, vals_list):
    courses = super().create(vals_list)
    return courses

# 3. ràng buộc dữ liệu
@api.constrains('duration_hours')
def _check_duration(self):
    ...

# 4. route của controller, ghi đè phải gắn lại @route()
@http.route('/vinc_course/courses', auth='public')
def courses(self, **kw):
    ...
DecoratorTác dụng (theo tài liệu Odoo)
@api.depends(...)Khai báo field mà compute method phụ thuộc; ORM tính lại khi chúng đổi
@api.constrains(...)Method kiểm tra ràng buộc, chạy khi các field được nêu bị sửa
@api.onchange(...)Cập nhật form khi field thay đổi, chỉ trong giao diện
@api.modelMethod mà nội dung self không quan trọng, chỉ cần model
@api.ondelete(at_uninstall=False)Chạy trong lúc xóa bản ghi, cho phép chặn xóa mà không ảnh hưởng gỡ module
@http.route(...)Gắn method vào một URL; ghi đè controller phải gắn lại @route()

Bạn không cần tự viết các decorator này mà chỉ cần hiểu chúng là hàm bọc hàm, và đặt đúng chỗ ngay trên dòng def. Điều đó giải thích vì sao tài liệu Odoo lưu ý rằng ghi đè method của controller mà quên gắn lại @route() sẽ làm route biến mất: decorator mới là thứ đăng ký method vào hệ thống.

Thực hành: decorator ghi log và kiểm tra

  1. Viết decorator log_call in tên hàm và đối số trước khi chạy hàm gốc, dùng functools.wraps.
  2. Áp dụng nó lên một hàm tính giá mỗi giờ ở bài 5 và kiểm tra __name__ vẫn là tên cũ.
  3. Tạo class OnlineCourse như trên và thêm method describe dùng super(); thử thêm LogMixin.

Lỗi hay gặp khi mới học

  • Quên super().__init__(...) trong class con. Thuộc tính của cha không được tạo, và về sau gặp AttributeError.
  • Ghi đè method mà quên return. Hàm trả None thay vì kết quả cha, làm hỏng mọi nơi gọi.
  • Viết decorator mà quên functools.wraps. Hàm mất tên và docstring (f.__name__ thành wrapper).
  • Quên gọi retry(3) khi decorator có tham số. Viết @retry thay vì @retry(3) truyền hàm vào chỗ tham số.

Tổng kết

  • Class con kế thừa, ghi đè và dùng super() để tái sử dụng class cha; mixin cung cấp một khả năng riêng.
  • Khi ghi đè method Odoo: luôn gọi super(), làm việc trên bản sao đối số và trả về cùng kiểu.
  • Decorator là hàm bọc hàm; dùng functools.wraps; decorator có tham số cần thêm một tầng.
  • Hãy nhận ra @api.depends, @api.constrains, @api.model, @http.route là decorator.

Câu hỏi thường gặp

super() dùng để làm gì? ▾
super() trả về cầu nối tới class cha để bạn gọi lại method gốc, ví dụ super().create(vals_list). Nhờ đó bạn thêm logic trước hoặc sau mà vẫn giữ nguyên hành vi của cha.
Vì sao phải gọi super() khi ghi đè method trong Odoo? ▾
Tài liệu Odoo nhấn mạnh phải luôn gọi super() để không phá vỡ luồng xử lý, và trả về dữ liệu cùng kiểu với method cha, ví dụ cha trả dict thì bản ghi đè cũng trả dict.
Decorator là gì? ▾
Decorator là hàm nhận một hàm và trả về hàm mới có thêm hành vi. Cú pháp @ten đặt trên dòng def là cách viết gọn của ham = ten(ham).
Vì sao cần functools.wraps khi viết decorator? ▾
Nó sao chép tên và docstring của hàm gốc lên hàm bọc. Thiếu nó, hàm bị đổi tên thành wrapper và mất docstring, gây khó khăn khi debug.
