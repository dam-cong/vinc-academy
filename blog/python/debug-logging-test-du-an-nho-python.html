Debug, logging, test và dự án nhỏ: hoàn thiện công cụ Python

Bài cuối ghép mọi thứ đã học thành một công cụ dòng lệnh: gỡ lỗi bằng breakpoint() và pdb, ghi log có cấp độ, viết test với unittest và Mock, thêm type hints, rồi hoàn thiện script nhập khóa học từ CSV vào Odoo.

Cập nhật: 16/10/2026 16 phút đọc Đội ngũ Vinc Academy

Tóm tắt nhanh

Bài cuối gom mọi kỹ năng thành một chương trình hoàn chỉnh: đọc CSV, kiểm tra dữ liệu, gọi API JSON-2 của Odoo, ghi log và có bộ test. Công cụ đi kèm: breakpoint() để gỡ lỗi từng dòng, logging thay cho print, unittest (nền của TransactionCase trong Odoo) cùng Mock để test không cần mạng, và type hints để code tự mô tả. Cuối bài là script import_courses.py chạy được, đã kiểm tra bằng 6 test và một server giả lập.

Gỡ lỗi: breakpoint() và pdb

Thay vì rải print khắp nơi, hãy dừng chương trình ngay chỗ nghi ngờ và quan sát. Hàm dựng sẵn breakpoint() mở trình gỡ lỗi pdb tại dòng đó:

def price_per_hour(price, hours):
    breakpoint()                    # dừng tại đây và mở trình gỡ lỗi pdb
    return price / hours

Bạn cũng chạy được cả chương trình dưới trình gỡ lỗi bằng python3 -m pdb script.py. Khi làm việc với Odoo, cách thường dùng là pip install ipdb rồi đặt import ipdb; ipdb.set_trace() tại dòng cần dừng, như đã nhắc ở bài 2 của series Odoo, và chạy server ở chế độ có terminal để nhập lệnh. Nhớ xóa breakpoint trước khi commit: một breakpoint() sót lại trên server sẽ treo tiến trình chờ người nhập lệnh.

logging: ghi nhật ký có cấp độ

print không cho biết thông điệp quan trọng đến đâu, không có thời gian, và không tắt được khi chạy thật. logging giải quyết cả ba:

import logging

print(logging.DEBUG, logging.INFO, logging.WARNING, logging.ERROR, logging.CRITICAL)
# 10 20 30 40 50

logging.basicConfig(level=logging.INFO,
                    format="%(asctime)s %(levelname)s %(name)s: %(message)s", datefmt="%H:%M:%S")
log = logging.getLogger("vinc.import")      # logger có tên, thường dùng __name__

log.debug("không hiện vì level là INFO")
log.info("đã nạp %d khóa học", 5)            # 11:41:00 INFO vinc.import: đã nạp 5 khóa học
log.warning("khóa %s thiếu giờ", "PY-F")     # 11:41:00 WARNING vinc.import: khóa PY-F thiếu giờ

try:
    1 / 0
except ZeroDivisionError:
    log.exception("lỗi tính toán")           # ERROR kèm toàn bộ traceback
Cấp độGiá trịDùng khi
DEBUG10Chi tiết cho lập trình viên khi tìm lỗi
INFO20Xác nhận mọi thứ chạy như dự kiến
WARNING30Có điều bất thường nhưng chương trình vẫn chạy (mức mặc định)
ERROR40Một việc không làm được

  • Chỉ thông điệp từ cấp độ đã cài trở lên mới hiện: với level=INFO, dòng debug bị bỏ qua.
  • Truyền tham số riêng (log.info("đã nạp %d", n)) thay vì dựng chuỗi bằng f-string: chuỗi chỉ được ghép khi dòng log thật sự được ghi.
  • log.exception(...) trong khối except ghi cả traceback.
  • Đặt tên logger theo module (logging.getLogger(__name__)) để lọc theo nguồn.

Odoo dùng đúng cách này: trong code Odoo bạn gặp _logger = logging.getLogger(__name__) rồi _logger.warning(...) (tài liệu về server action có ví dụ như vậy), và bạn điều chỉnh độ chi tiết bằng tham số --log-level của odoo-bin. Nguyên tắc ngón tay cái: print cho kết quả chương trình, logging cho mọi thứ còn lại.

Viết test với unittest

Test tự động chạy code của bạn với dữ liệu đã biết và so kết quả với mong đợi. Python có sẵn unittest, và TransactionCase của Odoo (bài 13 series Odoo) chỉ là phần mở rộng của nó: những gì bạn học ở đây dùng được nguyên vẹn khi viết test cho model.

import unittest

class TestCourseRow(unittest.TestCase):
    def setUp(self):                          # chạy trước MỖI test
        self.row = {"name": "  Odoo  ", "hours": "24"}

    def test_valid_row(self):
        course = CourseRow.from_dict(self.row)
        self.assertEqual(course, CourseRow(name="Odoo", hours=24))

    def test_bad_hours(self):
        for bad in ("abc", "0", "-3"):
            with self.subTest(hours=bad):     # mỗi giá trị là một phép thử riêng
                with self.assertRaises(InvalidRow):
                    CourseRow.from_dict({"name": "X", "hours": bad})

if __name__ == "__main__":
    unittest.main()

Chạy bộ test bằng python3 -m unittest -v (tự tìm các file test_*.py). Một test thất bại in rõ giá trị lệch:

class T(unittest.TestCase):
    def test_fail(self):
        self.assertEqual(1 + 1, 3)

Mock: test mà không cần mạng

Test không nên gọi API thật: chậm, cần key và có thể làm đổi dữ liệu. unittest.mock.Mock tạo đối tượng giả ghi nhớ cách nó bị gọi, để bạn kiểm tra rằng code đã gọi API đúng và đủ:

from unittest.mock import Mock

def test_calls_api_for_each_row(self):
    client = Mock()                           # đối tượng giả, thay OdooClient thật
    client.call.return_value = [1]
    rows = [CourseRow("A", 8), CourseRow("B", 16)]

    self.assertEqual(import_rows(client, rows), 2)
    self.assertEqual(client.call.call_count, 2)
    client.call.assert_any_call("vinc.course", "create",
                                vals_list=[{"name": "A", "duration_hours": 8}])

Đây là lý do bài 13 khuyên gói HTTP vào OdooClient: hàm import_rows nhận client như một tham số nên test chỉ cần truyền client giả.

Type hints: code tự mô tả

Gợi ý kiểu ghi kiểu dự kiến của tham số và giá trị trả về. Python không kiểm tra chúng lúc chạy, nhưng chúng giúp người đọc, trình soạn thảo và các công cụ kiểm tra kiểu phát hiện sai sót sớm:

def total(hours: list[int], factor: float = 1.0) -> float:
    return sum(hours) * factor

print(total([1, 2], 2))                  # 6.0 (factor là int dù khai báo float: Python không phàn nàn)
print(total.__annotations__)
# {'hours': list[int], 'factor': <class 'float'>, 'return': <class 'float'>}

def find(code: str) -> dict | None:      # dict hoặc None
    return {"code": code} if code else None

print(find(""), find("X"), find(123))   # None {'code': 'X'} {'code': 123}   <- gợi ý kiểu không chặn lúc chạy
Gợi ýNghĩa
x: int, name: strKiểu cơ bản
list[int], dict[str, int]Danh sách số nguyên, dict khóa chuỗi giá trị số
str | NoneChuỗi hoặc None
-> floatKiểu giá trị trả về
@dataclass với name: strKhai báo trường của lớp dữ liệu (bài 8)

Tài liệu Odoo cũng ghi chữ ký method kèm kiểu, ví dụ search(domain, offset, limit, order) -> Self, nên đọc type hints giúp bạn hiểu tài liệu ORM nhanh hơn.

Và chương trình chính:

import_courses.py

#!/usr/bin/env python3
"""Nhập khóa học từ file CSV vào Odoo qua API JSON-2."""
import argparse
import csv
import logging
import os
import sys
from dataclasses import dataclass
from pathlib import Path

import requests

_logger = logging.getLogger("import_courses")


class OdooAPIError(Exception):
    """Lỗi do Odoo trả về hoặc lỗi kết nối."""


class InvalidRow(Exception):
    """Dòng CSV không hợp lệ."""


@dataclass
class CourseRow:
    name: str
    hours: int

    @classmethod
    def from_dict(cls, row: dict) -> "CourseRow":
        name = (row.get("name") or "").strip()
        if not name:
            raise InvalidRow("thiếu tên khóa học")
        try:
            hours = int(row["hours"])
        except (KeyError, ValueError) as e:
            raise InvalidRow(f"số giờ không hợp lệ: {row.get('hours')!r}") from e
        if hours <= 0:
            raise InvalidRow(f"số giờ phải lớn hơn 0: {hours}")
        return cls(name=name, hours=hours)


class OdooClient:
    def __init__(self, base_url: str, api_key: str, database: str | None = None, timeout: int = 10):
        self.base_url = base_url.rstrip("/")
        self.timeout = timeout
        self.session = requests.Session()
        self.session.headers["Authorization"] = f"bearer {api_key}"
        if database:
            self.session.headers["X-Odoo-Database"] = database

    def call(self, model: str, method: str, **payload):
        url = f"{self.base_url}/json/2/{model}/{method}"
        try:
            response = self.session.post(url, json=payload, timeout=self.timeout)
        except requests.RequestException as e:
            raise OdooAPIError(f"Không gọi được {url}: {e}") from e
        if not response.ok:
            try:
                message = response.json().get("message", response.text)
            except ValueError:
                message = response.text
            raise OdooAPIError(f"HTTP {response.status_code}: {message}")
        return response.json()


def read_rows(path: Path) -> tuple[list[CourseRow], list[str]]:
    ok, errors = [], []
    with open(path, encoding="utf-8", newline="") as f:
        for number, row in enumerate(csv.DictReader(f), start=2):   # dòng 1 là tiêu đề
            try:
                ok.append(CourseRow.from_dict(row))
            except InvalidRow as e:
                errors.append(f"dòng {number}: {e}")
    return ok, errors


def import_rows(client, rows: list[CourseRow], dry_run: bool = False) -> int:
    created = 0
    for row in rows:
        if dry_run:
            _logger.info("[dry-run] sẽ tạo: %s (%s giờ)", row.name, row.hours)
            continue
        ids = client.call("vinc.course", "create",
                          vals_list=[{"name": row.name, "duration_hours": row.hours}])
        _logger.debug("đã tạo id=%s", ids)
        created += 1
    return created


def main(argv=None) -> int:
    parser = argparse.ArgumentParser(description="Nhập khóa học từ CSV vào Odoo.")
    parser.add_argument("csv_file", type=Path)
    parser.add_argument("--dry-run", action="store_true", help="chỉ kiểm tra, không gọi API tạo")
    parser.add_argument("-v", "--verbose", action="store_true", help="hiện log chi tiết")
    args = parser.parse_args(argv)

    logging.basicConfig(level=logging.DEBUG if args.verbose else logging.INFO,
                        format="%(levelname)s %(message)s")
    try:
        rows, errors = read_rows(args.csv_file)
    except FileNotFoundError:
        _logger.error("Không thấy file: %s", args.csv_file)
        return 2
    for message in errors:
        _logger.warning("bỏ qua %s", message)
    _logger.info("đọc được %d dòng hợp lệ, %d dòng lỗi", len(rows), len(errors))

    client = OdooClient(os.environ["ODOO_URL"], os.environ["ODOO_API_KEY"], os.environ.get("ODOO_DB"))
    try:
        created = import_rows(client, rows, dry_run=args.dry_run)
    except OdooAPIError as e:
        _logger.error("Odoo báo lỗi: %s", e)
        return 1
    _logger.info("hoàn tất: tạo %d khóa học", created)
    return 0 if not errors else 3


if __name__ == "__main__":
    sys.exit(main())

Hãy đối chiếu với từng bài của series: pathlib, csv và with (bài 10, 11); @dataclass và @classmethod (bài 8, 9); exception tự định nghĩa InvalidRow, OdooAPIError (bài 10); requests.Session và timeout (bài 13); logging (bài này); if __name__ == "__main__" và sys.exit (bài 7). Thêm vào đó argparse đọc tham số dòng lệnh (--dry-run, -v) và tự sinh phần --help.

Lỗi hay gặp khi mới học

  • Để sót breakpoint() hoặc print gỡ lỗi trong code. Hãy tìm và xóa trước khi commit; dùng logging cho những gì cần giữ lại.
  • Gọi logging.basicConfig sau khi đã có log. Cấu hình đầu tiên mới có hiệu lực; hãy gọi một lần, sớm, trong main.
  • Test phụ thuộc thứ tự hay dữ liệu ngoài. Mỗi test phải tự chuẩn bị dữ liệu (setUp, thư mục tạm) và không gọi mạng thật.
  • Tưởng type hints chặn được lỗi kiểu. Chúng không ngăn find(123) chạy; cần công cụ kiểm tra kiểu hoặc test để bắt lỗi.
  • Test tên không bắt đầu bằng test. unittest sẽ bỏ qua (cũng như quy tắc của Odoo ở bài 13 series Odoo).

Tổng kết cả series và bước tiếp theo

  • breakpoint() và pdb cho gỡ lỗi; logging với cấp độ thay cho print.
  • unittest + Mock để test không cần mạng; TransactionCase của Odoo là phần mở rộng của nó.
  • Type hints mô tả kiểu nhưng không bắt buộc lúc chạy.
  • Một chương trình thực tế là sự kết hợp của file, kiểm tra dữ liệu, API, log và test.

Câu hỏi thường gặp

Khi nào nên dùng breakpoint() thay vì print để gỡ lỗi? ▾
breakpoint() mở trình gỡ lỗi pdb ngay tại dòng đó, cho phép xem biến (p), chạy từng dòng (n, s) và tiếp tục (c) mà không phải sửa code thêm. Vài dòng print cũng đủ khi luồng đơn giản, nhưng với luồng phức tạp thì breakpoint() nhanh và sạch hơn; nhớ xóa nó trước khi commit.
Vì sao nên dùng logging thay cho print? ▾
logging gắn cấp độ (DEBUG tới CRITICAL), thời gian và tên logger, và bạn tắt hay bật theo mức mà không sửa code. print phù hợp cho kết quả chương trình, logging cho thông tin vận hành; Odoo cũng dùng logging.getLogger(__name__) và điều chỉnh bằng tham số --log-level.
Type hints có bắt lỗi kiểu khi chạy không? ▾
Không. Python không kiểm tra type hints lúc chạy, nên find(123) vẫn chạy dù khai báo find(code: str). Chúng giúp người đọc, trình soạn thảo và công cụ kiểm tra kiểu tĩnh như mypy; muốn bắt lỗi kiểu thì phải chạy công cụ đó hoặc viết test.
Odoo dùng unittest hay bộ test riêng? ▾
Odoo dùng unittest: TransactionCase cùng các lớp test của Odoo là phần mở rộng của unittest.TestCase, nên kiến thức assertEqual, setUp hay assertRaises ở bài này dùng được nguyên vẹn khi viết test cho model.
