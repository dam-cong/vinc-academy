Gọi API bằng Python requests: JSON-2 của Odoo từ A–Z

Tích hợp Odoo với hệ thống khác hầu như luôn bắt đầu bằng một lệnh gọi HTTP. Bài này dạy thư viện requests, cách đặt timeout, xử lý lỗi, và gọi API JSON-2 của Odoo 20 bằng API key, rồi gói lại thành một client dùng lại được.

Cập nhật: 16/10/2026 15 phút đọc – lượt xem Đội ngũ Vinc Academy

Tóm tắt nhanh

Thư viện requests gửi yêu cầu HTTP chỉ trong một dòng: requests.post(url, json=body, headers=h, timeout=10). Hãy luôn đặt timeout, gọi raise_for_status() để biến mã lỗi 4xx/5xx thành ngoại lệ và đọc dữ liệu bằng .json(). Với Odoo 20, bạn gọi model qua API JSON-2: POST /json/2/<model>/<method> kèm API key trong header Authorization: bearer, đúng như bài 12 của series Odoo.

HTTP trong năm phút

Một yêu cầu HTTP gồm: phương thức (GET để đọc, POST để gửi dữ liệu...), URL, header (thông tin kèm theo như loại nội dung, xác thực) và tùy chọn body. Phản hồi gồm mã trạng thái, header và body. Mã trạng thái cho biết kết quả:

MãÝ nghĩaGặp ở API Odoo
200Thành côngBody là giá trị trả về của method, dạng JSON
401Chưa xác thực / key saiVí dụ lỗi trong tài liệu: "message": "Invalid apikey"
403Bị cấmThu hồi key sai báo 403 Forbidden
404Không tìm thấySai đường dẫn hoặc model
422Không xử lý đượcVượt giới hạn sinh API key bằng lập trình
4xx/5xx khácLỗi phía client / serverBody là đối tượng JSON có name, message, arguments, context, debug

requests: gửi yêu cầu và đọc phản hồi

import requests

r = requests.get("https://example.com/api/courses",
                 params={"level": "beginner", "page": 1},     # thành ?level=beginner&page=1
                 headers={"Accept": "application/json"},
                 timeout=10)                                  # LUÔN đặt timeout

print(r.status_code, r.ok)                  # 200 True
print(r.headers["Content-Type"])            # application/json; charset=utf-8
data = r.json()                             # đọc body thành list/dict
print(r.url)                                # URL đầy đủ đã gồm tham số
print(r.elapsed.total_seconds())            # thời gian phản hồi (giây)

URL trong ví dụ là giả định (example.com không có API này); hãy thay bằng một API thật khi thử. Mô phỏng một server cục bộ cho kết quả đúng như các dòng chú thích.

Tham số / thuộc tínhTác dụng
params={...}Tham số trên URL (query string), tự mã hóa ký tự đặc biệt
json={...}Gửi body JSON và tự đặt Content-Type
headers={...}Header của yêu cầu
timeout=10Số giây tối đa chờ phản hồi
r.status_code, r.okMã trạng thái; ok đúng với mã dưới 400
r.json(), r.textBody đã giải mã JSON / body dạng chuỗi
r.raise_for_status()Ném HTTPError nếu mã là 4xx/5xx

Phương thức HTTP và cách gửi body

HàmPhương thứcThường dùng để

Có hai cách gửi body: data= mã hóa dạng form (application/x-www-form-urlencoded) còn json= gửi JSON và đặt Content-Type: application/json. API của Odoo mong JSON nên hãy dùng json=. Phản hồi không phải JSON (như ảnh, PDF) thì đọc bằng .content (kiểu bytes) và ghi ra file như ở bài 11:

p1 = requests.Request("POST", "http://x/y", data={"a": "1", "b": "x y"}).prepare()
print(p1.headers["Content-Type"], p1.body)
# application/x-www-form-urlencoded a=1&b=x+y

p2 = requests.Request("POST", "http://x/y", json={"a": 1, "b": "tiếng"}).prepare()
print(p2.headers["Content-Type"], p2.body)
# application/json b'{"a": 1, "b": "ti\\u1ebfng"}'

img = requests.get(url_cua_anh, timeout=10)
print(type(img.content).__name__)                # bytes: dùng cho file nhị phân
Path("anh.png").write_bytes(img.content)         # lưu thẳng ra file (bài 11)

Phân trang khi dữ liệu nhiều

Không nên lấy hàng chục nghìn bản ghi trong một lệnh gọi. Tài liệu ORM mô tả search nhận offset (số bản ghi bỏ qua), limit (số bản ghi tối đa) và order. Vòng lặp dưới đây dùng OdooClient ở phần sau để lấy từng trang cho tới khi trang cuối ngắn hơn page_size:

def fetch_all_ids(client, domain, page_size=100):
    ids, offset = [], 0
    while True:
        page = client.call("vinc.course", "search", domain=domain,
                           offset=offset, limit=page_size, order="id")   # tham số của search
        ids.extend(page)
        if len(page) < page_size:        # trang cuối thiếu phần tử: đã hết dữ liệu
            return ids
        offset += page_size

# với dữ liệu giả gồm 7 id: fetch_all_ids(client, [], page_size=3) -> [1, 2, 3, 4, 5, 6, 7]

Hãy kiểm tra trang /doc của database để biết chính xác tham số của từng method trên hệ thống của bạn.

Gọi API JSON-2 của Odoo

Theo tài liệu Odoo 20, bạn gửi POST tới /json/2/<model>/<method>. Header bắt buộc gồm Authorization: bearer <API key> và Content-Type: application/json (requests tự đặt cái sau khi bạn dùng json=); X-Odoo-Database là tùy chọn, cần khi một server chứa nhiều database. Body JSON gồm ids (nếu method làm việc trên bản ghi), context tùy chọn và các tham số của method:

import os
import requests

BASE_URL = os.environ["ODOO_URL"] + "/json/2"          # ví dụ https://mycompany.example.com
headers = {
    "Authorization": "bearer " + os.environ["ODOO_API_KEY"],   # KHÔNG ghi key vào code
    "X-Odoo-Database": os.environ.get("ODOO_DB", ""),
}

r = requests.post(
    f"{BASE_URL}/vinc.course/search_read",
    headers=headers,
    json={"domain": [["level", "=", "beginner"]], "fields": ["name", "level"]},
    timeout=10,
)
r.raise_for_status()
print(r.json())
# [{'id': 1, 'name': 'Odoo cơ bản', 'level': 'beginner'}, ...]

Lưu ý bảo mật: API key phải nằm ngoài code, thường trong biến môi trường (os.environ) hoặc nơi lưu bí mật của hệ thống, vì key có quyền của người dùng sở hữu nó. Tài liệu còn khuyến nghị dùng "bot user" riêng với quyền tối thiểu cho tích hợp tự động, và key có thời hạn tối đa ba tháng nên cần xoay vòng định kỳ.

bad = requests.post(f"{BASE_URL}/vinc.course/search_read", headers={"Authorization": "bearer WRONG"}, json={}, timeout=10)
print(bad.status_code, bad.json()["message"])    # 401 Invalid apikey
bad.raise_for_status()
# requests.exceptions.HTTPError: 401 Client Error: Unauthorized for url: .../json/2/vinc.course/search_read

Xử lý lỗi và timeout

Tài liệu requests nêu rõ: nếu không đặt timeout, yêu cầu không bao giờ hết hạn và chương trình có thể treo vô hạn; gần như mọi code production nên đặt tham số này. Các lỗi của requests đều kế thừa requests.exceptions.RequestException:

import requests

try:
    r = requests.post(url, headers=headers, json=body, timeout=5)
    r.raise_for_status()
except requests.Timeout:
    print("Quá thời gian chờ")             # server không trả lời trong 5 giây
except requests.ConnectionError:
    print("Không kết nối được")            # DNS lỗi, bị từ chối kết nối...
except requests.HTTPError as e:
    print("Odoo trả lỗi:", e.response.status_code, e.response.text[:100])
except requests.RequestException as e:      # lớp cha của mọi lỗi requests
    print("Lỗi khác:", e)
Ngoại lệKhi nào
ConnectionErrorSự cố mạng: DNS lỗi, từ chối kết nối
TimeoutKhông nhận được phản hồi trong thời gian timeout
HTTPErrorChỉ khi bạn gọi raise_for_status() và mã là 4xx/5xx
TooManyRedirectsChuyển hướng quá số lần cho phép

Lưu ý timeout không giới hạn tổng thời gian tải phản hồi mà là thời gian chờ không nhận được byte nào từ server.

Gói thành một client dùng lại được

Khi gọi API nhiều lần, hãy dùng requests.Session: nó giữ lại header (như Authorization) giữa các lệnh gọi và tái sử dụng kết nối tới cùng một host, nhanh hơn đáng kể. Kết hợp với kiến thức class (bài 8) và exception tự định nghĩa (bài 10), ta có một client nhỏ gọn:

class OdooAPIError(Exception):
    """Lỗi do Odoo trả về hoặc lỗi kết nối."""

class OdooClient:
    def __init__(self, base_url, api_key, database=None, timeout=10):
        self.base_url = base_url.rstrip("/")
        self.timeout = timeout
        self.session = requests.Session()                      # dùng lại kết nối và header
        self.session.headers["Authorization"] = f"bearer {api_key}"
        if database:
            self.session.headers["X-Odoo-Database"] = database

    def call(self, model, method, **payload):
        url = f"{self.base_url}/json/2/{model}/{method}"
        try:
            response = self.session.post(url, json=payload, timeout=self.timeout)
        except requests.RequestException as e:
            raise OdooAPIError(f"Không gọi được {url}: {e}") from e
        if not response.ok:
            try:
                message = response.json().get("message", response.text)
            except ValueError:
                message = response.text
            raise OdooAPIError(f"HTTP {response.status_code}: {message}")
        return response.json()
client = OdooClient(os.environ["ODOO_URL"], os.environ["ODOO_API_KEY"], os.environ.get("ODOO_DB"))

print(client.call("vinc.course", "search_read", domain=[["level", "=", "beginner"]], fields=["name", "level"]))
# [{'id': 1, 'name': 'Odoo', 'level': 'beginner'}]
print(client.call("vinc.course", "create", vals_list=[{"name": "Odoo cơ bản", "duration_hours": 24}]))
# [7]

OdooClient(os.environ["ODOO_URL"], "WRONG").call("vinc.course", "search_read")
# OdooAPIError: HTTP 401: Invalid apikey

Mọi chi tiết xấu của HTTP (header, URL, timeout, mã lỗi) nằm gọn trong OdooClient; phần còn lại của chương trình chỉ gọi client.call(...) và bắt OdooAPIError. Đây là kiểu tách lớp giúp bạn dễ viết test (bài 14): thay client thật bằng đối tượng giả.

Thử lại khi mạng chập chờn

import time

def with_retry(func, attempts=3, delay=0.5):
    for i in range(1, attempts + 1):
        try:
            return func()
        except OdooAPIError:
            print(f"lần {i} lỗi")
            if i == attempts:
                raise                       # hết lượt thử: ném lại lỗi cuối
            time.sleep(delay * i)           # chờ lâu dần giữa các lần thử

with_retry(lambda: client.call("vinc.course", "search_read", fields=["name"]))

Chỉ nên thử lại với thao tác an toàn khi lặp lại, như đọc dữ liệu. Với thao tác ghi (create), thử lại có thể tạo bản ghi trùng nếu lần đầu thực ra đã thành công. Tài liệu API còn nhấn mạnh mỗi lệnh gọi JSON-2 là một transaction riêng, nên các bước liên quan nhau cần được gói vào một method duy nhất phía server.

Thực hành: kiểm tra kết nối tới Odoo

  1. Tạo API key trong tùy chọn người dùng Odoo và đặt ODOO_URL, ODOO_API_KEY, ODOO_DB thành biến môi trường.
  2. Dùng OdooClient gọi search_read cho model res.partner với fields=["name"] và limit nhỏ.
  3. Cố ý đặt key sai và kiểm tra bạn nhận OdooAPIError: HTTP 401: Invalid apikey.
  4. Đặt timeout=0.001 và quan sát lỗi quá thời gian.

Lỗi hay gặp khi mới học

  • Quên timeout. Chương trình có thể treo mãi khi server không trả lời.
  • Quên raise_for_status(). Mã 401/404 không tự gây lỗi, r.json() sau đó trả về nội dung lỗi mà bạn tưởng là dữ liệu. Luôn kiểm tra r.ok hoặc gọi raise_for_status().
  • Header sai định dạng. Phải là Authorization: bearer <key>; thiếu chữ bearer hay key hết hạn đều cho 401.
  • Ghi API key vào code hoặc Git. Key có quyền của chủ sở hữu; hãy dùng biến môi trường và thu hồi ngay nếu lộ.
  • URL thiếu https://. Báo MissingSchema: Invalid URL ... No scheme supplied.

Tổng kết

  • requests.get/post(..., timeout=...); đọc .status_code, .json(); raise_for_status() biến mã lỗi thành ngoại lệ.
  • API JSON-2 của Odoo: POST /json/2/<model>/<method>, header Authorization: bearer, body JSON; key để trong biến môi trường.
  • requests.Session giữ header và kết nối; gói thành client có exception riêng.
  • Chỉ thử lại thao tác an toàn khi lặp; mỗi lệnh gọi JSON-2 là một transaction.

Câu hỏi thường gặp

Vì sao luôn phải đặt timeout trong requests? ▾
Theo tài liệu requests, nếu không đặt timeout thì yêu cầu không bao giờ hết hạn và chương trình có thể treo vô hạn khi server không trả lời. Gần như mọi code production nên đặt tham số này.
raise_for_status làm gì? ▾
Nó ném HTTPError khi phản hồi có mã trạng thái 4xx hoặc 5xx. Nếu không gọi, mã lỗi như 401 không tự gây ngoại lệ và r.json() sẽ trả về nội dung lỗi mà bạn có thể nhầm là dữ liệu.
Gọi API JSON-2 của Odoo cần những header nào? ▾
Bắt buộc có Authorization với giá trị bearer kèm API key và Content-Type application/json. X-Odoo-Database là tùy chọn, cần khi một server chứa nhiều database. requests tự đặt Content-Type khi bạn dùng tham số json.
requests.Session có lợi gì? ▾
Session giữ lại header như Authorization giữa các lệnh gọi và tái sử dụng kết nối tới cùng một host nên nhanh hơn, phù hợp khi gọi API nhiều lần.
